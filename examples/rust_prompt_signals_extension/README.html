Standalone example · Rust · protocol v1

Rust prompt signals process extension

A separately built executable demonstrates the one-shot metrics and pane contract.

The extension summarizes recorded user and assistant message roles and token counters. These signals are observational context, not an efficacy score or causal claim.

Build and select

cargo build --release --manifest-path examples/rust_prompt_signals_extension/Cargo.toml
sha256sum examples/rust_prompt_signals_extension/target/release/agenturm-prompt-signals-extension

Copy the lowercase digest and absolute executable path into a user-managed v1 catalog. Declare capability/1, ui-contribution/1, and the usage and message-role grants, then run:

agenturm inspect --db ./agenturm.sqlite \
  --extension-catalog ./agenturm-extensions.json \
  --extension example.prompt-signals

Data boundary

The host sends source ID, a decimal nanosecond timestamp, observation kind, snapshot metadata, and only grant-permitted typed payload. It omits event and session identifiers, prompt text, commands, tool output, paths, source roots, and arbitrary adapter payloads. The mandatory envelope remains visible even if the grant filters out a row's payload.

The process runs as the Agenturm user. Grants constrain protocol data; they do not restrict what files that OS user can read. A hash pin is not a sandbox.

See the process extension RFC for the full framing and safety contract.

Agenturm Rust 0.3.16

Faster history navigation

Recent-history reads use ordered SQLite indexes instead of sorting the entire observation store. Exact sessions and older-page cursors seek directly to their scope. Sparse roster indexes find lifecycle and relationship facts without scanning every tool or message, including when no parent is recorded.

This removes a measured bottleneck shared by navigation, workflow checks, and background collection. A 256-record page took about 2 ms in a million-record synthetic query benchmark. That measures the database read, not end-to-end navigation. See the measurement and limits.

The release also includes workspace Traces paging and reduced cockpit startup latency shipped on main since 0.3.15.

Upgrade

Quit older Agenturm processes before launching 0.3.16. The first writer open upgrades native history to schema 28 and builds additional indexes. Large stores can take longer to open initially. Older versions cannot read the upgraded database.

Observation identity, grants, snapshots, retention, and source authorization retain their semantics. Indexes require extra disk space and add write work. This upgrade does not delete history.

Native archives support Linux x86-64 and ARM64 with glibc 2.39+, and Apple Silicon macOS 13+. Each archive has a SHA-256 sidecar. Intel Macs and Rosetta are unsupported.

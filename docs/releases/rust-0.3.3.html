Agenturm Rust 0.3.3

The Linux release candidate adds broker-backed workspaces, private evidence and source-backed task continuity, alongside local decoder installation and JavaScript OTLP traces.

Broker workflows

A distinct Linux storage principal owns observation history. Separate reader, grant administration and maintenance identities can list approved content, change grants, prune history, create backups and restore into a fresh data root. The cockpit and task CLI use a workspace bound to the broker endpoint and persistent history identity. Replacing history at the same socket opens a separate workspace.

Private prompts and Codex operation details retain their exact source proof and current approval through terminal redaction. Escape, quit and Ctrl-C replace the private view before releasing its acknowledgement. Client roles can be denied direct access to both broker history and source transcripts.

Source-backed task drafts revalidate the exact occurrence and grant before approval. The task stores source references and authored continuation; source excerpts require a fresh proof on reveal. Task updates, structured briefs, decisions, archives and handoffs support revision checks. A stale cockpit form cannot overwrite an intervening CLI edit.

Producers, adapters and connectors

The shipped JavaScript client can emit OTLP traces through agenturm run or serve-traces, with explicit source and session identity. The trusted local adapter installer verifies an operator-supplied SHA-256 pin and publishes a private catalog atomically. A native Pi fork can retain its parent session when both native headers and the inherited first row agree.

The Linux isolated connector can forward typed status operations through a grant-bound local Unix endpoint. The host checks its peer before sending a credential, and derives receipts without reflecting endpoint content. Production connector qualification remains open.

Validation and scope

Development checks include real adapter process tests, Node-to-Rust OTLP, separate-principal broker task and private-display journeys, role restrictions, retention, backup and fresh-grant restore. The supported release platform is Ubuntu 24.04 x86-64. A real Kiro transcript, production connector endpoint, additional platforms and the remaining full-distribution cutover journeys still need their own qualification. The default Python distribution has its separate release and entry point.

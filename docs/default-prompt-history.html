Default local prompt history

In the Linux live local cockpit, open Prompts (or press P from the agent list), select a request, then press Enter or Right. A previously unconfigured source receives a durable user-text-only grant when Prompts opens. It covers that source's sessions, not other sources. Session and worker filters still limit the selected history. Native prompt reading remains Linux-only.

What stays explicit

  • Revoked grants stay off, even when revocation preceded first access.
  • Changed source bindings require explicit reapproval. Replacing the source file or changing pinned adapter configuration does not inherit approval.
  • Disabled backup grants stay disabled when reopened.
  • Saved-history views, CLI content previews and remote readers do not create default grants. An already enabled grant still follows its existing rules.
  • Tool inputs/results, commands, edits, telemetry and evaluations retain independent permissions.

Where permission was withheld or invalidated, the UI still offers Enable prompt history (a) for deliberate reapproval.

Opt out for a source

Stop the collector using that history so the command can acquire its writer lease, then use the exact database path and source ID:

agenturm content revoke --db <history.sqlite> --source-id <source-id>

This revokes all private-content kinds for that source, not only prompts. Restarting or opening Prompts does not undo it. Reapproval must be explicit. It changes access, not retention; it erases neither history nor native logs.

Older versions did not retain revocations made before any grant existed. Such opt-outs cannot be recovered; run the command again with this version to record them.

Privacy boundary

This change stores authorization state, not another transcript copy. Text is read from the existing native source on request and may contain project data or secrets. Recognizable-credential filtering is best-effort.

Source/checkpoint proofs, exact session/worker scope, snapshot and history identity, source-replacement checks and revocation-fenced delivery still govern listing and disclosure. There is no new network transfer, provider call or automatic export.

Protect native logs, the local database and backups as sensitive files. Retention is logical deletion, not secure erasure.

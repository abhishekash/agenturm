0.1.2 · Native session status, MCP inventory, optional AI summary

Shows agent and session IDs, repo/project, lifecycle status, update age, pending wait, and task details. MCP server calls now link across start/result events, expose qualified Claude Code and Codex tool names, report completion/error status, and include all stored history in server counts. Agenturm

A terminal-first monitor and local telemetry receiver for AI agents. It discovers supported local agent sessions, then accepts OTLP/HTTP traces, logs, and metrics in protobuf or JSON from instrumented runtimes and the existing agent-harness JSONL format. The terminal cockpit shows agents, activity, MCP calls, traces, host processes, and metrics. Data lives in SQLite. The receiver uses Python's standard library (3.11+); the terminal UI uses Textual.

GitHub Copilot CLI telemetry

Copilot CLI can send its built-in OpenTelemetry traces and metrics directly to the cockpit receiver. Start agenturm in one terminal, then launch Copilot CLI from the project in another:

export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:14318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/json
export OTEL_SERVICE_NAME=github-copilot
copilot

Setting the endpoint enables Copilot telemetry. The CLI defaults to http/json; the protocol is shown explicitly here. The cockpit groups spans into sessions when Copilot supplies gen_ai.conversation.id and reports model usage, tool activity, and recognized hook, skill, compaction, truncation, and session lifecycle events. Tool records contain only fields the CLI exports; the MCP Calls view can identify a server or tool only when those identities are present in telemetry. Prompt and response capture is off by default in Copilot CLI; keep it disabled unless you intend to collect that content. Copilot's OTel settings and span/event schema describe the emitted signals and optional content capture.

Install and launch the terminal cockpit

Python 3.11+ is required. Install the published CLI in an isolated environment with uv tools:

uv tool install --force agenturm
agenturm

To try it without installing, run uvx agenturm. If uv is not installed, use its official installation instructions. If the installed command is missing from your PATH, run uv tool update-shell and open a new terminal. You can also install into an active Python environment with python -m pip install agenturm.

The cockpit opens Agents, Activity, MCP Calls, and Traces as primary views; use More or 5–7 for Host, Metrics, and Findings. Agents opens to Today: current work, sessions that need you, and reported completions awaiting human review. The filter also offers Running, History, and Errors. History includes earlier work, including yesterday’s unreviewed completions. Task-first rows have an evidence inspector. Its website-aligned Observation palette is the default; change themes with Ctrl+P. Findings provides a searchable, paged review queue with occurrence counts, evidence links, and direct navigation to the source trace. Session counts and live process counts are separate; approval reviews are hidden by default. The cockpit attaches to a receiver on 127.0.0.1:14318, or starts one there. Run agenturm for full-screen panels in your current terminal. From this checkout, python3 -m observatory also works without installation.

Continue work across sessions

Press b to open Saved tasks, then n to save the selected session as a task. Give it a title, workspace, and brief with your intent, decisions, and next step; Ctrl+S saves. A task keeps its ID and notes when you close Agenturm, change agents, or clear retained telemetry. You can also start a blank task without a connected receiver.

Open a saved task to Edit notes, Link the selected monitoring run, Capture Git changes, or preview a Handoff. Runs shows the exact associations and lets you unlink one. Link again to refresh a run's saved evidence. Token and reported cost totals cover linked exact runs only; session-only links do not contribute totals. Missing values remain unknown, and incomplete coverage is labeled partial. Cache counts are input breakdowns, not additional tokens or estimated savings.

Handoff previews the saved brief, workspace snapshot, linked runs, and recorded checks. Copy brief copies that exact preview. Write MD + HTML creates a new Markdown/HTML pair without overwriting existing files. Capturing Git reads the local repository only when requested; it does not run tests. Recorded check results do not prove the current changes pass. Read the saved-task guide for CLI examples, storage, capture limits, and privacy details.

Existing Codex and Claude Code agents

Local receivers automatically discover recent session files under ~/.codex/sessions and ~/.claude/projects (CODEX_HOME and CLAUDE_CONFIG_DIR are respected). Start the monitor with no agent filename or Python environment flags:

agenturm

It reads actual logged activity as files update, including already running sessions. Agents need no restart or configuration change. Source logs stay untouched. Select an agent for its status and latest action; press e for the zero-setup recorded-progress summary or s for its activity. When a session explicitly asks for a user reply or approval, the monitor points you to that agent's own terminal; it cannot submit the answer or approve actions for the agent.

Native session capture includes bounded text and content by default. Recognizable credentials and sensitive structured fields are redacted before storage; this is best effort. Opaque/encrypted reasoning, private reasoning text, binary payloads, process environments and credential files are excluded. Content is limited to 8,000 characters per activity record, with nested fields bounded to 2,000 characters and at most 60 entries. Source schemas and upstream truncation can leave gaps. Use serve --metadata-only or cockpit --metadata-only for a receiver that omits native message text, commands and results. This setting controls future ingestion and does not erase previously stored content.

The Working agents headline counts unfinished, actively observed turns and names their runtimes; total sessions and open host processes are separate. A quiet model/tool call does not become idle after 35 seconds. On Linux, exact open session-file matches provide process/child CPU and I/O evidence; shared working directories are never used to guess a session-to-process match. Token usage comes from records; input counts include repeated/cached context and are not a billable-cost estimate. Costs remain unknown when not reported. Model-call latency is marked unknown when the log has no start time.

Discovery scans every 10 seconds and tails discovered files every second. It selects up to 50 Codex/Claude Code/Pi files modified within the past 24 hours and up to 50 OpenCode sessions with recent session or message activity, importing at most the last 8 MiB initially per file. Pi sessions are read from $PI_CODING_AGENT_DIR/sessions (default ~/.pi/agent/sessions). OpenCode supports both the legacy message/part tables and current session_message records, including recent records whose parent session row is absent. Claude Code subagent transcripts under a selected session's subagents/ directory and Codex subagent rollouts use the same limits; linking never triggers an unbounded historical scan. If a limit is reached, the terminal health line reports how many sessions are outside the visible window. Summaries may cover only part of a long session. Codex response IDs, Claude message IDs, and Pi message IDs prevent duplicate usage entries on reread; older Codex cumulative token snapshots are handled separately. A version with a different log schema may expose less activity. GET /api/health reports discovery status, session/task snapshots, runtime metadata, source count, read errors, and skipped malformed records. GET /api/activity?limit=100&service=codex&domain=shell&q=... exposes a bounded, searchable activity view from the latest 100 observed traces. The terminal shows up to 100 recent events, with full trace investigation available separately.

Local discovery runs in the receiver. If you installed an earlier version, reinstall the CLI and restart that receiver to enable it. A cockpit attached to an older receiver cannot enable discovery there. Add --no-local-agents to serve or cockpit to disable discovery in a receiver started by that command. Receivers bound to non-loopback addresses do not discover local sessions automatically. Other agent products still need an adapter or OTLP export.

Read an agent's work

Press Enter on an agent to open its inspector. Overview leads with its task, state, latest agent-reported update, recorded command/output, recent work, and delegated children. An agent's claim and a successful tool result are different evidence; neither verifies the entire objective. The footer states which recent records are loaded. A quiet session gets its own exact-scoped read, even when its events have left the global activity window.

The inspector opens with its Overview / Prompts / Details tab strip focused. Use ←/→ to choose a section and Enter to enter it. In Prompts, ↑/↓ from the tabs enters request navigation and chooses an older/newer request; in other sections ↓ enters the reader. From the reader, Ctrl+←/→ switches sections; m also cycles them. Tab and Shift+Tab move between the inspector's visible controls. While the text reader has focus, ↑/↓, Page Up/Down, and Home/End scroll its content. Esc closes an open selector first, then returns to the selected agent. The task, runtime and status remain visible above the content; switching sections preserves the reading position. Prompts reads one request at a time, starting with the latest. It opens on the chronological index at wide sizes: ↑/↓ chooses requests, Home/End chooses oldest/latest, and Enter or → reads. In compact layouts, ↑/↓, Enter or Space opens the native request chooser; arrows select and Enter confirms and reads. → reads the current compact choice directly. From the request text, ← returns to its navigator. [ moves to the previous request, ] to the next, and l to the latest loaded request. Earlier prompts loads an older page without moving the request you are reading. The reader retains up to 300 requests, preserving the selected request and newest arrivals; older history remains available in Activity.

F1 opens a persistent, scrollable keyboard reference from any screen, including editors; Esc or F1 returns without losing the draft or selection. The footer distinguishes choosing requests from scrolling their text. Ctrl+R opens the selected agent's recorded-work review. The complete keyboard navigation guide covers the inspector, Workflow, Review, saved tasks, dropdowns and editors.

Known complete runtime context blocks are separated from the readable request, with a visible disclosure. z toggles original captured text for that request. Literal JSON, code, line breaks and indentation are retained. c copies the selected request in its current readable/original form; x previews an export of that same request. s opens the selected request in Activity. Original text means the stored, bounded, redacted record, with terminal control characters removed; it cannot restore content omitted upstream. Details holds IDs, model, reported usage, status evidence and relationship provenance.

Agent rows prioritize the first substantive task. Runtime and project sit below, with worker counts where relevant. Whitespace and a subtle alternating background separate whole agent blocks: four lines at 120×36 or larger, three at 24 or more terminal rows, and two in shorter layouts. Each tree level adds four cells, with aligned metadata and continuing ancestor guides. Selection remains visible through resize, and only a branch's first line is its disclosure target. Collapsed parents retain both working and attention counts for their descendants. ←/→ collapse/expand branches in Today, Running and History; search temporarily reveals matching paths. Parent-only filter context is labeled. Alt+Up, Alt+Down and Alt+Right navigate to the parent, first visible child, or a descendant needing attention, revealing hidden targets. At 80×24 and in a 60-column terminal split, Enter opens the inspector as a single reading pane. The supported floor is 60×18; smaller terminals show a resize message.

Resource usage

The terminal fetches live data every two seconds; stored session inventory, MCP, metrics, usage and findings are cached for five seconds. Filter and selection actions can wake the feed immediately. Collection continues independently, even when display updates are paused. Tables update changed cells instead of invalidating an entire row. Stored session inventory has its own five-second budget, so changing views does not reload the same global history.

When the receiver is reachable but stored reads time out, Agents keeps the available native roster and labels the view Partial data or History delayed. Previous activity and traces are retained only for the identical filters and hierarchy scope. Missing evidence is unknown, and stale totals are disclosed in Details. Other evidence views retain their existing reconnect behavior. Reads retry automatically; R retries immediately. Restart the cockpit and any separately running receiver after upgrading to use the optimized queries.

OpenCode polling skips unchanged databases between a 30-second lookback refresh; that periodic refresh ages old sessions out even when OpenCode writes nothing. When a database changes, unchanged messages are not normalized or written again. On schemas with part update timestamps, unchanged tool payloads are not loaded again; older schemas fall back to content comparison. Revision caches contain only fixed-size digests within the 50-session / 30-message import window, not retained tool outputs. Payloads are capped at 2 MiB per record and 16 MiB per poll; deferred records resume on later polls. Initial import still costs more than steady-state monitoring, and large histories or sustained telemetry can increase CPU, memory and database size.

Run python scripts/benchmark_resources.py for a repeatable synthetic reader benchmark (idle, unrelated database writes, and one changed tool). It uses a temporary database, not personal sessions. Results measure reader CPU, logical reads and span write counts; they exclude terminal rendering and derived Store work. Regression tests in tests/test_resource_usage.py and tests/test_opencode.py enforce polling, cache and redundant-write behavior without relying on hardware-dependent CPU thresholds.

OpenCode local database

On loopback, the receiver checks OpenCode's local SQLite database in read-only mode and lists recent sessions with their project, task title, model, and assistant-turn token counts. Recorded tool parts appear as trace spans; persisted todo checklists appear as progress events with completion percentages. MCP names are attributed when OpenCode records an explicit qualified server/tool name. The usual database path is ~/.local/share/opencode/opencode.db; XDG_DATA_HOME and OPENCODE_DB are honored. Reasoning parts are never read. Inputs and results follow the same bounded, redacted content policy as other native sources; pass --metadata-only to omit those payloads and task text. Discovery covers the 50 most recently updated sessions from the last 24 hours, up to 30 assistant messages per session, 200 tool parts per message, and 100 checklist items per session. Both legacy session metadata and V2 session_v2 metadata are supported, with V2 taking precedence for migrated IDs. User/assistant and idle-outcome records determine running, completed, interrupted, and failed status independently of the bounded transcript window. OpenCode's internal schema can change; use OTLP for a stable cross-version integration. Inactivity does not imply an approval wait.

Optional Python SDK capture

Native session discovery is automatic for supported local agents. For another Python agent, automatic SDK capture is a separate command-line workflow; the monitoring cockpit itself does not launch agents. Install the capture extra into the agent's environment:

uv pip install --python .venv/bin/python 'agenturm[auto]'
agenturm run --endpoint http://127.0.0.1:14318 --service my-agent agent.py

Replace the environment path, service name, and agent filename with your own. Arguments after agent.py go to the script; --module runs a Python module. If Goechala is already installed in the active agent environment, use python -m observatory run --endpoint http://127.0.0.1:14318 --service my-agent agent.py.

This launcher runs the selected script in that terminal and is intended for SDKs not already captured from local session records. Existing processes can send OTLP telemetry to the receiver. Python SDK prompts and responses are omitted unless you add --capture-content. Native session capture has its own --metadata-only receiver setting.

Press d for local collection diagnostics: source paths, last successful reads, backlog, skipped records, schema errors, first-run guidance, and retention commands. Diagnostics do not show receiver credentials or raw events. Source paths can still identify projects or users. Older receivers may not report all diagnostic fields.

Press x to export selected evidence. On Agents, Shift+X dismisses or restores the selected attention item; export and dismissal use separate shortcuts. A frozen privacy preview shows the exact JSON before anything is written. Choose a new destination and explicitly select Write reviewed export. Existing files are never overwritten; new files are owner-only. Exports contain only the selected record and currently loaded evidence, not complete history. They may contain private prompts, outputs, paths, or producer-recorded secrets: review before sharing.

Theme (Observation by default), active view, Reviews, Prompts, and Activity/MCP error-filter flags are saved in $XDG_CONFIG_HOME/agenturm/ui.json (or ~/.config/agenturm/ui.json). Searches, session IDs, selected records, endpoint addresses, and credentials are not persisted. Set AGENTURM_UI_PREFERENCES=0 to disable preference reads and writes. Headless tests do not access personal preferences unless explicitly given a test preference path.

Each view has its own search field and result count directly above its rows. Search in Agents filters sessions by task, project, model, runtime, or session ID. Activity, MCP Calls, and Traces query their own records; Host filters the process list; Metrics filters OTLP instruments by name, service, kind, unit, or description; Findings searches severity, finding type, task, and evidence text in the current page. Findings are global across sessions and can be paged with Older, Newer, and Latest.

The Metrics view shows the latest stored point for each instrument with its value, unit, point attributes, resource attributes, and data. Select an instrument to load its latest 100 points; points with OTLP exemplars can open the linked trace with t or Open exemplar. The overview loads up to 500 catalog entries and 500 latest points, with inventory cached for five seconds. The session Scope control filters Metrics by the selected session's service; metric points are not attributed to individual sessions unless the telemetry itself includes that association.

Filters stay with their view when switching tabs. A task search in Agents does not hide MCP calls or reduce the selected agent's recent-work feed. Clear resets that view's query; the session Scope control applies across views. Overview counters retain the inventory for the selected session scope. The Errors button in Activity and MCP Calls filters failures within the current results; it does not change the inventory counts. a also resets these error filters. Tables prioritize subject and status columns in narrow terminals; lower-priority metadata returns when widened, and complete records remain available in the inspector. Inspectors wrap long text to the panel width.

MCP shows reported servers, tools or methods, state, duration, arguments/results and trace/span IDs. It includes protocol methods such as tools/call, tools/list, resources/read, and prompts/get when telemetry records them. Calls without a reported server remain visible under Not reported; Goechala does not guess their server. Tool execution spans are joined to transport calls to fill in arguments or results when the transport span omits them. Explicit MCP isError results mark the run and call as failed, appear in error filters, and create an evidence-linked finding even when the producing span has no error status. The trace view shows a parent-linked span tree; unknown durations remain “not reported”. “Error” describes recorded errors within a trace; “Active · errors” means a logged active turn also contains an error. Live host process counts exclude zombie/exited states and do not imply that every open terminal is working on a turn.

Connection feedback. The cockpit loads the visible view without requesting all-history totals or hidden MCP/metrics/findings views. The initial session read starts alongside the other required reads. Before the first snapshot, the session area says it is waiting for receiver data; it does not claim there are no sessions. Data timeouts name the affected request and show Loading delayed. Startup immediately prints the receiver address and shows Connecting until the first complete snapshot arrives. An explicitly selected receiver being offline opens the cockpit in reconnect mode. After the first snapshot, refresh/reconnect feedback stays in the fixed header and footer, keeping the list and inspector stationary. Slow refreshes show the current loading stage and elapsed time; disconnections retain the last good data, show its age, and display an attempt count and retry countdown. Click Retry now during startup or press Shift+R at any time to skip the next retry delay. A retry requested during an active read runs when that read finishes. Reconnect attempts use a one-second lightweight liveness probe before loading session data, with retry delays from half a second up to two seconds. Normal data reads retain their three-second socket timeout. Authentication failures name the missing configuration. The /api/health?probe=1 endpoint checks liveness without performing process/session discovery; the full health response still carries collection diagnostics. Restart a separately running receiver after updating to enable the lightweight probe.

Today and task outcomes. Today uses the local calendar day. Active work and explicit input/approval requests stay visible even if they began earlier. Today’s failed, interrupted, incomplete, and unknown outcomes appear under Needs attention. The inspector distinguishes a recorded failure or pending input from unavailable status. Earlier completed or failed tasks remain in History. The Agents Errors shortcut shows only unseen recent error evidence; old failures do not inflate the attention count or Workflow inbox. A quiet, stale running span without a linked live process needs a status check; it is never counted as confirmed live work. The collector’s discovery limits still apply. At 24 terminal rows or fewer, the header and navigation shrink to one row each. At 24 rows task blocks keep one separator line; shorter layouts use two content lines, leaving room for tasks and usage in a 60-column split. Help and quit remain in the bottom hint line.

Ready for review means the agent reported completion and you have not marked that run reviewed. It does not mean the changes or tests have been verified. Press r to mark a completion or attention item reviewed; the acknowledgement is stored locally for that run. Today removes reviewed completed work, while History retains it. Press r in History to reopen its review. A new task lifecycle in the same session gets a new review. Normal tool/model span errors remain evidence and do not override the task’s reported lifecycle. When no task outcome was captured, Agenturm shows Unknown, even when low-level spans succeeded. Trace health and error counts continue to describe the recorded telemetry.

Below 120 columns, the facts stack into one scrollable reading pane. Chronological prompt history. The expanded inspector shows recorded user prompts together, oldest to newest, numbered with local timestamps. Opening it loads the latest 100 prompts for the selected session or exact agent, independent of the recent tool-activity window. Earlier prompts loads the next older page and opens its beginning; overlapping events are deduplicated. New captured prompts join the timeline without resetting the reading position. Pause and follow live. Press p or click Pause to freeze the displayed records and their order while collection and polling continue. The status line counts distinct new or changed records in the loaded view, not polling cycles or every event in the database. Click Follow live or press p again to catch up, retaining the selected record. Searches, scope changes, and linked investigations still work while paused; up to four recently visited views retain their frozen snapshots. Pausing is temporary and is not saved between launches.

Recent error reminders. Agents Errors N counts sessions with unseen errors in the two most recently active conversations for each project/runtime. Confirmed subagents share their parent conversation’s window. Search and selecting an older session do not bring old errors back into this queue. Lifetime tool/run error totals do not create reminders. A later successful identical operation in the same exact agent, session and run suppresses its earlier reminder; this does not establish overall task correctness.

From a session, press s or click Failed call / Failures to open the recorded evidence. Selecting an agent row or seeing its badge does not mark its errors seen. Displaying the loaded error details in Activity stops that error’s reminder, including after restarting Agenturm. In a narrow terminal, press Enter to open the inspector. A hidden inspector, a metadata-only reference, or a failed details fetch does not count as seen. A distinct new failure can appear again. If the runtime reports a failed outcome without a captured failed call, opening Failures marks that exact outcome seen. This does not change the native task status, mark a completion reviewed, or clear an approval request. Resolve problems in the original agent terminal; Agenturm observes the evidence.

Reminder evidence is bounded: up to five pending error references per agent from the newest two compact trace error indexes and the latest 50 session log records, plus an explicit current failed outcome. Each trace index holds at most 20 metadata references and updates when the trace receives new telemetry; existing traces are not replayed on upgrade. Missing or older evidence remains unknown. Minimal hashed seen receipts stay locally in the workflow SQLite store, with a 10,000-receipt limit; the oldest receipts can be removed at capacity. Receipt writes run off the UI thread. If storage is unavailable, the error stays seen for the current monitor and Agenturm reports that it could not save the receipt.

Investigate error history. Activity’s Errors filter and Traces retain the full recorded history, including errors already seen and errors outside the reminder window. Opening a failure clears unrelated Activity searches and prompt filters and scopes the investigation to that exact agent. Identical failed operations are grouped within the loaded page; the inspector lists occurrence IDs, captured input/output, and up to three nearby loaded events on either side. Later matching success is observed evidence, not proof of a fix. Press t for the linked span, then Alt+Left or Back to return to the original session with selection, filters and scroll position restored.

Local workflow · w. Press w or choose Open local workflow in the command palette for the attention inbox and selected-session review. Enter on an inbox row selects that session. The view is a point-in-time review; Refresh reads the latest collected snapshot. It shows snapshot age and receiver errors separately from agent state, exact observed process IDs, collector backlog, and other active sessions recorded in the same working directory. Shared directories are overlap warnings, not inferred file ownership. Completion review lists recorded file operations and check commands from loaded Activity, labels whether checks preceded later recorded edits, and does not claim a clean worktree or complete verification. Context events include recorded compaction/truncation; cumulative tokens never stand in for context occupancy. Confirmed direct delegated children show their own latest-run usage separately, without an ambiguous combined total.

Desktop attention alerts are opt-in under Workflow → Settings. Initial inventory is silent; new explicit approval/reply requests, recorded failures, possible stalls, and exceeded task thresholds generate a coalesced desktop notification. Ordinary tool waits do not. Notifications include project names and a generic attention message, with prompts/commands omitted. Delivery uses native Linux/macOS helpers in a bounded background worker; unavailable/failed delivery is shown in Workflow. Snooze 10m suppresses desktop delivery while retaining the inbox. Limits for task tokens, reported USD, and elapsed minutes persist locally; 0 disables each. Elapsed alerts require a reported start time and active task, and missing prices remain unknown. Thresholds are advisory alerts; the monitor does not enforce runtime limits. Alert wait ages mean time first observed by this cockpit, not a reconstructed historical wait. Keep the cockpit open for delivery.

Terminal selects a uniquely verified tmux pane by exact session-process identity and ancestry on Linux. It does not match by project name or working directory. Outside tmux, attach to the target tmux session to see the selected pane. Missing/ambiguous process evidence leaves terminals untouched. Copy resume provides a shell-quoted native command for Codex/Claude sessions; inspect ownership before running it, since an active writer may already own the session. Other terminal/runtime handoffs remain explicitly unavailable.

Tokens and spend per task. Each task row shows tokens and cost for its latest recorded run/turn. Cache stays out of the list. The inspector shows input/output tokens and cached input with its percentage of input; cache writes appear only when reported, and u opens the full breakdown with the exact trace ID. A task here is one recorded run, not the sum of every turn in the session. Traces lets you select an older run. Session lifetime totals are never substituted if the latest run’s telemetry is missing. The shared top-level usage bar is removed. Narrow rows abbreviate or truncate values; the inspector and details preserve access to the complete breakdown. Missing telemetry displays Not reported, explicit reported zero remains zero, and + marks a partial subtotal. For Python agents that need manual instrumentation, the package includes a small synchronous and asynchronous client. Nested spans inherit their parent, progress is posted while the run is active, and completed spans are sent when the run exits. Pass resource_attributes to identify the host in the endpoint inventory; host identity collection is opt in:

import platform
import socket

from observatory import Client

telemetry = Client(
    service="research-agent",
    token="optional-bearer-token",
    resource_attributes={"host.name": socket.gethostname(), "os.type": platform.system().lower(),
                         "os.version": platform.release(), "host.arch": platform.machine()},
)

async def run_agent():
    async with telemetry.trace(task="Find current guidance", session_id="thread-42") as run:
        await run.aprogress("planning", "Choosing a search strategy", 10)
        async with run.span("tool.search", attributes={"tool.name": "search"}):
            await search_web()
        async with run.span("llm.call", attributes={"gen_ai.request.model": "my-model"}) as call:
            answer = await ask_model()
            call.set_attribute("gen_ai.usage.input_tokens", 320)
            call.set_attribute("gen_ai.usage.output_tokens", 85)
        return answer

Current boundaries

This is a working local vertical slice, not an Origin equivalent. The latest captured request for the selected run is separate from its stable session task label. Recognized informational commands do not count as validation; file reads do not count as edits. A shared or incompletely attributed trace does not supply individual-agent usage or a trace-wide outcome to a selected worker.

For the pilot, deterministic repeated-work findings are explicitly enabled on the receiver with AGENTURM_WORKFLOW_PATTERNS=1. Restart the receiver to change it. These rules inspect at most 500 records per run, refresh at most 20 existing runs when enabled, and remain out of desktop alerts. They do not establish wasted work or correctness.

Recent completion reviews and unknown status

Unknown or unconfirmed lifecycle evidence stays visible as Status unknown and does not count as actionable attention. A shared Codex daemon is not proof that a particular session is advancing. Explicit approvals/replies, recorded failures and genuine possible stalls retain their evidence-based behavior.

Workflow defaults to completion reviews from the last 24 hours. Press h to include older completions; pending requests remain visible. Shift+R reviews the exact completion IDs in the current filtered inbox together; it excludes approvals, replies, budget incidents and later arrivals. Ages use hours/days. Accepted acknowledgements and viewed-error receipts drain on graceful shutdown with a bounded failure notice; SIGKILL cannot provide that guarantee.

Investigate retained paths, commands and instructions

Press Ctrl+F in the monitor, choose History in Activity, or use the command palette’s Investigate retained history action. Choose Path, Command or Instruction and enter a query. Paths match exactly, including case and Unicode. Commands and instructions match a literal word phrase. Results describe retained recorded observations; no matches does not prove no activity.

Use arrows, Page Up/Down and Home/End to select a result, then Enter to read exact recorded evidence. Escape returns to results, then the monitor. Tab reaches Filters, More and Back; Ctrl+C cancels the current read or goes back. The same screen fits a 60×18 terminal. Queries never execute commands or retry agent work.

agenturm investigate path src/retry.py
agenturm investigate command pytest --failed
agenturm investigate instruction "keep the public API" --format json

Use --service for an exact producer, --pages 1..5 and --limit 1..100 for bounded CLI reads, or the returned cursor to continue the same query. The UI retains at most five pages, 250 results and 2 MiB. Each result supplies a pinned source_command / source_path; use that complete reference to read a source. A bare event ID cannot be rebound to a fresh receiver. Capture denial, identity changes or pruned records may make evidence unavailable. SQLite FTS5 support and a ready source index are required; there is no broad raw-history fallback.

The watcher connects to an existing receiver and shares private Workflow state with the cockpit. It never launches an agent or approves a native request.

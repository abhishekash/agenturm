Agenturm Rust bundle for Linux

The bundle contains the Agenturm CLI and inspector, the process host, the Codex, Pi, Claude Code, Kiro, and OpenCode adapters and their SHA-256-pinned catalog, plus the trusted connector driver. The runtime requires a compatible Linux system and does not require Python or Rust. The managed collector uses a running systemd user manager. Foreground collection is available on Linux systems without a user manager.

Platform Build Collector
Ubuntu 24.04 x86-64 Local bundle and CI artifact Foreground and systemd user service verified
Other Linux releases and architectures Host build script available Qualification open

Build and install

From a source checkout on Linux with the pinned Rust toolchain and a native C build toolchain, run scripts/build-rust-linux-bundle.sh ./dist. The script builds for the local Linux architecture and emits a tarball and checksum.

From the directory containing the archive and its checksum, set the version and use the archive name for your architecture.

archive="agenturm-VERSION-linux-x86_64.tar.gz"
sha256sum -c "$archive.sha256"
mkdir -p "$HOME/.local/opt"
tar -xzf "$archive" -C "$HOME/.local/opt"
agenturm="$HOME/.local/opt/${archive%.tar.gz}/bin/agenturm"
"$agenturm" --version

Use the archive and directory names produced by the build for your version and architecture. Keep the catalog and binaries in the extracted directory.

Open the cockpit

From a terminal, run the installed binary.

"$agenturm"

The cockpit opens on Agents. It uses ${XDG_STATE_HOME:-$HOME/.local/state}/agenturm-rust/history.sqlite. It starts session-owned collection of supported local harnesses when the default database is available for writing. When another writer owns the database, the cockpit reads the same history. When the cockpit owns collection, it also receives OTLP/HTTP traces at http://127.0.0.1:14318/v1/traces. Set AGENTURM_OTLP_PORT to use another loopback port. Both stop on quit.

Use ↑ and ↓ to choose a session, / to search the loaded roster, and Enter to open its Overview. The newest roster page refreshes while open. Press r in Agents to refresh it immediately. Open Activity with a or Review with v, and open the selected session’s Usage with u. Press y in Review to acknowledge the displayed evidence. The acknowledgement is stored next to the history database and applies to the reviewed version.

From Agents, g opens the cross-source Overview. Use 2 for Activity, 3 for MCP, 4 for Operations, 5 for Findings, 6 for Host, and 7 for Usage or 8 for Traces. Press t in a history view to select a recorded turn, F1 for keyboard help, and q to quit. The available evidence varies by source. For Codex MCP calls the view includes the server, tool, method, duration and outcome when recorded.

Press m in the MCP pane to choose an exact recorded Codex call. Enter opens a byte-verified payload where an MCP approval is active. Use content grant --kind codex.mcp_payload with the history path, source configuration and source ID to establish it. Use content revoke --kind codex.mcp_payload to remove that approval.

From Agents or a session or turn detail, press b to open saved tasks. Use n to create a task linked to the selection, r to see its linked runs, and h to create a handoff using the current selection. Open the handoff list with o and export the selected handoff with x. Tasks can also record a Git snapshot from a directory you choose with G.

From Agents, press w to see recorded requests. Use s to mark an item seen and l to focus the matching tmux pane when Agenturm verifies the route. Respond in the harness terminal.

In Review, press n for saved decision notes. In the decision list, press e to write a note against the selected evidence version and Ctrl+S to save it. Review shows recorded Codex edit counts. Press e from Review or turn activity to select a recorded edit, then Enter to view its paths and any bounded diff or file contents. Escape clears the preview and returns to the same selection.

Edit detail requires its own approval and verifies the selected event, session, turn and operation against the retained source receipt. Set db to the history file, config to the collection configuration, and source_id to the exact recorded source ID.

"$agenturm" content grant --kind codex.edit_detail --db "$db" \
  --config "$config" --source-id "$source_id"
"$agenturm" content revoke --kind codex.edit_detail --db "$db" \
  --source-id "$source_id"

Select a session and press p for eligible user prompts. Press Enter to reveal one and Escape to clear it. The view requires a current grant for a pinned source and uses sources.json next to the history database or the path set in AGENTURM_CONTENT_CONFIG. It verifies retained JSONL rows by their committed receipts. OpenCode SQLite prompts can also use a retained admission proof after later sweeps. The default cockpit uses its collector's writer lease for reveal. Establish or revoke grants from the CLI while the history writer is available.

Use "$agenturm" cockpit --db <path> or "$agenturm" inspect --db <path> to open a specific existing Rust store without starting local collection. For collection between cockpit sessions, set up the managed collector below.

Export a Review receipt

Select one exact source, session, and turn. Add --worker-id for the recorded worker. Omitting it selects workerless evidence. The receipt records the store snapshot ID, observation revisions, and any cursor for older evidence. Each receipt covers one page.

"$agenturm" review --db "$db" --harness-id "$source_id" \
  --session-id "$session" --turn-id "$turn" --limit 200 \
  --format json --output ./review-receipt

The new private directory contains review.md, review.html, and review.json. Use --format text, --format markdown, or --format html for readable stdout output. Omitting --format preserves the history query JSON on stdout. Review receipts contain retained observation metadata. Use the content-grant commands separately to inspect protected bodies.

Edit tasks from the CLI

Set db to an existing Rust history database and get a task's ID and revision from task list or task show. Pass --expected-revision when updating or archiving a task and when changing its brief, decisions, exact links, or Git snapshot. The local task CLI returns exit code 3 on a revision conflict and 2 on invalid input or storage failure.

"$agenturm" task create --db "$db" --title "Review the release" --workspace .
"$agenturm" task update "$task" --db "$db" --notes-file notes.txt --expected-revision "$revision"
"$agenturm" task brief "$task" --db "$db" --next-action "Check the upgraded store"
"$agenturm" task decide "$task" --db "$db" --kind accepted --text "Keep the current format"
"$agenturm" task decisions "$task" --db "$db"
"$agenturm" task handoff "$task" --db "$db" --output ./release-handoff

task brief --file reads a JSON object with intent, acceptance_criteria, constraints, open_questions, and next_action. Omitted brief fields keep their previous values and an empty string clears a field. Brief and decision text fields take up to 4 KiB of UTF-8 each. To replace a decision, add a new version with --supersedes and the current decision ID. task decisions shows current and superseded versions.

task snapshot captures a summary of the selected local Git worktree. Set or change the directory with task update --workspace. Changing it clears the prior Git summary. task handoff uses a single saved task revision and defaults to Markdown with current decisions. Use --format html or --format json for another stdout format, and --include-decision-history to include superseded decisions. With --output, a new private directory contains both handoff.md and handoff.html.

task archive hides the task from the default list while preserving its history. Use task list --all to include it and task archive --restore to return it to the default list. The workspace backup includes these task records and their decision history.

Prepare a source-backed continuation

Use content list after granting user prompt access to find the event, revision, turn, and worker if recorded. task draft captures one eligible prompt from that exact scope. Give --output a new path to write a private JSON file. Without --output, the excerpt and draft go to stdout.

"$agenturm" content list --db "$db" --config "$config" \
  --source-id "$source_id" --session-id "$session"
"$agenturm" task draft --db "$db" --config "$config" \
  --source-id "$source_id" --session-id "$session" --turn-id "$turn" \
  --event-id "$event" --revision "$event_revision" --task-id "$task" \
  --output ./task-draft.json
"$agenturm" task approve-draft ./task-draft.json --db "$db" --config "$config"
"$agenturm" task continuity "$task" --db "$db"
"$agenturm" task continuity "$task" --db "$db" --config "$config" \
  --approval-id "$approval"

Include --worker-id when the selected prompt belongs to a worker. Edit the JSON continuation field before approving. Omit --task-id at draft creation to approve the draft as a new task, using the JSON title or --title on approve-draft. Approval checks the source bytes, event revision, and original grant again. A draft for an existing task also checks the task revision captured during preparation.

Use task decide --source-file ./task-draft.json --config "$config" with the usual task ID, kind, and decision text to cite its source. For a draft created without --task-id, also pass the current task --expected-revision. Use an approval ID from task continuity to reopen the original excerpt. The original grant must still be active. Task handoffs and backups retain the exact source reference and the text you wrote for the task.

For broker history, use agenturm broker task with --broker-config and the broker's configured source and permission. If the connection breaks after an approval is saved, the command can return an error. Check the task's continuity list for the draft digest and the task's revision before retrying. A draft digest can receive one approval.

Open native traces

Point an OTLP/HTTP producer at the loopback receiver. Each span needs a session.id or gen_ai.conversation.id string attribute. The receiver accepts uncompressed JSON or protobuf at http://127.0.0.1:4318/v1/traces. To attach the span to a native session, also set agenturm.source.id to the exact collected harness source ID. Press 8 from a native session to see its linked spans.

For turn-level evidence, set the span's agenturm.turn.id to the exact native turn ID. When the turn belongs to a worker, also set the span's agenturm.worker.id to its native worker ID. Use string values and put all IDs on each span you want to link. A turn-scoped span requires its own source and session attributes. Agenturm checks the native turn and worker against the same history snapshot as the span.

"$agenturm" serve-traces --listen 127.0.0.1:4318 --db traces.sqlite --source-id otlp.local

You can also load an export directly.

"$agenturm" import-traces --file export.json --db traces.sqlite --source-id otlp.local

To list trace spans for a known native turn, add --linked-traces to the exact Review command. Supply --worker-id if the turn belongs to a worker. To open the native turn of a known trace, supply the trace ID, its OTLP source, and the expected native source and session.

"$agenturm" review --db traces.sqlite --harness-id "$source_id" \
  --session-id "$session" --turn-id "$turn" --linked-traces --format json
"$agenturm" review --db traces.sqlite --harness-id "$source_id" \
  --session-id "$session" --turn-of-trace "$trace_id" \
  --trace-source-id otlp.local --format json

Trace-to-turn selection requires one explicit native scope among the trace's turn-scoped spans and a retained anchor for that scope. It checks up to 4,096 retained span rows for one trace. Spans with session-only attributes remain available in the session trace view. If a trace names conflicting turns or its native anchor has expired, choose an explicit source, session, and turn for Review.

After the first stored span, open the cockpit in another terminal and press 8 in Agents.

"$agenturm" cockpit --db traces.sqlite

If you target a database owned by an active history writer, the receiver returns HTTP 503 until the writer releases its lease.

Use run to start a program whose OpenTelemetry exporter already honors OTLP environment configuration. It starts a loopback listener on an ephemeral port, sets the program's trace exporter to HTTP/protobuf, and closes the listener after the program exits. The default source is otlp.run. The program keeps its standard streams and exit status. Spans without native session identity are grouped under the actual launch.

"$agenturm" run --db traces.sqlite --source-id otlp.local -- ./instrumented-program

The launcher replaces inherited OTLP endpoint, transport, and header settings, disables metrics and log exporters for this run, and adds loopback addresses to the proxy exclusions. Configure scope on the producer as described above. The launcher is for existing instrumentation and SDKs that honor these settings. OpenTelemetry exporter configuration

Use the workspace from scripts

agenturm task --help lists the native task and handoff commands. They use the same task records as the cockpit. Run agenturm attention status --db <path> for one pending-request snapshot or agenturm attention watch --db <path> for changes.

Explicitly enable installed capability executables in ${XDG_CONFIG_HOME:-$HOME/.config}/agenturm-rust/extensions.json. The file uses the inspector extension catalog with an additional enabled array of selected plugin IDs. Agenturm verifies the pinned SHA-256 and the declared data grants before starting them. An empty selection starts no capability processes. A cockpit opened with --db accepts explicit --extension-catalog and --extension options.

Discover, collect, and inspect

The bundle discovers Codex, Pi, Claude Code, Kiro, and OpenCode in their default local data directories. Discovery also honors CODEX_HOME, PI_CODING_AGENT_DIR, CLAUDE_CONFIG_DIR, KIRO_HOME, and OPENCODE_DB. It selects up to 16 sources, giving each available harness a slot before taking additional recent transcript files. OpenCode contributes one read-only SQLite source with a 1 GiB database limit, a 512 MiB WAL limit, and a 50,000-row limit. Existing follow configurations retain the roots they declare.

state="${XDG_STATE_HOME:-$HOME/.local/state}/agenturm-rust"
mkdir -m 700 -p "$state"
"$agenturm" discover > "$state/sources.json"
"$agenturm" service install --config "$state/sources.json" --db "$state/history.sqlite"
"$agenturm" service status
"$agenturm" query --db "$state/history.sqlite"
"$agenturm" inspect --db "$state/history.sqlite"

Discovery looks in $CODEX_HOME/sessions and $PI_CODING_AGENT_DIR/sessions, defaulting to ~/.codex/sessions and ~/.pi/agent/sessions. It selects up to four recent JSONL files per harness by modification time. Use --sessions-per-harness <1..8> to set the limit. Each file gets a source ID derived from its canonical path so an unchanged path resumes its stored cursor. Discovery prints a configuration snapshot. The collector watches the selected files, and newly created session files become eligible when you regenerate the config and restart the service. Previously collected observations remain available in the database. For rolling discovery, run discover --follow when creating the config. A running collector rescans the captured roots at most once every five seconds and watches the same bounded selection of newest files. It starts even when both roots are empty. A file that leaves the selection keeps its durable cursor and history. To change the captured roots or replace a static config, write a temporary file first and replace the config only after discovery succeeds.

To restart the managed collector, run systemctl --user restart agenturm-collector.service. If there is no user manager, use "$agenturm" collect --config "$state/sources.json" --db "$state/history.sqlite" --watch instead of installing the service.

The turn picker lists the recorded turns on the current history page. Use the arrow keys to choose a turn, then press Enter to open its scoped observations. A recorded pull request appears as a work result alongside the native lifecycle state.

Use review to read the typed history for an exact recorded turn as JSON. Omit --worker-id to select its workerless records. Use the same scope and the returned cursor fields to load an older page.

"$agenturm" review --db "$state/history.sqlite" \
  --harness-id <source-id> --session-id <session-id> --turn-id <turn-id>

Back up and restore

Create a history-only snapshot while collection is running or stopped.

"$agenturm" backup --db "$state/history.sqlite" --output "$state/history-backup.sqlite"

Use a workspace backup to include saved tasks, handoffs, request seen state, and review acknowledgements and notes. The destination directory must be new.

"$agenturm" backup --db "$state/history.sqlite" --bundle "$state/workspace-backup"
"$agenturm" restore --bundle "$state/workspace-backup" --output "$state/restored"
"$agenturm" cockpit --db "$state/restored/history.sqlite"

Private-content approvals require renewal after restore. Connector delivery state lives in its explicitly configured ledger. See the trusted connector runtime.

Uninstall

Run "$agenturm" service uninstall to stop and remove the systemd unit. Remove the extracted bundle directory afterward if desired. The configuration and SQLite database stay in the state directory. The extracted or a compatible Agenturm CLI can query or inspect the database after uninstall.

Qualify a release candidate

Run the archive checks on each supported platform after building from the release tag. The Linux CI workflow accepts Rust tags in the form rust-v<version>. The version comes from rust/agenturm-app/Cargo.toml. The workflow verifies the tag matches the version in the archive and retains the qualified archive and checksum as workflow artifacts. Python releases use the separate v<version> tag family.

scripts/verify-rust-linux-bundle.sh "./dist/$archive"

The verifier extracts the checksum-verified archive into a fresh state directory. It discovers and collects fixture sessions with an empty PATH, checks that reopening and replay preserve history, opens recorded turn activity in a PTY, and reopens a backup. A narrow-PTY run starts the cockpit with empty state, adds fixtures while it is open, refreshes the roster, and verifies the next collector can reopen the history after quit. Qualification uses Bash, jq, GNU coreutils, GNU tar, and util-linux script.

On a dedicated Ubuntu 24.04 x86-64 account with a running systemd user manager and no Agenturm collector unit, pass --systemd-user to verify managed install, restart, inspection, and retained data after uninstall. Also repeat those steps with real local Pi and Codex data. When a prior standalone Rust artifact is available, pass --previous /path/to/agenturm-<previous>-linux-x86_64.tar.gz. The verifier uses that artifact and its adjacent checksum to create a database, then checks that the current bundle retains its history and resumes its cursors.

Publish a qualified archive

After the tag run succeeds, download the archive and checksum from that specific run. Set run_id to the successful run for the release tag.

tag=rust-vVERSION
asset="agenturm-${tag#rust-v}-linux-x86_64.tar.gz"
gh run download "$run_id" --name agenturm-rust-linux-x86_64 --dir ./release
scripts/verify-rust-linux-bundle.sh "./release/$asset" --systemd-user

Complete the real-record checks above using the same extracted archive. Record the tag, OS and architecture, artifact checksum, and results. Attach the tested files to the existing tag with release notes identifying the supported platforms and linking to these instructions.

gh release create "$tag" "./release/$asset" "./release/$asset.sha256" \
    --verify-tag --latest=false --title "Agenturm Rust ${tag#rust-v}" \
    --notes-file "$release_notes"

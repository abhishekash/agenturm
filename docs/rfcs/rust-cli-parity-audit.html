AP1 — SDK/CLI parity audit: Python 0.2.8 against the Rust rewrite

Updated 23 November 2026. This is the AP1 audit required by the remaining-work plan and the execution plan: reconcile every retained Python 0.2.8 CLI entry point, cockpit keyboard journey, and selected SDK integration with its actual Rust code path. Every implemented row was verified by reading the Rust parse/dispatch code, not inferred from documentation. The audit records dispositions; confirmed missing journeys remain on the active Python-parity plan unless an explicit product decision retires them.

Method and boundaries

  • Python surface: observatory/__main__.py, observatory/attention_cli.py, review_cli.py, investigation_cli.py, task_cli.py, native_lifecycle.py, and the journeys in keyboard navigation.
  • Rust surface: rust/agenturm-app/src/lib.rs Command enum (:237-302), main.rs dispatch (:27-300), parse_command (:849-947), and the agenturm-ui keymap/workbench/workspace handlers.
  • Base comparison: the cutover workflows table.
  • Python receiver-attach forms (--receiver-protocol python-v0.2.8) are Linux-only in the Rust app (#[cfg(target_os = "linux")], lib.rs:863-905).
  • Classifications are exactly: implemented, test-only acceptance pending, confirmed missing feature, scope decision needed. No CLI or SDK row required the native evidence unavailable class in this audit; that class stays reserved for harness-side items such as the actual Kiro transcript (A4/Q8), which this audit does not cover.

Dispositions for previously unrecorded items

  1. attention native bind/send/hook/retry — implemented in Rust (Linux-only, token-file required); this audit is its first recorded disposition. The cutover table's attention row now covers it by reference.
  2. task draft --workspace / task handoff --endpoint revalidation — confirmed missing flags. The Rust model is offline-first with explicit local-history anchors; receiver-revalidated handoff sections need a product decision before becoming development work.
  3. task create --snapshot — implemented as an explicit opt-in to match the Python convenience while preserving the safer default: task creation alone does not inspect a workspace. The existing task snapshot command remains available for later recaptures. A failed capture preserves the task and reports its ID plus a snapshot_error.
  4. task list --offset — disposition: cursor paging (--limit/--before) is the retained model; offset paging is not planned.
  5. cockpit --no-local-agents / --metadata-only / --capability-config — disposition: replaced by the inverted explicit-grant capture model and the process-extension catalog (see process extension RFC). Flag-level parity is not planned; the capabilities are reached by different, explicit means.
  6. serve --no-auth / --allowed-host / plugin flags — remote deployment flags remain the recorded open wire/TLS gap (cutover:18); plugin flags are superseded by the Rust plugin host (disposition 5).

Findings that gate the B1/D3 cutover decision

Confirmed missing cockpit journeys and flags remain active parity work under the user's completion direction. The separate implementation plan assigns their development; this audit records the source-backed gaps:

  1. Ctrl+P action palette (choose session, save task, open workflow, investigate) beyond the theme selector.
  2. Saved-task p Brief and d Decisions cockpit editors with the decisions version-chooser journey.
  3. Ctrl+R reload of a concurrently edited saved task.
  4. Workflow h include-older-completions toggle.
  5. task draft --workspace binding and task handoff receiver revalidation.
  6. Remote receiver deployment (--allowed-host, TLS) — already recorded open in the cutover table.

Scope decisions with no development implied: o sort menu (intentional Updated ↓ ordering), compact/wide prompt-index dual mode, task list --offset, cockpit --port.

SDK coverage verdict

All five selected SDK families (OpenAI, Anthropic, LangChain/LangGraph, Google ADK, Pydantic AI) have CI jobs exercising a real Rust path via the launcher, plus the manual Python and Node clients. Caveats recorded: Anthropic shares the automatic-capture job rather than a dedicated one; the auto-capture bootstrap remains the Python OpenInference layer (a recorded product decision); and passing jobs at older heads are not current-head acceptance — Q7 owns that record. Nothing documented-but-untested remains in the SDK scope.

No workflow is retired by this audit. Installed and paired-state acceptance remains with the separate test owner (CF1–CF7 and Q1–Q10).

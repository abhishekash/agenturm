# Rust-only Agenturm execution plan

Status: scope reset on 21 November 2026 at the user's direction. This document supersedes the Python-bridge, compatibility, and migration portions of `rust-plugin-kernel-plan.md` for all future implementation.

## Product decision

Agenturm is being rebuilt as a Rust application. Python is not part of the target runtime. Do not preserve Python runtime compatibility, create dual-runtime paths, route Python clients through a Rust bridge, or build data-migration tooling. The Rust application starts with its own clean data directory. Existing Python-era state is out of scope for automatic import.

The application keeps three independent extension families:

1. **Harness adapters** discover and decode agent activity, then submit bounded observations to the kernel.
2. **Capabilities** derive optional, typed signals from authorized observations.
3. **UI contributions** provide data-only panes; the Rust UI owns layout, navigation, focus and terminal lifecycle.

Connectors remain a later runtime extension family. The new `agenturm-connector-api` crate defines preliminary, versioned inbound and outbound contracts; it does not yet register, supervise, authorize, or persist connector work. The **target** kernel owns extension identity, policy, durable writes, query boundaries and supervision. The current `agenturm-kernel` owns supervised admission and a bounded durable observation read port, but not product policy, app configuration (which lives in CLI input), or process supervision. Rust performance is a user-chosen implementation direction; no gain is claimed without whole-application measurements.

## Milestones and gates

### 1. Rust composition kernel — foundation implemented

Deliver typed extension ports and deterministic registries for harnesses, capabilities and UI contributions. The host stamps source identity, validates bounded snapshot results, records returned errors/unwind panics, and returns a render-neutral snapshot. This seam is synchronous and trusted; it is not a process, time or allocation isolation boundary.

**Current evidence:** `agenturm-kernel` provides these three ports, stable ID-ordered polling, validated result bounds and per-extension error reporting. Supervised source adapters register by extension ID; the kernel validates facts, commits the durable cursor and observations through a storage port, then ACKs. In-process extensions can register individually or as a build-time `ExtensionPlugin` package; package registration stages harnesses, source adapters, capabilities, combined observation extensions, and UI contributions and commits them atomically after duplicate and capacity checks. The app exposes registration seams for all three in-process extension families. A combined `ObservationExtension` port now evaluates trusted capability and pane output once, validates both before publishing either, preserves durable query scope in its input without changing the public `Snapshot` shape, rejects ID collisions with capabilities/panes, and is skipped when durable history reads fail. The process-plugin follow-on is now in progress in [the process extension RFC](rust-process-extension-plugins.md): explicit catalog selection, strict DTO projection, and one-shot process supervision are wired in the current worktree; the standalone Rust example is packaged; end-to-end tests and independent Rust/security reviews pass locally. `refresh_with_store` reloads a bounded newest page of committed observations before evaluating capabilities and panes; the Rust store supports close/reopen reads and reports when older rows are outside the page. Versioned source configuration now composes up to 16 registered process adapters in one collection; version 2 selects user-managed, SHA-256-pinned adapters from an explicit catalog and verifies catalog artifacts before opening the store and again before host launches. Linux systemd user-service installation is now available; automatic discovery, dynamic capability/decoder loading, and cross-platform service managers remain open. Catalog integrity checks do not sandbox adapters; children retain the Agenturm user's OS privileges. Trait extensions are trusted in-process code: calls are synchronous, result checks follow extension allocation, and caught panics still run the standard panic hook. This does not establish the full-screen UI.

### 2. First real Rust vertical slice — durable admission/read primitives implemented; gate open

Wire one bundled Rust harness through the process protocol into the kernel, persist its observations in a Rust-owned SQLite store, and render/query the same session after restart. Exercise duplicate replay, malformed output, adapter crash, store failure before commit, and process restart. The runtime must not start or import Python.

**Current evidence:** the kernel now reconstructs committed typed observations after reopening the SQLite store, and a generic capability/pane can evaluate that durable history. Real-process tests cover Codex ingestion, commit retry, follow-up polling, and kernel rehydration from a reopened database. An injected `SourceBatchDecoder` boundary lets the same supervised source handle different harness IDs; the Pi process test covers decoder reset, durable commit retry, ACK, and reopened-store rehydration. `agenturm collect --config <json> --db <path>` runs several configured adapters through one kernel and store transaction path; version 2 selects user-managed catalog entries with protocol/features declarations and SHA-256 pins; `--watch` retains adapters between repeated polls and closes them on handled shutdown. CI proves actual Pi and Codex processes in the same run and reads both sessions after reopen. The store, kernel, and app now expose a bounded source/session-filtered keyset query. Query pages pin to a durable receipt watermark, so later collection writes cannot shift a traversal; `agenturm query` returns a reusable cursor, and `inspect` can page to older history with `[` and return through a four-page in-memory back stack with `]`. See the [history query validation record](../validation/rust-general-history-query.md) and [plugin catalog validation record](../validation/rust-plugin-catalog.md). Linux systemd user-service install/status/uninstall is implemented for the foreground collector; automatic discovery and dynamic capability/decoder loading remain open.

See [configured harness collection](rust-collection-config.md) for the versioned JSON schema, path rules, and current runtime limits.

**Gate:** an installed Rust application can discover actual local harness data, commit one session atomically, restart and render it from durable state. A fixture worker alone does not pass.

### 3. Rust UI and capability composition — generic viewer and crate-level composition implemented; runtime discovery open

Build the Ratatui application over kernel query/pane models. Register one built-in capability and one independently packaged pane without editing the central app's view dispatch. Cover no sources, empty history, partial adapter failure, stale data, terminal resize and narrow terminal behavior. UI remains data-only at the extension boundary.

**Current evidence:** `agenturm-ui` is a separate Ratatui crate that renders contribution panes, capability metrics and failures through generic model data; it does not dispatch on harness or capability IDs. A separately packaged example implements a capability and data-only pane through the public kernel traits and an `ExtensionPlugin` package; the app installs both alongside the built-in Overview through atomic build-time composition, rejects duplicate package IDs, and leaves no partial contributions after a failed package install. TestBackend tests render the pane at 80×24 and 60×18. This proves crate-level static composition, not dynamic binary discovery or process isolation. See the [independent UI extension validation record](../validation/rust-independent-ui-extension.md) and [example package](../../examples/rust_lifecycle_extension/README.md). `agenturm inspect --db <path>` reopens the Rust store and displays the bounded durable snapshot, with keyset-backed older-page navigation. `agenturm query --db <path>` supports bounded read-only source/session filtering and emits the next stable cursor as JSON. The Overview now reports the latest safe diagnostic code, severity, source and source/session scope alongside the diagnostic count. The UI has explicit small-terminal handling, pane navigation, row scrolling, and a managed terminal lifecycle. State and rendering tests cover selection and wide, narrow and too-small dimensions. Cross-platform service managers, runtime plugin discovery, and a PTY lifecycle test remain open.

### 4. Harness and domain parity — typed tool, lifecycle, check, and message slices implemented; gate open

Port each supported harness to Rust and map its source identities, lifecycle, usage, tool activity, relationships, coverage gaps and content-grant behavior to typed kernel events. Keep provider-specific parsing and identity rules in the adapter crates. Prove source fixtures against the documented product behavior; no Python differential runtime is required.

**Current evidence:** the shared bundled decoder preserves source-neutral tool observations (`category`, `result`, and native `operation_id`), lifecycle observations (`state` and optional bounded `reason_code`), check observations (`category` and `result`), message role observations (`user` or `assistant`), and privacy-safe diagnostics (`code` and `severity`) alongside usage facts. Diagnostics use explicit source/session scope; only closed-catalog codes are retained, while unknown codes remain count-only. The Overview displays the latest diagnostic and lifecycle evidence with source/session identity. Pi and Codex process fixtures prove interrupted lifecycle state, source reason codes, and both message roles survive commit, ACK and reopen. Codex process fixtures prove lint check category/result survives the same path. The app query JSON exposes typed fields. Message body/content, commands, outputs and raw error messages are not retained. See the [tool observation validation record](../validation/rust-tool-observations.md), [lifecycle observation validation record](../validation/rust-lifecycle-observations.md), [check observation validation record](../validation/rust-check-observations.md), [message observation validation record](../validation/rust-message-observations.md), [source-scoped diagnostics record](../validation/rust-source-scoped-diagnostics.md), and [diagnostic inspector record](../validation/rust-diagnostic-inspector.md). This is a bounded domain slice; relationships, check coverage gaps, content grants and complete harness parity remain incomplete.

### 5. Rust-owned persistence and recovery — primitive implemented, integration open

Implement schema creation, bounded writes, transaction receipts, replay, correction, revocation, retention, backup and crash recovery as native Rust behavior. Start from a new Rust-owned data directory; do not import the legacy Python database. Test kill/restart around each commit boundary and validate recovery from SQLite WAL state.

**Current evidence:** `agenturm-store` is a Rust-owned observation store and implements the kernel storage port. It atomically binds source-scoped event IDs and revisions, explicit source/session scope, typed session/worker/turn/operation identity, nanosecond timestamps, content-bound request receipts and opaque 800-byte expected/next cursors. Exact replay (including retry after later cursor advance), stale-cursor rejection, deterministic request IDs, rollback injection, unrelated-database rejection and close/reopen reads are tested. `agenturm collect --config <json> --db <path>` loads a bounded versioned config, registers up to 16 process adapters together, and admits them through one kernel and store; version 2 resolves adapters through a user-managed catalog, pins their artifact hashes, and checks protocol features at handshake. `--watch` retains process adapters between cycles until shutdown. `ingest-usage --plugin-id ...` and `ingest-codex-usage` remain one-source shortcuts. The kernel commits before sending ACK. The shared observation decoder preserves partial and cached usage counters (including absent-versus-zero), typed tool category/result and opaque operation identity, typed lifecycle state/reason evidence, typed check category/result, typed message role and safe diagnostic code/severity; malformed or unsupported facts fail closed. Local real-process tests exercise Pi and Codex host/adapter processes through this decoder and reopen usage, tool, lifecycle, check, message and diagnostic observations from the Rust store. The shared store schema is v8, with transactional v2→v3→v4→v5→v6→v7→v8, v3→v4→v5→v6→v7→v8, v4→v5→v6→v7→v8, v5→v6→v7→v8, v6→v7→v8 and v7→v8 upgrade coverage. Lifecycle facts collected before v5, check facts collected before v6, and message facts collected before v7 cannot be reconstructed because those facts were not previously stored and the source cursor has advanced. This remains short of the full gate: automatic discovery and dynamic capability/decoder loading, and support for all domain facts are open, and service support currently targets Linux systemd user managers. The app still has no production service identity, cross-process writer fence, product policy, retention, backup, or full crash-recovery drill. Catalog hash checking is not a sandbox.

### 6. Capability SDK, packaging and connectors

Package harnesses and capabilities independently while shipping a useful default bundle. Publish extension contracts only after at least two real harnesses and one capability use them. A preliminary connector API now has separate inbound and outbound ports, bounded DTO validation, stable delivery request digests, and fake source/sink contract tests. Inbound work must commit with its checkpoint before ACK. Outbound attempts are at-least-once; ambiguous outcomes are reconciled by the same idempotency key, never assumed to be exactly-once. See [the Rust connector API RFC](rust-connector-api.md). Runtime registration, process supervision, host-owned grant evaluation, durable inbound checkpoints/outbound receipts, retry scheduling, revocation fencing, credential policy, and OS isolation are not implemented. Connector processes must not be treated as sandboxes; no third-party executable is safe to authorize until least-privilege isolation and credential boundaries exist. Connector runtime work remains gated behind the Rust service, recovery, and packaging critical path.

## Current blockers

- The Rust TUI can inspect durable snapshots, and the app can poll a bounded configured set in foreground watch mode; versioned process-adapter catalog selection is wired; automatic discovery and dynamic extension loading remain open. Linux systemd user service installation is wired; cross-platform service support remains open.
- Existing harness crates are standalone processes; the app composes configured Pi and Codex adapters through kernel-owned admission and can select catalog entries by ID, but does not automatically discover plugins, dynamically load decoders/capabilities, or expose all domain facts yet.
- The Rust observation store now supports bounded source/session queries and receipt-watermarked keyset pagination; the app's query and inspector paths use it. Domain-specific query families, broader filters, and a separate production storage service identity remain open.
- Existing Rust admission and query work proves bounded subsets, not product semantics across all evidence and policy cases.
- The service unit and plugin descendants run under the same user identity; a separate storage authority or tighter child sandbox is still required for untrusted adapters. Cross-platform managers, automatic discovery, dynamic extension loading, packaging, crash recovery and release workflows also remain open.

Do not call the project Rust-only, end-to-end, production-ready, or faster until the corresponding milestone gate has passed. Validating the Linux service install on a managed host, extending restart queries to the remaining domain facts, and completing cross-platform packaging remain on the critical path; optional connector and sample-only work must not displace them.

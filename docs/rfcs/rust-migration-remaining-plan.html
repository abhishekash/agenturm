F4. Connector profiles beyond the qualified local boundary

Existing tasks: C6–C8. Owner: connector runtime/security boundary.

C6 and C7 are implemented and locally qualified for their documented scope: isolated_linux runs pinned static Linux x86-64 connectors using staged inode verification, Landlock, seccomp and descriptor isolation, with fail-closed setup. The child has framed I/O and cannot create files, sockets or processes. unix_status_v1 is a host-mediated outbound transport. Its grant binds endpoint, peer UID/GID, private credential reference, artifact and policy epoch; it checks peer/inode before opening the private token and rechecks authority before write. Bounded status operations, redacted receipts and same-key reconciliation pass. These controls must not be reassigned as wholly missing features.

Remaining feature scope: HTTPS/general provider transport, production credential provisioning and sandbox support on other architectures remain unimplemented. Implement the profiles actually selected for production; do not claim arbitrary outbound permissions or portable isolation from the local proof. Existing C6/C7 behavior needs deployed acceptance, not reinvention.

Done when: the selected supported configuration passes Q9 under least privilege, with any required new profile implemented first. An approved production endpoint/configuration is still needed. Keep unsupported profiles and unqualified production activation disabled. See the connector contract and profile limits.

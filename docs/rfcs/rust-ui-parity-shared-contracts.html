1. Shell invariants

The shell owns terminal lifecycle, navigation, focus precedence, the action inventory, the palette, help and the footer. Lane modules own their models, rendering and screen-specific actions. The shell is generic over model data: no provider ID, extension ID or app-level special case appears in shared code.

One inventory

keymap::ACTIONS drives footer hints and F1/? help. Each row has a stable id, keys, label, detail, group and contexts.

One palette

Ctrl+P opens palette::Palette. It returns a stable key; it never performs app work itself.

No hidden focus

Every key has one owner. Unknown keys are inert. A chooser owns Escape before its enclosing form.

No destructive help

Opening or scrolling help mutates nothing. Drafts, selection, filters, cursor and scroll survive.

No late replacement

Responses carry a navigation generation. A superseded response is discarded with a visible reason.

No invented names

Missing titles are derived by the owning screen from title, nickname, provider, role and project; unknown values stay explicit in Details.

3. Action inventory

pub(crate) struct Action {
    pub id: &'static str,        // stable dispatch/palette identifier
    pub keys: &'static str,      // documented keys, e.g. "Ctrl+P"
    pub label: &'static str,     // footer/help/palette label
    pub detail: &'static str,    // one-sentence explanation
    pub group: Group,            // VIEWS, SESSION, EVIDENCE, LIVE, ...
    pub contexts: &'static [Context],
}
  • Context is CommandCenter, History, Workbench, Investigation or Form.
  • keymap::actions(context), help_sections(context), hint(&[id, …]) and find_action(id) are the public seams.
  • keymap::PALETTE_EXCLUDED names keys without an unambiguous palette command (currently only modifier-plus-direction agent-family navigation).
Adding an action. Add one id constant, one ACTIONS row with the right contexts/group, and one dispatch arm in Workspace::run_action (send the documented key or call the same typed request). Do not add a second key table or help string. Use keymap::hint for the shared footer portion.

4. Focus and key ownership

keymap::Focus names the current owner; Workspace::focus() derives it from state. No lane stores a second focus object.

Ownership rules

  1. Chooser Escape. A chooser consumes Escape before an enclosing form or screen. It restores the opening control and changes no data.
  2. Literal text. Text fields keep letters, digits, [, ], /, ? and punctuation. F1 remains available while editing and returns to the same draft.
  3. Question mark. ? opens help outside text entry; in search/editors it is text.
  4. Tab order. Palette/help move through visible choices. The command center keeps Python's status-filter Tab and the inspector keeps pane switching; these are documented screen-local exceptions.
  5. Activation. keymap::activate is Enter or Space. The theme picker applies with either. A dialog activates only a visible control.
  6. Ctrl+C. Public loaded-evidence focus (command center, history table, evidence inspector) copies the loaded metadata view and stays open. Private prompts, text editors, forms, palette and help keep terminal interrupt/quit. c always copies, x exports, q quits.
  7. Drafts. Help, resize and cancel preserve search drafts, export directories, workbench edits and private prompt deadlines/fences. Cancel explicitly restores the prior value.

Precedence: private interrupt → help overlay → palette overlay → Ctrl+P → help shortcut → private prompt → form/investigation → workbench → search filters → history choosers → history keys → command center.

5. Command palette (Ctrl+P)

palette::Palette is a data-only overlay; Workspace::open_palette builds entries from the current context.

Entry {
    key: String,       // command id or "session|<harness>|<session>"
    label: String,
    detail: String,    // or an explicit unavailable reason
    group: String,
    enabled: bool,
}
  • Search. Typing edits the query in place; digits, brackets, ? and punctuation are literal; space is text. Up/Down, Tab/BackTab move; PgUp/PgDn, Home/End jump; Enter runs an enabled row; Esc cancels; Backspace edits; Ctrl+A clears. Empty results stay open with a message.
  • Stable selection. Filtering retains the selected key while visible; a missing key selects the first deterministic row.
  • Run. The palette closes before Workspace::run_action executes the same path as the documented key.
  • Session chooser. Choose agent session freezes the roster in approved newest-first order. session|all clears only the session filter. A chosen identity is re-resolved; if gone, the chooser reports “That session is no longer available. Choose another session.” and changes nothing. Escape cancels before the monitor handles Back.
  • Themes. Ctrl+P no longer opens appearance. Themes stay on F2 and are a palette row. The picker remains reversible: preview, Enter/Space apply, Esc restore, saved preference.
  • Contents. Destinations; session chooser; Today/History; evidence scope to the exact session/turn or all sources; pause/resume and refresh/retry; diagnostics; five retained-history investigations; Review, Prompts, Traces, turns, MCP payloads, edits, notes, acknowledgement; page navigation; copy/export; internal reviews; Workflow and saved tasks; search, inspect, back, quit.
  • Unavailable rows. A row that cannot act stays visible as Unavailable · reason; it does not run and never fabricates a selection.
  • Rendering. Centred popup with search line, visible count, scrolling list, two-line detail and hint. Usable at 60×18; below 20×6 it shows a resize message and Esc cancel.
  • Privacy. Entries contain labels, ids and reasons only. The palette never reads captured prompt text.

6. Contextual help (F1 / ?)

  • F1 opens from every non-private context, including editors, palette and session choosers, forms, history, workbench and investigation. Help over a chooser returns to the frozen chooser state. ? opens outside text entry.
  • The first section is the current context; THIS VIEW lines name the exact session/turn, review state, captured text, evaluations, MCP payloads and workflow draft behavior when present.
  • Up/Down, PgUp/PgDn, Home/End scroll. Esc, F1 or ? close; q quits when no private content is open.
  • Closing returns to the exact originating control. The shell does not reconstruct the underlying model, so drafts, selection, filter, cursor and scroll are untouched.
  • One border, terminal-cell wrapping and a visible Esc, F1 or ? close help hint. Readable at 60×18.
  • UI-03 should remove the legacy command-center help body when it next edits command_center.rs; the shared overlay already includes every command-center action and the Rust-only destinations. Workbench keeps its private flag only for direct tests.

7. Header, footer, themes and connection state

  • Keep the Agenturm summary, horizontal view strip, active scope and connection state recognizable. “Paused”, “Loading…”, “History reader stopped”, scoped denials and stale/partial notices stay visible.
  • Footer priority: explicit error/message → pending load → current-view hints → keymap::hint inventory hints.
  • Five themes: Observation, Current, Bright, Dark, Solarized. F2 previews; Enter/Space applies; Esc restores. Preference is $XDG_CONFIG_HOME/agenturm-rust/ui.json, owner-only writes; AGENTURM_UI_PREFERENCES=0 disables persistence.
  • NO_COLOR removes colour, not structure: selection uses reverse/bold and status text stays readable.

  • AgentList::apply_filters restores the selected session by exact identity; a vanished identity keeps the nearest prior row and sets lost_selection so the caller shows why.
  • UiModel::restore_view restores the pane by title and scroll when it still exists; a missing pane keeps the nearest deterministic row and reports “<pane> is no longer in this page · kept the nearest view”.
  • Independent time/session scopes survive refresh. A refresh never silently clears them.
  • Workspace::request stamps the in-flight request with generation. Closing a history view, returning to Agents, closing a workbench surface or superseding a review context increments it. Workspace::finish discards mismatched responses with “Discarded a late response for a closed or superseded view”.
  • The single-pending/deferred queue and loader thread remain the backpressure boundary. event::poll(80 ms), resize and overlay redraws keep the loop responsive.

9. Lane integration

UI-03 · command center

Consume the shared help sections; wire Today/History to time_scope with the tagged boundary; use the session chooser action; preserve exact selection through title, resize and refresh.

UI-04 · prompts

Add prompt actions with exact request identity and scope. Escape order: chooser → reader → section → roster. Report retained caps and unavailable private content through the status contract.

UI-05 · observability

Add filter/detail actions to the inventory. Preserve occurrence identity, filter, page cursor and snapshot; report a missing occurrence and choose the nearest row. Keep / inside focused filters; F1 keeps drafts.

UI-06 · review and workflow

Add Tab/Shift+Tab button order, Enter/Space activation, chooser-first Escape, dirty-editor confirmation and palette rows for settings, alerts, retry, resume, save and handoff.

UI-07 · visual

Compare overlays at 120×32, 80×24 and 60×18. One border per region, one selection cue, semantic palette colours, readable NO_COLOR state, focus and draft preserved after resize.

All lanes

Do not edit the shared shell files except through UI-02. Add one inventory row per action. Never render Name unavailable. Use exact identities and explicit unavailable reasons.

11. Known gaps handed to dependent lanes

  • Today boundary (UI-03). The shell's provisional rule is UTC day + active/pending. The tagged Python boundary and timezone need the fixed-clock matrix.
  • Evidence row identity (UI-05). Pane, scroll and filter identity are preserved; selected operation/finding/point identity across pagination needs the owner's stable key and a missing-identity notice.
  • Workbench palette coverage (UI-06). Shared rows work over workflow, tasks and investigation; workflow-specific palette rows, button Tab order and dirty-editor confirmation remain with the surface owner.
  • Mouse equivalence. The shell is keyboard-first; any mouse route added by a screen must call the same action id.
  • Visual matrix (UI-07). Overlay spacing, semantic status styles, monochrome cues and CJK/emoji clipping need the paired visual pass.
Acceptance requires the exact installed candidate. Unit checks in this lane do not replace the paired UI-Q matrix against the tagged Python build.

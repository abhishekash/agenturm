# Inbound connector adapter contract, version 1

This contract specializes Agenturm's framed `source-adapter/1` transport for read-only connectors. A connector advertises `connector-adapter/1` in its pinned manifest and child `hello_ack`; the explicit source config lists it under `requires_features`. Server preflight checks the manifest claim without launching a child or creating a Store. After Store activation, the generic supervisor checks the child handshake before polling. No connector-specific dispatch branch is required. The connector uses the existing host-owned source lease, capture policy, durable cursor, evidence admission and projection. It cannot send an outbound action through this protocol.

The manifest also declares `configured-root/1` and `configured-source-read` for the configured local connector file. This loopback fixture additionally declares `loopback-http-read`. Grants are host admission declarations, not an OS network sandbox. This fixture validates its URL at startup and follows no redirects; the config file's endpoint can still be edited by the same user within the permitted loopback class. A production connector needs explicit endpoint identity and credential policy before general network access.

## Frame sequence

Every frame is length-prefixed UTF-8 JSON. Protocol major is integer `1`. The host sends `hello` containing its approved plugin ID, source ID and frame limit. The child replies with `hello_ack` and a feature list contained in the manifest that includes `connector-adapter/1`. The host sends one `poll` with the last committed cursor, record and byte budgets. The child replies with one `batch`; only after the host transaction commits the records, cursor and dirty marker does it send `ack` for that cursor. A failed commit or malformed batch closes the child without ack. `stop` requests shutdown. The data and control frame limits are inherited from `source-adapter/1`; a batch has at most 256 records, and the worker remains alive across polls.

The connector cursor is opaque to the host. This fixture encodes the service page token and last observed event timestamp in a bounded cursor. An idle page or `429` returns an empty batch with the unchanged cursor; the host acknowledges it without a new write. The child delays subsequent polls after `429`, while the service remains authoritative after a process restart. A service `410` for an old token produces a durable `cursor_expired` warning and a gap cursor. Once that gap batch is committed and acknowledged, the child requests the first currently available page. A fresh cursor that also gets `410` fails the worker. The warning reports possible missing source records; it never certifies recovery or complete coverage.

Distinct source record IDs are distinct occurrences. Repeated IDs with higher revisions correct an occurrence; duplicate same-revision records are idempotent only if their bytes match. The host validates metadata, identity, policy epoch and lease before its single write transaction. The child cannot choose another receiver or acknowledge itself. A crash after commit but before ack resumes from the host cursor without duplicating evidence. Capture revocation fences active workers, erases this source's admitted metadata/projection and retains the last acknowledged source cursor. Re-enabling requires a new explicit policy epoch and does not silently replay erased history.

This v1 fixture admits lifecycle and usage metadata plus coarse diagnostics. Content, arbitrary text, source credentials, message/tool/check parity, retention guarantees for external services and general endpoint policy are outside this contract proof. At the current 50,000-distinct-record source cap, the host can evict an oldest half-window atomically and expose a durable retention gap; affected sessions lose terminal, usage and confirmed relationship projections. It is not a lossless external spool.

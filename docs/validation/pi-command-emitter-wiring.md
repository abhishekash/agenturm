# Opt-in Pi requested-command reference emitter

Recorded 20 November 2026. This checkpoint wires the receiver-owned command admission primitive to an **explicit** Pi directory capture mode. The default Pi process reader remains metadata-only; user-text and requested-command modes are mutually exclusive. Python Store remains the sole production writer for the receiver database. No performance gain or full Pi parity is claimed.

## Boundary

`--directory --command-refs` installs a separate source ID, `pi-review-text-command-v1` capture, `pi-command-ref/1` feature, and a SHA-pinned Rust Pi binary. The host requires the Pi replacement claim, configured root, read grant, discovery/root-gap features, and a matching negotiated batch handler before it mints a command grant. The child process receives an exact selected batch feature and emits `command_refs` with schema version 1. Ordinary and user-text envelopes remain strict. A command batch never carries command bytes, arguments, source contents, or a child-chosen path to be trusted by the receiver.

The Rust reader nominates only a `bash` `toolCall` in an assistant row with a same-batch content-free started shell fact. It checks a bounded prefix, source generation, member identity, complete JSONL row, and preceding Pi user turn before nominating an offset, row hash, block index and call identity. The host independently opens the configured root and member without following symlinks, checks the durable member checkpoint and row/tool/turn/timestamp proof, and stores at most 4 KiB of best-effort redacted requested command text in a separate table. A started fact proves only that Pi recorded a request; it does not prove the command ran or succeeded. Tool-result text and non-bash calls cannot nominate command content.

Idle, root-gap and member-gap batches carry an empty `command_refs` envelope. A gap invalidates prior command content. Exact accepted replay retains the receipt; altered references fail. Capture revocation removes command rows and receipts atomically with policy change. Command bytes do not enter process frames, retained Activity, or ordinary copy/export output. There is **no command-specific HTTP, TUI, Review, copy, or export read path** in this change. Logical deletion does not sanitize SQLite pages, WAL archives or backups.

## Verification

The focused Rust Pi test suite checks exact command nomination, prior acknowledged user turn, non-bash and changed-file suppression, plus existing user-text and metadata behavior. Installed receiver tests check exact wire reference, metadata default, separate mode, empty idle/root-gap envelopes, non-bash and result-only cases, redacted Store row, Activity/copy output, replay and revocation. Existing Pi content transport, config, runtime, batch handler and admission suites cover compatibility. The remaining read/delivery gate must bind a selected Activity item to policy-current exact source proof and label it **Requested shell command** before any preview can be shown.

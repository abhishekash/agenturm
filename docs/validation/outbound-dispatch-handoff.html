Outbound dispatch handoff checkpoint

20 November 2026. This is a feature-off quiescence guard for the fixture outbound queue. No receiver starts it automatically, no Rust production writer is enabled, and no destination is published.

OutboundQueue.dispatch_handoff_guard(timeout) holds an exclusive POSIX flock for the entire caller-owned context. Ordinary dispatch holds a shared flock across its claim, external action and final Store write. Reconciliation now holds the same shared flock across its initial read, external status lookup and final Store write. Recovery uses an exclusive flock. The handoff guard therefore waits for a cooperating action or lookup already in progress and excludes new cooperating ones until the caller leaves the context. Flock acquisition uses a positive timeout of at most 60 seconds and never reports success after that deadline; filesystem calls themselves cannot be preempted safely.

The lock file is opened with O_NOFOLLOW | O_CLOEXEC, mode 0600. Before and after acquiring the flock, on explicit guard.verify(), and when leaving the context, Agenturm compares the opened file with its pathname and requires one regular link, current-user ownership and private permissions. The handoff path also requires a direct, singly linked 0600 database in a current-user-owned private parent, checks replaceable ancestors, and pins both database and parent device/inode. A symlink, replaced lock or database pathname, changed mode or hard link fails closed. Explicit or shared paths without this private-parent proof are unsupported by this guard. This is a cooperating lock, not a sandbox against an old binary or a same-user swap-and-swap-back race between checks.

The future cutover order is: stop outbound scheduling; acquire and retain this guard; quiesce the Store and other writers while still holding the guard; verify it again before each authority-changing step; then reconcile or migrate every durable in_flight/uncertain delivery and its idempotency receipt. Releasing the context before migration ends removes dispatch exclusion. Grant, revoke and enqueue operations do not acquire this flock; they require Store admission fencing and a complete mutation route. Other Store instances and older binaries remain separate gates.

Validation: python -m unittest tests.test_fake_outbound_connector -q passed locally. Tests hold an external reconciliation lookup while another queue instance times out acquiring the guard; a successful guard blocks recovery and reconciliation. A crashed lock owner releases its OS flock, after which recovery marks a stranded claim uncertain. Symlinked, replaced, world-readable and hard-linked lock files and replaceable database parents are rejected. Existing fixture delivery, retry, revocation and lookup tests remain green.

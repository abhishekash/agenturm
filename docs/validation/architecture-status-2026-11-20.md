# Agenturm kernel architecture checkpoint

Recorded 20 November 2026 at merged main `43c4b17` (PR #210). This is an implementation checkpoint for the [reviewed Rust kernel plan](../rfcs/rust-plugin-kernel-plan.md), not a completed migration or a speed claim.

| Building block | Working path | Remaining acceptance work |
| --- | --- | --- |
| Harness adapters | Trusted bundled native readers register source, format and turn Review contributions. Opt-in Rust Pi, Codex, Claude Code, Kiro and OpenCode process readers use framed supervision, Store admission, durable cursors and explicit source replacement. Codex directory mode can track up to 48 files through one process with atomic member checkpoints, a four-file poll budget and fair scan progress. Durable member ownership narrows a file gap to its proven sessions; legacy or ambiguous ownership falls back to source-wide invalidation. The shared JSONL runtime verifies each file's acknowledged prefix; OpenCode's `oc2` cursor catches same-count row replacement and ordinary restored-mtime rewrites. | Only Codex has bounded directory discovery. Process readers still need broader native-format and source-to-Review/export parity before default replacement. A missing/unreadable directory leaves prior projected outcomes as last recorded while source health reports unavailable; whole-root failure disposition remains open. Full-prefix JSONL verification can read up to 1 GiB per idle poll at the 512 MiB ceiling; whole-app cost has not been measured. |
| Connectors | An isolated inbound loopback fixture proves pagination, rate limits, durable cursor, expiry, replay and capture revocation. A fixture-only action process proves grants, durable outbox, idempotency, uncertain-response lookup and recovery fencing. | Real destinations, credentials, user controls and production delivery are not enabled. |
| Capabilities and UI | Generic pane registration renders a bounded Prompt signals process model at 60×18. Its receiver-side aggregate endpoint checks exact native ownership and capture provenance at request time, with a database change watch before response. Native MCP config inventory comes from trusted adapter declarations. Host and plain output render bounded, source-neutral coverage descriptors, including unknown or failed process projection states. `/api/health`, the session inspector, Host and plain output surface unavailable process sources without changing stored run outcomes. | Capability process activation remains opt-in and UI models refresh asynchronously. Prompt signals reports observations rather than efficacy. General third-party SDK and broader metric capabilities are open. |
| Rust host and distribution | The opt-in Rust process host runs installed adapters under Python Store and policy authority. Control writes, backpressure, bounded discovery and process-group cleanup have regression coverage. A Linux x86_64 wheel bundles a SHA-pinned host and passes isolated installed receiver checks; the pure wheel remains functional. | Further platform wheels, publication gates, default activation and a measured whole-app performance result remain. |
| Durable authority | Python Store owns capture policy, leases, admission, global and member cursor/commit/ack, session-member ownership, retention, projection and the sole database writer. A read-only Rust shadow snapshot is fenced by receiver, lease, policy, dirty sequence and published revision. Pure Rust reducer fixtures v1–v3 match Python lifecycle, usage, relationship, Activity and durable source-gap invalidation on the tested corpus. A pure Rust exact-session query checks source scope and always reports partial coverage over a validated v3 snapshot. | The Rust query is offline and cannot itself check snapshot freshness. Full live query/storage compatibility, Rust authority, legacy writer exclusion, one-writer cutover and rollback drill remain. No production data is written by Rust storage. |
| Validation | Focused Rust workspace and installed receiver tests passed for the merged slices. PR #204 passed 74 installed harness and Store tests plus an independent 22-test admission/discovery check after review fixes. PR #210 passed 64 Store tests (1 skipped) and 6 installed Codex directory tests; independent final-head checks passed 20 Store and 6 installed tests. The broad PR #188 Python snapshot ran 1,639 tests with 43 skips and one disk-reserve failure; that exact smoke passed alone after cleanup. | The broad snapshot is not green and predates newer merges. GitHub CI for recent PRs was queued. The retained-history under-5% CPU gate, sustained-write latency gate, full installed-client matrix and migration drill have not passed. No Rust performance gain is asserted. |

An independent Rust architecture review found the crate dependency direction clean: the host depends on the protocol, harness binaries depend on shared source crates, and the domain reducer and exact-session query have no harness dependency. It found no merged Rust path writing directly to Agenturm's Store. The first bounded multi-session path is now present for Codex, with Store-owned member ownership and a visible source availability overlay. The next correctness gates are complete evidence parity for one real harness, whole-root failure disposition, and live query/storage compatibility. Remaining Python compatibility logic should leave generic services through registered contributions.

Python remains the sole writer until source semantics, query compatibility, crash recovery and rollback gates pass. The user chose idiomatic Rust for the implementation; performance is measured separately and is not a prerequisite to continuing the architecture work.

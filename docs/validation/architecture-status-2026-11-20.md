# Agenturm kernel architecture checkpoint

Updated 20 November 2026 at merged main `4913e66` (PR #264). This is an implementation checkpoint for the [reviewed Rust kernel plan](../rfcs/rust-plugin-kernel-plan.md), not a completed migration or a speed claim. The [execution ledger](../rfcs/rust-plugin-kernel-plan.md) lists the intervening PRs through #261.

## Current architecture through PR #264

- **Harness adapters and UI contributions.** Trusted adapter declarations now own more native reader behavior, including Kiro collector status, Codex state context, and a generic native status registry. Opt-in Rust Pi user-text and requested-command emitters pass exact source references through host admission; normal capture remains metadata-only. A trusted Activity content-provider registry supplies transient, explicit `z` previews. PR #262 adds the Pi requested-shell-command provider over the exact local command route. Its redacted text is limited to inspector state, expires after 20 seconds, is rechecked, and does not enter Activity rows, copy, Review or export. A requested command does not prove execution or success. See [the preview validation](pi-command-activity-preview.md) and the [execution ledger](../rfcs/rust-plugin-kernel-plan.md).
- **Rust storage boundary.** The Linux service remains feature-off and probe-only. Its v1 socket listener checks peer credentials and framed request identity; it opens no canonical database. PR #263 adds an installed Docker test using separate service and client UIDs/GIDs: the accepted probe works, wrong credentials and receiver are rejected, and fresh Python `Store` opens against a service-owned private data root fail for both absent and existing disposable SQLite files. This does **not** revoke an already-open legacy writer handle. PR #264 adds a data-only, 64 KiB v2 lifecycle admission request/reply contract and canonical replay comparison. Its digests, lease and policy fields are untrusted assertions until a future service validates and commits them durably; no v2 service dispatch or production mutation exists. See [the account proof](rust-storage-distinct-principals.md), [v2 contract](rust-storage-mutation-v2.md) and [writer ownership gate](rust-writer-cutover-gate.md).
- **Writer cutover gates.** Python `Store` remains the production canonical writer. The write inventory includes `Store` initialization, migration, derived repair, OTLP and retention; plugin admission and projection; receiver policy; outbound delivery; separate `WorkflowStore` and `TaskStore` databases; and native lifecycle outbox writes. A point-in-time authority marker and cooperative locks cannot exclude old processes with already-open SQLite handles. Before enabling Rust authority, route every durable mutation through the service, prove workers and checked-out read/write leases quiesce before releasing ownership, use a protected versioned canonical path under a distinct service identity, and run adversarial old-binary tests against both canonical and archived paths. Migration needs a consistent backup including WAL, receiver identity and receipt verification, and a forward-recovery plan after the first Rust durable write. Explicit/shared stores and other platforms need their own isolation qualification. The [cutover gate](rust-writer-cutover-gate.md) remains binding.
- **Verification state.** PR #262 passed 33 combined route/UI/content tests before the shared health-fixture repair, then 30 focused tests after that repair and two independent live route/UI tests on its final head. PR #263 passed the isolated cross-UID Docker proof and ten installed service tests; an independent reviewer reran both. PR #264 passed 17 Rust contract tests, Clippy, formatting, and one Python differential fixture; an independent Rust reviewer repeated those gates. Each PR had 14 GitHub checks **queued at merge**, so these local results do not represent a completed CI matrix. No whole-app Rust performance gain or production Rust writer cutover is claimed.

The new boundaries are documented in [backup exact query](rust-backup-exact-query.md), [live exact attestation](rust-backup-live-attestation.md), and the [Pi content reference gate](../rfcs/pi-content-reference-gate.md).

An independent Rust architecture review found the crate dependency direction clean: the host depends on the protocol, harness binaries depend on shared source crates, and the domain reducer and exact-query crate have no harness dependency. It found no merged Rust path writing directly to Agenturm's Store. Bounded multi-session paths now exist for opt-in Codex and Pi directory readers through the shared source crate, with Store-owned member ownership, conservative root/member continuity disposition and a visible source availability overlay. The next correctness gates are complete evidence and content-backed Review parity for one real harness, remaining source-history limits, and full live query/storage compatibility. Remaining Python compatibility logic should leave generic services through registered contributions.

Python remains the sole writer until source semantics, query compatibility, crash recovery and rollback gates pass. The user chose idiomatic Rust for the implementation; performance is measured separately and is not a prerequisite to continuing the architecture work.

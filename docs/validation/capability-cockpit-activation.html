Explicit cockpit capability activation

Recorded 20 November 2026. The installed Prompt signals process proof can be enabled by naming its descriptor. This is an opt-in fixture, not a general third-party SDK or a performance claim.

Activate

python examples/prompt_signals_process/install.py --destination /absolute/private/capability
agenturm cockpit --capability-config /absolute/private/capability/capability.json

--once has no pane and rejects the flag. --new-window forwards the absolute path. Default launches do not read capability manifests or start a child. The named descriptor is validated before receiver startup. The generic pane registry renders the contribution without a UI branch. Shutdown closes the host, child process group and watcher before the feed and receiver.

Capture and data path

The UI thread checks only memory. It requires a fresh Feed snapshot, the same receiver, no error or bootstrap state, global capture enabled, and an exact service, session and agent health row explicitly allowing capture. An independent watcher checks receiver health about every 100 ms while selected. Approval expires after 250 ms. Revocation, disconnect or check failure withdraws approval; the next pane query clears its warm model. A denial stays in place for that selected scope until restart or selection change.

The worker verifies receiver health before and after one bounded, exact-scope Activity read. It checks the receiver identity again on the Activity response. Only host-derived aggregate counts reach the child. SQLite and HTTP never run on the Textual input thread. Unknown and metadata-only scopes are unavailable.

Revocation timing: 250 ms is the maximum age of cached permission, not an atomic revocation guarantee. A backend change can remain visible until the next watcher result or approval expiry and UI query. A policy-fenced receiver aggregate endpoint or push invalidation would be needed for stronger semantics. The counts are observational, not an efficacy score.

Validation

Installed tests cover CLI forwarding and cleanup, exact HTTP bounds against the real handler with one Pi health row and 201 newer sibling events, and warm-model clearing after backend revocation or disconnect while the Feed snapshot has not refreshed. Existing protocol tests cover content-free frames, malformed children and the 60×18 pane.

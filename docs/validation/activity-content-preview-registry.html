Trusted Activity content-preview providers

Recorded 20 November 2026. The cockpit keeps the explicit z preview for one Pi user message. A bounded, trusted registry now selects a provider for an exact Activity row. The built-in Pi provider supplies eligibility, a same-origin /api/plugin-… path and inspector labels. A trusted caller can inject another provider at app construction without editing the central Activity inspector. Ambiguous matches, undeclared routes, malformed IDs and invalid provider output fail closed.

Privacy boundary

The shell checks receiver and exact Activity revision around the HTTP call; the receiver separately proves source and policy before response headers. Only a sanitized 4096-byte response field enters transient inspector state. Selection, receiver, provider or tab changes, revocation recheck and 20-second expiry clear both state and rendered RichLog strips. Copy, export, ReviewHistory and Activity rows remain content-free.

A loaded point-in-time preview may remain visible until its 20-second expiry if a same-inode source is edited later without changing its Activity revision.

Scope

This is an in-process trusted UI contract. It does not discover external UI plugins, expose a Pi requested-command read API, register a production command provider or relax the receiver source gate. A later command provider requires its own reviewed exact-event HTTP route.

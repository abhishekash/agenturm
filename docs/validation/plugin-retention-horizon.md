# Process-plugin evidence retention checkpoint

This checkpoint bounds the opt-in process-plugin inbox after its 50,000-record source cap. It was developed against the relationship-projection checkpoint `0e8f9d0`, rebased onto main including the Rust sample adapter `f42c5cb`, and tested with a reduced cap to exercise rollover. It changes no native-harness retention or Python Store authority.

When a new distinct event would exceed the source cap, the host evicts the oldest admitted half-window in the **same transaction** as the incoming evidence, cursor and dirty sequence. Incoming event identities are protected from eviction. It records the greatest occurrence timestamp among evicted records as a durable source watermark, the number of dropped events, and up to 2,000 affected native session IDs. The receiver exposes `local_agents.plugin_projection.retention_gaps` with source ID, decimal-string watermark and dropped count. Affected sessions are projected as `unknown` with reason `retention_gap`, no terminal outcome, usage total or confirmed relationship. This deliberately invalidates their old derived facts; it does not manufacture a cumulative summary from incomplete evidence. New sessions whose evidence remains inside the window can still be projected.

After the first checkpoint, an unknown event with a nonzero revision or an occurrence time at or below the watermark is refused before cursor advance. This is the explicit late-evidence horizon. The source contract assumes an event ID keeps its occurrence timestamp across revisions; a producer that changes IDs or times to impersonate new events violates that contract. Known retained IDs still accept monotonic corrections. An exact committed-batch replay is acknowledged without a second deletion. If no safe victims remain, or the invalidation budget would be exceeded, the host refuses the whole batch and keeps its cursor. Capture revocation deletes the checkpoint, invalidation rows, evidence and projection under its policy fence.

The test cap of four exercises the mechanism; it is not a scale or performance measurement. The existing full test suite and retained-history performance acceptance are separate gates.

Limits: retention is source-local and metadata-only. It intentionally stops arbitrary-old corrections rather than retaining unbounded tombstones. The visible gap remains until capture is revoked; re-enabling resumes at the last acknowledged cursor, so it does not restore discarded history. A source that needs complete historical reconstruction must use a separate durable archive and retention contract. No Rust performance gain is claimed.

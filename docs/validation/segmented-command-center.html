Segmented command center

Design review for the Agenturm task roster, 2026-11-27. Implementation and verification are in progress; the validation entries below remain pending until the final build is checked.

Intended behavior

The main loop is to find a task, identify its recorded state, and open its evidence. The screen separates application destinations, time and state filters, the task list, and the selected task. Context and commands follow the task instead of competing with its title.

This remains a full-screen Ratatui application with a master/detail layout on wide terminals and a task-first drill-down layout on smaller terminals. Existing session identity, ordering, tree expansion, filtering and inspector navigation remain the behavioral contract.

Clutter audit

SignalPrevious rosterDesign change
BordersOne preview border; navigation, filters and roster run togetherOne contour per functional region, no outer application frame or nested boxes
Task rowsEvery ordinary task occupies two rows; the second commonly repeats only CodexOrdinary tasks use one row; additional context appears only when it distinguishes an agent or task
Repeated boilerplateA full project path heads the group and repeats in the preview; raw completion reasons and model-provider metadata fill the previewShort, disambiguated project headings; bounded project path in preview; full metadata stays in the inspector
StateLarge counters for every state, including zero values and an additional unknown counterWide state controls; compact active-state control; explicit state words remain in task rows
SelectionStrong emphasis across task names, controls and status textMain selection should have the strongest emphasis; idle metadata stays quiet
FooterThree or four dense lines of scope, shortcuts, project provenance and collector internalsTwo lines with primary commands and a short status; full diagnostics in scrollable help
Always-on markersRepeated provider subrows carry no distinction when all tasks use one providerTree markers only for expandable rows and a selection marker only for the selected row

For 100 ordinary tasks without distinguishing secondary context, task content falls from 200 rows to 100 rows: a 50% reduction in row consumption. Contours and filter segmentation add a fixed amount of chrome. This is a layout calculation, not a measured whole-screen cell percentage. Total chrome-to-data ratio depends on terminal size, grouping and secondary context; final rendered frames must be reviewed at the floor as well as the wide size.

A status uses at most a word and one semantic color. Meaning does not depend on color. The design keeps border nesting at depth one.

Responsive and state behavior

60×18Single task pane; active filter remains explicit; names truncate by terminal cell width. Primary shortcuts remain visible.

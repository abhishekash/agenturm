Feature-off Linux Rust storage-service skeleton

Scope: agenturm-storage-service runs only a local v1 protocol probe. It has no SQLite connection, mutation operation, receiver caller or migration. Python Store remains the receiver writer; WorkflowStore and TaskStore are separate Python mutation paths.

Data rootService-owned, 0700, emptyPlaceholder for a future protected canonical store; this binary never opens a database.
Transport directoryService-owned, client primary group, 2710Client group may traverse the known socket pathname, but cannot list or replace entries.

Service and client UIDs must be distinct non-root accounts. Paths and ancestors resolve directly without symlinks; writable ancestors are refused except root-owned sticky directories. Roots cannot nest. Identity and mode are checked at startup and before each accepted connection; drift stops the service.

Socket lifecycle

A persistent no-follow 0600 lock fences a second cooperating instance even if the socket pathname is removed. The fixed socket agenturm-storage-v1.sock is created service-owned, client-group-owned and 0660. Existing socket paths or symlinks are never unlinked on startup.

Bounded readiness polling observes SIGINT/SIGTERM. Before graceful unlink the service checks the original socket inode and directory binding; a replaced pathname is left alone. Crashes leave stale sockets for operator inspection. The lock file remains across restarts.

Peer contract

Each connection supports only the v1 probe. Kernel SO_PEERCRED checks the configured client UID/GID before frame parsing; the receiver ID must match. A same-UID client is denied. A probe reply certifies the transport contract only and makes no storage-writer claim.

CLI inputs: --data-root, --transport-dir, --receiver-id, --client-uid, --client-gid, and optional positive --max-connections.

Verification

One Rust unit test covers direct-root symlink and writable-parent refusal. Ten installed real-binary tests cover modes, same-UID denial, graceful shutdown, second instance after pathname removal, replacement preservation, pre-existing symlinks, directory preflight and live root/lock drift. Focused build, tests, Clippy and formatting passed.

The installed fixture runs under one UID and therefore does not prove an authorized probe across real distinct principals.

Open gates

Protected deployed service/socket ownership, typed mutation and durable replay/policy APIs, routing all Python mutation paths, old-handle quiescence, adversarial legacy-binary exclusion, backup/WAL migration and recovery remain required. Same-service-UID code can race a pathname check and unlink. This is no performance or production cutover certificate.

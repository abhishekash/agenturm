Trusted batch handler dispatch

Agenturm validation · 20 November 2026

This refactors the transport boundary. It does not create a public plugin SDK or change capture policy.

What changed

PluginProcess resolves one host-owned batch validator from approved required_features before starting a child. Ordinary v1 batches stay strict. pi-content-ref/1 selects the existing versioned content envelope and same-batch reference checks. Missing or malformed Pi envelopes close without acknowledgment. An unregistered content-reference feature or conflicting handlers fails before launch. Child-advertised extras cannot select a validator.

An unexpected trusted-handler error, invalid batch shape, or different source ID closes the child without acknowledging a cursor.

Trusted host code can compose an immutable BatchHandlerRegistry. A synthetic second handler worked through a real child without changing PluginProcess. Child processes cannot register Python handlers or access Store through this seam.

Authority and limits

PluginSession and Store still own Pi configuration, filesystem proof, capture policy, source lease, durable admission, and redaction. Each new wire envelope needs a reviewed host handler and admission contract. This work grants no arbitrary extension content access and makes no performance claim.

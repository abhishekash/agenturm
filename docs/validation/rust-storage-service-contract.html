Feature-off Rust storage-service contract

Scope: agenturm-storage-service-contract has no listener, production caller, database handle or mutation operation. Python Store remains the receiver database writer; WorkflowStore and TaskStore are separate Python mutation paths.

Strict v1 frame

One Unix socket connection carries one request and response. A four-byte big-endian length precedes 1–65,536 JSON bytes; the sender half-closes its write side. Each whole frame has one two-second monotonic deadline. Every socket read/write uses only the remaining time, so drip-fed bytes cannot renew it.

Only probe with protocol or receiver_identity is accepted. Unknown operations, versions, fields, duplicate fields, malformed, incomplete, oversized or trailing data fail closed. The reply must echo the exact version, request and receiver IDs.

Peer identity

On Linux, both sides check SO_PEERCRED before parsing peer bytes. The server policy binds its effective UID and PID and requires a distinct non-root client UID and exact GID. The client policy pins its own identity and checks the expected distinct service UID/GID. Other Unix targets report the kernel peer check unavailable.

This proves local process identities only. Socket path protection, database ACLs, source authorization and old-writer exclusion remain separate gates.

Replay relation

A canonical request digest distinguishes exact reuse of a request ID from a conflicting topic or receiver. The comparison is pure and stores no receipt. A future writer must commit a durable receipt atomically with each mutation. protocol_ready signals only that this contract was negotiated; it does not claim a ready storage writer.

Verification

Eleven focused Rust tests cover a kernel-backed socket round trip, client/server peer denial before parsing, receiver/reply mismatch, malformed/oversized/incomplete/trailing frames, drip-fed requests and responses past one deadline, unsupported mutation, duplicate keys, invalid IDs, policy identity and replay comparison. The round trip uses a test-only synthetic policy because both ends share one UID; no installed distinct-principal service is tested. Formatting, focused tests and Clippy were run in the isolated worktree. No performance claim is made.

OpenCode patch-path evidence and private reveal

24 November 2026. FD2 continuation from the interrupted implementation; development branch feature/opencode-edit-detail, based on 57b7580 (PR #393). This is a focused development handoff, not release or installed qualification.

Native evidence and limits

A read-only SQLite snapshot of the local OpenCode database contained 141 part rows of type patch. All 141 joined the current session_message table by both message and session ID. The observed patch keys were type, files (a string list) and hash (40 lowercase hex characters). The earlier inspection found no nonempty session-diff files. No personal paths, prompts, patch bodies or native IDs are included here; regression fixtures are synthetic.

The producer hash is treated as opaque. Its presence does not prove the path list, re-derive a diff, or attest the worktree. Session-level aggregate columns are not exact operation evidence and are not used as a fallback. The current source must also have the supported V2 session/message/part layout. A missing optional part table simply supplies no patch evidence.

Implemented contract

  • FileChange { files, digest } retains only a bounded distinct-file count and SHA-256 of the canonical native patch JSON. It contains no path text, diff, inferred add/delete counts or command content. The digest is a content commitment, not anonymization or an execution attestation.
  • The adapter reads at most four patch summaries per assistant message, with an extra row to detect overflow. Oversized/malformed records are withheld; bounded overflow diagnostics contain no source content. A patch must have 1–256 distinct nonempty paths and a recognized native hash shape.
  • A patch is attached only to its exact message/session and a provable preceding idle boundary. No first-turn boundary or worker identity is guessed. Its event and operation IDs derive from the database epoch and native IDs; time comes from the native part's update timestamp.
  • Native polling uses oc5; upgrading an unchanged oc4 cursor forces a sweep. Old cursors remain readable for prompt proofs. Legacy Python admission continues using oc4 and does not receive the new fact.
  • Schema 24 adds the independent opencode.edit_detail approval. The v23 upgrade preserves prior grants. A prompt, Claude or Codex approval cannot authorize OpenCode edit detail. The binding includes source/adapter pins, configured path and file identity under agenturm.opencode-edit-detail/1.
  • Reveal selects the exact retained event, revision, source, session, turn and operation under the existing writer/grant fence. It opens SQLite read-only, checks one unique native part, timestamp, current turn membership, file count and canonical record digest. A same-count path rewrite with unchanged native hash and timestamp is denied. A later admitted correction requires a fresh selection. Missing, ambiguous, replaced, over-limit or revoked evidence denies.
  • Source reads retain the existing database/WAL ceilings and sidecar preflight. Patch JSON is capped at 64 KiB before transfer/decode; reveal scans at most 8,192 session part rows, failing closed above that ceiling. The source stamp, including WAL metadata, is rechecked before delivery.
  • Revealed paths are at most 512 bytes each, truncated on UTF-8 boundaries, credential/control screened and bounded below the shared 8 KiB output limit, accounting for JSON escaping. reported_files preserves the original count; truncated identifies partial output. The terminal explicitly says diffs and add/delete counts are unavailable.
  • Review/turn pickers include eligible OpenCode and Claude edits while keeping worker and occurrence fences. Shared VerifiedEdit carries an optional provider-shaped detail instead of coercing path-only patches or Claude tool inputs into Codex diffs. Local and broker consumers use that same proof type. Path investigation refuses exact matches from a truncated OpenCode list.

Operator commands

Use an explicitly configured, SHA-256-pinned OpenCode adapter and native SQLite source. Substitute real values; no command below approves other content kinds.

agenturm content grant --db HISTORY --config SOURCES \
  --source-id SOURCE --kind opencode.edit_detail

agenturm content preview --db HISTORY --config SOURCES \
  --source-id SOURCE --kind opencode.edit_detail \
  --session-id SESSION --turn-id TURN --operation-id OPERATION \
  --event-id EVENT --revision REVISION

agenturm content revoke --db HISTORY --source-id SOURCE \
  --kind opencode.edit_detail

Revocation prevents subsequent disclosure; it does not erase native records or previously viewed content. Collection remains content-free for these facts. No install command, default distribution, public release or support platform changes as part of this slice.

Rust harness evidence coverage

This matrix describes the evidence each Rust adapter can emit and the checks that exercise it. The Linux bundle discovers Pi, Codex, Claude Code, Kiro, and OpenCode through separate Rust adapter executables. Source continuity diagnostics report specific gaps the adapter detected.

Inspector acceptance

The Overview pane displays the latest recorded lifecycle state with the source, session and optional reason. A separate row shows the exact turn ID when present. An identified turn ending stays visible when a later lifecycle record describes ongoing activity. The pane uses the currently loaded history page. The rows can wrap and scroll in a narrow terminal.

A 60×18 Linux PTY showed a failed Kiro fixture turn beside the next ongoing turn after collection and reopen. Scrolling exposed both IDs, Tab switched to Metrics, and quitting restored the PTY's terminal settings.

The durable fact retains the repository and PR number. Shell pipelines, command chains, dry runs, assistant claims and output that needs interpretation fall outside that evidence rule. An interrupted turn and a raised PR from that turn can both appear after reopen. Terminal lifecycle state comes from native turn evidence. Core development follow-up: neutral native presence

The current source extends existing Codex header discovery to supported Pi and Claude Code openings. A Pi exact session header, or supported Claude timestamped metadata/user stub with an exact native session identity, emits the existing neutral session_discovered fact when ordinary session facts are absent. A proved existing Pi relationship already supplies that neutral identity and is not duplicated. Unbound preludes, unsupported metadata and missing/invalid native timestamps do not produce a row. Native file mtime is not substituted.

Verified header-only cursor backfill is idempotent and preserves the committed source bytes/offset. Legacy admission omits the new fact. This is presence evidence, not current liveness or Working state. Real lifecycle facts remain authoritative. Forty-one focused adapter checks and strict Clippy passed; actual collection/restart/concurrent roster acceptance remains delegated under CF1 in the core feature test plan.

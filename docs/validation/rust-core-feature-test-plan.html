Core feature development: delegated test plan

Updated 23 November 2026. The user assigned this implementation session to core feature development and a separate agent to test execution. This plan is the handoff contract. It supplements Q1–Q10 in the remaining-work plan.

Ownership and execution

  • Feature developers: implement the four slices below; run only focused compile/parser/state checks that protect the changed behavior; provide source head, exact patch scope, focused result and known limitations.
  • Test execution agent: own joined workspace/Clippy, actual native collection, broad terminal/privacy journeys, schema/upgrade, SDK matrix and artifact/KVM qualification. Record executable hashes and results in this plan or linked validation records. Return defects with exact scope and reproduction.
  • Integration owner: combine reviewed changes, publish the exact source head for testing and fix returned defects. Do not duplicate the test agent's campaigns or call an implemented feature release-qualified prematurely.

The base is merged 18aa7026be1041b93a0b8517874f5b518da44777 (PR #381). Its existing 833-test and development terminal/KVM results are historical baselines, not results for the new feature slices. Every new row starts not run until the test agent records evidence against the integrated head.

Results and defect handoff template

For each execution record: feature/test ID; source commit; executable/archive SHA-256; OS/architecture; native producer/version or fixture; terminal size; expected and actual result; PASS/FAIL/BLOCKED; exact log/artifact path. Do not combine results from different source heads into one qualified candidate.

For each defect return: minimal reproduction, exact owner/source/session scope, last expected state, failed invariant, and affected feature paths. Developers fix that defect and return the new source head. The test owner decides the necessary regression breadth; developers do not restart the entire campaign.

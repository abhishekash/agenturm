Private telemetry selection

Rust 0.3.5 and 0.3.6 could interpret a saved telemetry selector from one fresh history in another history with the same source, span, session and numeric watermark. A synthetic reproduction opened different text. Each history required its own current grant.

The 0.3.7 fix in c1d2a28 checks the issuing history identity and snapshot inside the existing grant fence. A restored branch needs a fresh snapshot and approval. Older selection files without history_identity fail with refresh guidance. Run trace-payload snapshot against the intended history and copy its history_identity and snapshot_id together. The fix uses the history identity already stored by Rust.

Eleven JSONL CLI process tests and two Store telemetry tests passed. The packaged distinct-UID guest rejected a wrong history identity and the older selector format. It verified restore, replay, retention, and terminal redaction on Escape, q, and Ctrl-C. The imported JSONL fixture belonged to the collector with mode 0600, and the reader's direct file open failed with PermissionError. The broker denied reader admission in a separate stdin test. agenturm-037-telemetry-history-cli.log, agenturm-037-telemetry-history-store.log, agenturm-037-exact-vault-kvm.log

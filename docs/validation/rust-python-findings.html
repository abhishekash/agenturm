Python receiver Findings qualification

23 November 2026. Rust can browse Findings from an explicitly attached Python 0.2.8 receiver and display an exact, currently authorized source. The reference is tag commit 2802d79930728bb331db1d4d718d6dea1c9c374d. The client starts no Python receiver and imports no Python history into Rust storage.

Implemented journey

Press 7 for the bounded receiver-wide Findings list, Enter to inspect a selected finding, and s for its supported source. Escape redacts the private view and restores the selected finding. Paging, refresh, loading, failure and compact views retain the selected ID when it still exists. Metadata uses closed kind/severity labels and exact owner/member IDs; server titles, detail fragments and source bodies do not become public row labels or exports.

Private display checks authenticated receiver identity, readiness, applicable current capture policy, exact finding ID, producer/actor/session/trace/turn, and every selected source reference. It reads the current source twice before publication and continues checking during display. Only bounded known log, span-error and evaluation fields are rendered. Arbitrary attributes, resources and unknown raw record shapes are excluded. Malformed or credential-like text is withheld. Private copy/export remains unavailable.

The guard uses the existing bounded terminal writer and redaction acknowledgement. Authorization is sampled by polling, not held by a remote server transaction. The visible lifetime remains bounded. An evaluation source reference identifies the current returned record, not an immutable historical evaluation revision. New policy generations require refreshed metadata before another reveal.

Review

  • review_receipt.rs now emits the tagged Review sections: scope, summary and next inspection step, latest request, agent update, recorded checks, modifying operations, errors, usage, context events, excerpt index, older-evidence cursor and raw observations.
  • Checks are counted passed/failed/unknown/unclassified. Missing sections say so explicitly, for example “No recognized validation records in the loaded evidence. This does not establish that no validation ran.”
  • Token and reported-cost totals are exact; partly reported token sets are marked partial. Captured prompt or provider payload text is never reconstructed by the receipt.
  • Excerpts carry a stable kind, label and event revision n source for task draft --review-file / save-as-task.
  • JSON gains summary and excerpts; the legacy no-format shape is unchanged. Copy and export keep the same loaded-page scope and disclose partial history.
  • cockpit_workflows.rs adds a regression proving decision notes stay bound to the exact evidence version after a later admitted event advances the session receipt.

Workflow

  • workflow_alerts.rs: incident detail begins with the observed owner (source · main session/worker · turn), a recorded approval-state line, and delivery attempt plus policy revision.
  • Refresh preserves the exact incident by (id, scope, evidence). If it is gone, the nearest recorded incident is selected with a stale notice; a changed history incarnation says so instead of implying the old selection is current.
  • workflow_settings.rs: first Escape arms “Esc again to discard · Ctrl+S save”; typing cancels the arm; only a second Escape leaves. Desktop/snooze commands remain immediate receipts. Desktop-only refresh keeps unsaved threshold drafts.
  • workflow_resume.rs: unavailable_reason() distinguishes worker execution, unsafe/absent native identifier and unsupported provider. Commands remain fixed to codex resume / claude --resume with a safe, provider-matched main-session identifier.
  • workflow_route.rs: local no-pane failures direct the operator to an explicit --route-file for receiver-host executions; remote failures never guess or select a pane. Invalid identifiers are separate from route failures.

Saved tasks, decisions and handoff

  • task_cli.rs: task list --search <text> filters the loaded page by title, notes, workspace directory and exact linked source/session/worker/turn identity. It reports "page_local": true and treats empty text as no filter.
  • handoff_export.rs: export collision preserves the first Markdown/HTML pair and fails with AlreadyExists without leaving staging files. Current/superseded decision history keeps History and Supersedes n labels.
  • tests/task_cli.rs covers search by title, note and exact linked identity, empty results and the empty-search no-filter case.
  • Existing revision/CAS, decision supersession, brief, Git snapshot/diff, private handoff export and restore tests still pass.

Preferences and private display

  • review_visibility.rs: the preference save now syncs the parent directory after the atomic rename. Tests reject non-canonical, oversized and symlinked files; saving replaces a symlink rather than writing through it. The preference remains off by default.

What remains

These are real gaps, not accepted differences. Each needs shell or app work this lane must not land in shared files.

GapWhy it remains
Review screen actionsReview still exposes panes, edit list, older evidence, y acknowledge, n decisions and t traces, but not Copy, Export, Save task, Excerpt, Draft, Git or Map workspace. The receipt/excerpt models now exist; dispatch and forms do not.
Turn-scoped ReviewCtrl+R opens session Review; HistorySelection::Turn has no Review section. Python can open exactly scoped turn checks/edits/errors.
Save task from Reviewtask draft --review-file and approve-draft accept a receipt, but the cockpit has no action that writes a bounded review draft or opens the task editor.
Incident review acknowledgementSeen persists per pending request. Completion/failure incidents have no persisted reviewed acknowledgement independent of delivery retry.
Task search in the cockpitThe CLI supports --search; the shared task list has no search field, clear action, page-local disclosure or command carrying a query.
Decisions, Brief and version selectorThe app CLI supports brief, decide, decisions and supersession; the cockpit only edits task title/note and has no version chooser or dirty-editor confirmation.
Handoff previewThe cockpit exports a saved handoff but has no preview/copy of task handoff formats or a destination form that stays open on collision. The export layer already returns AlreadyExists.
Provider edit/MCP detailReview edit reveal remains the whole-session Codex browser and otherwise says “Edit preview is unavailable from this reader”. Remaining provider proofs/detail belong to FD2 with valid grants.
Cross-host discoveryRouting is explicit only. There is no route browser or hidden discovery; the remote cockpit must be reopened with the configured route file. This is intentional.
Receiver acceptanceThe Python receiver Review path and CF7/paired terminal acceptance are separate gates. This lane claims unit/integration evidence only.

Dispatch additions

  1. Add Review Copy/Export/Save-task/Excerpt/Draft/Git/Map commands to WorkCommand (or reuse ExportView with a review document) and route them from Workspace::key. The app owns receipt rendering and the task draft/decision CLI paths.
  2. Add a turn-scoped Review selection (or make SessionView::Review carry an optional exact turn/worker) and open it from the inspector and turn picker. Preserve the exact session/turn on return.
  3. Add a task-search field and Decisions/Brief sub-screen in workbench.rs, with command variants carrying page cursor, query and expected revision. Keep query and page-local limits visible.
  4. Extend Workflow help/footer for the new settings discard behavior and observed owner / approval state / delivery attempt detail.
  5. Add palette entries for Review, Workflow, Incidents, Saved tasks, Task search and “To review”. Keep F2 themes; Ctrl+P must restore the originating control and drafts.
  6. Surface receipt summary, excerpts and partial-page labels in Review and the export form so Copy/Export never imply complete history or verified correctness.

Pluggable-seam implications

  • The review receipt is a provider-neutral projection of retained observations. It classifies checks, edits, errors and usage without switching on a provider ID.
  • Provider edit and MCP payload detail stay behind RevealReviewEdit / RevealOperation, FD2 proofs and valid grants. Missing detail is labelled unavailable; no provider-specific UI branch was added.
  • Workflow routing is explicit configuration only: local route, remote route file, unique-pane proof and “Seen only acknowledges locally” wording are preserved. No hidden discovery, pane guessing or provider-hardcoded attach path was introduced.
  • Cross-host attach guidance lives in workflow_route and is transport-neutral. Configured route words are the operator’s own authenticated transport.
  • Task search and handoff export operate on operator-authored metadata and exact recorded identities, not captured body text.

Residual risks

  • Final acceptance still requires the installed Rust candidate paired with the tagged Python build at 120×32, 80×24 and 60×18, including real terminal keys and receiver cases. This lane’s evidence is unit/integration and component rendering only.
  • The Review screen remains shared-shell-owned. The receipt and incident models are ready, but visible parity of Copy/Export/Save task/Excerpt cannot be claimed until UI-02 lands dispatch and forms.
  • Incident acknowledgement persistence is a ledger feature, not a UI flag. Do not add a local-only “reviewed” badge that disappears on restart.
  • The untested paired matrix remains large: theme/compact rendering, connected/denied/stale receiver states and actual terminal-restoration behavior are UI-07/UI-Q evidence.

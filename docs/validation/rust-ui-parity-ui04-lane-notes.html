Resize and late data

  • Navigator ⇄ Chooser follows the 120-column breakpoint.
  • A focused reader stays a reader across the breakpoint (tagged behavior).
  • An open chooser closes when the layout crosses to wide.
  • The reader's visible source line (and offset within it) is retained when wrapping changes, not merely the wrapped row index.
  • A page response with a superseded load token is discarded with Discarded a late prompt response for a superseded view.
  • A delivery with a stale reader epoch reports Late(Superseded); a delivery for a different request reports Late(OutOfScope). Neither replaces the current request or screen.
  • Rows outside the exact source/session/worker scope are filtered with Ignored N request(s) outside the selected source, session or worker scope.

3. Wide and compact rendering

  • Wide: a Requests · N loaded index (ordinal + label + selection marker) beside a Prompt i of N reader pane. Before a grant the pane is metadata-only; after a grant the same pane renders the granted body with the Request i of N · <age> caption.
  • Compact: one chooser line (Request i of N · label ▾/▴) plus the reader body. The open chooser is a bounded popup (one row per request, maximum ten visible, ellipsised by terminal cells) that never displaces the body.
  • The status line is shared: loading, loaded count/older availability, N retained · older history in Activity, empty exact scope, capture disabled, missing identity, denial, revocation, expiry, missing capture, stale source and transport errors each have distinct copy.
  • Availability states render at 120×32, 80×24 and 60×18 without panics; below the shared terminal floor the module shows Terminal too small · resize · Esc back.

Every read request carries exact source, session, optional worker, request turn, event id, revision, snapshot id and history identity. Grant and query enforcement stay in agenturm-content/agenturm-app; the UI stores identifiers only.

Copy and export

The reference copies the selected request's readable or original text and previews an export (c / x). Rust's private prompt display remains no-copy: Ctrl+C stays a terminal interrupt in private/reader focus, and c/x are disabled while a granted prompt is displayed. This is the existing tighter disclosure policy and is recorded as an intentional difference awaiting acceptance (inventory P-09), not as parity. If accepted otherwise, the copy must be a new grant-aware seam shared with evidence — never a direct text dump.

5. Retained evidence paging

Prompt history now has an explicit page model, separate from the roster's History time scope:

  • PromptCursor { observed_at_unix_ns, event_id } is an exact keyset, not a row offset.
  • PromptPage reports the page rows, the retained window size, the adapter cap, whether the cap was reached, and the cursor for the next older page.
  • window() sorts/deduplicates deterministically and applies the cursor before slicing, so identity cannot shift on equal timestamps.
  • The adapter cap (256) is disclosed as 256 retained · older history in Activity; an empty exact scope is No user prompts were captured for this session and is never presented as a complete transcript.
  • Filters, selection, query and snapshot are not part of prompt history pages: prompts are scoped by exact source/session/worker and a pinned history identity. The existing Activity/MCP/Traces/Review page stack and its [/]/l identity rules are untouched (owned by the shell/UI-05).

The app page function is prompt_history::load_page, which calls the existing grant-checked content_preview::list_user_prompts. Until the adapter exposes a cursor beyond its 256-row window, "earlier" is page-local within the retained window and is labelled that way. This is the honest current limit; the inventory P-10 requirement (bounded adapter/kernel prompt-page cursor) remains.

8. Exact hooks for UI-03 / shell integration

8.1 Model ownership

Add to Workspace (owned by UI-03 in workspace.rs):

prompt_nav: Option<prompt::PromptNavigator>,
prompt_anchor: Option<WorkAnchor>,   // exact source/session/worker/turn
prompt_read_epoch: Option<u64>,      // echo from PromptInput::Read

Construct with PromptNavigator::new(PromptScope { source, session, worker, turn, capture, main_session }), then one begin_load() + accept_page(token, entries, meta) when the prompt page arrives. Convert the existing PromptEntry rows with PromptRequest::from(&entry); attach labels only from adapter-normalized facts. PromptCapture must come from the source capability/policy, never inferred from an empty list.

8.2 New focus variants (keymap.rs, UI-03)

  • Focus::PromptNavigator
  • Focus::PromptChooser
  • Focus::PromptReader

PromptReader must have the same precedence as PrivatePrompt: before help and palette, Ctrl+C remains interrupt, F1 is not routed into the granted body, Escape clears the body and returns to the previous prompt focus. PromptNavigator/PromptChooser are public-list focuses and precede history page keys.

8.3 Dispatch (workspace.rs, UI-03)

While the Prompts section is active, route this key set to PromptNavigator::key before global history actions ([, ], l, z) and before global navigation:

8.6 App-side typed result (UI-03 + app owner)

WorkResult::Prompts(Vec<PromptEntry>) currently cannot express capture policy, denial or retained-cap facts. Add a typed result (name is the app owner's choice):

PromptHistory {
    entries: Vec<PromptEntry>,        // newest first
    retained: usize,
    retained_cap: usize,
    earlier: bool,
    limited: bool,
    availability: PromptAvailability, // CaptureDisabled | MissingIdentity |
                                      // EmptyScope | Denied(reason) | Unavailable(reason)
}

and a page command carrying anchor plus an optional prompt_history::PromptCursor. prompt_history::load_page already returns these facts; map PromptHistoryError 1:1 to availability. Keep provider logic in the adapter.

8.7 Typed presentation seam (adapter → app → UI)

The current PromptDelivery sends raw text bytes. To remove the compatibility heuristic, extend the prompt delivery/result with a typed presentation:

PromptPresentation {
    original: String,
    readable: Option<String>,   // adapter-normalized body
    hidden_context: usize,      // count of typed leading context blocks
    truncated: bool,            // reader/export limit reached
}

Adapters normalize their own envelopes and send the facts; the UI calls PromptNavigator::accept_reader_presentation. Until then accept_reader uses legacy_envelopes, and an unknown normalization is labelled unavailable. This keeps provider parsing out of workspace/prompt.rs.

9. Remaining gaps

  1. No shared dispatch yet. The navigator is not reachable from the built cockpit until the UI-02/UI-03 integration pass adds the fields, focus variants, dispatch arms and render hook above. This is the lane boundary, not a hidden claim of parity.
  2. App result lacks typed status/page facts. prompt_history is ready, but WorkResult::Prompts does not carry it. Paging from Tab/Earlier is therefore not user-reachable yet.
  3. Prompt paging is window-local. The adapter/kernel still returns at most 256 references with no cursor; "Earlier prompts" cannot go past that window. The UI labels the cap honestly rather than claiming a complete transcript.
  4. Context normalization remains adapter work. The compatibility heuristic is still used for legacy deliveries; unnormalized captures are labelled.
  5. Copy/export remains the intentional tighter no-copy policy (P-09); it needs explicit acceptance or a grant-aware shared seam.
  6. Mouse equivalence (inventory P-24) is not implemented; the lane stays keyboard-first and records this as a keyboard-only acceptance candidate.
  7. Integrated PTY journey (inspector → Prompts → older request → original → Review/Activity → return) was not run because the shared render/dispatch hook is not present in this branch. Component state/render tests and the real content/investigation fixtures were run.
  8. Investigation idle policy invalidation (P-18) is partial: a changed source is refused on the next attempted read; results are not proactively cleared while idle.
  9. Activity/MCP/Traces/Review page identity was not changed; it relies on the existing page stack and remains UI-05/shell ownership.

10. Pluggable-seam implications

  • Kernel ports / adapters: the navigator consumes typed request metadata and a typed presentation; it does not parse harness files or provider envelopes. The only compatibility parser is explicitly named and isolated.
  • Grants: listing, cursor proof and reveal remain in agenturm-content. The UI never issues a text read; it carries event/revision/snapshot/history identity back to the app. Revocation/expiry clear the body before ACK.
  • No provider branches: request labels, capture policy and worker/main relationships arrive as facts. Missing facts are labelled unavailable (Readable form unavailable, Metadata only, Prompt history is unavailable).
  • Extension panes: nothing in this lane bypasses ExtensionPlugin/capability/ pane seams; the navigator is a generic session-evidence view over host-supplied facts and is only rendered when the shell owns the Prompts section.
  • Scope honesty: out-of-scope rows are dropped with a visible count, exact worker scope never inherits untagged or sibling requests, and main-session navigation is offered only from a caller-verified anchor.

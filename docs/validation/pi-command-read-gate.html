Pi requested-command read gate

Recorded 20 November 2026. This internal, feature-off receiver read handles one opt-in Pi bash requested command. It does not assert execution, success, or full Review parity. No HTTP route, UI pane, copy action, export, or public SDK calls it. Metadata-only remains the default Pi capture mode.

Boundary: The gate returns at most 4,096 bytes of redacted requested text with a point-in-time proof. A future delivery caller must recheck immediately before response headers. This module publishes nothing.

Proof

read_exact_pi_requested_command(store, activity_id) accepts only a canonical plugin Activity ID and the active receiver’s PluginSupervisor. A short SQLite snapshot requires current capture policy, configured Pi command grant and root fingerprint, matching receiver and projection revision, exactly one retained command row, an uncorrected started shell fact, exact member ownership, and no source-gap or retention invalidation. It recomputes the complete projected Activity row, including opaque operation and turn identity, from that fact.

The receiver discovers the hash-addressed member with bounded nofollow directory traversal, opens it without following symlinks, checks the acknowledged header and full prefix, independently derives the preceding user turn, and verifies the assistant row, exact bash block, operation ID, timestamp, command and redaction. It compares two file proofs separated by a second database snapshot, takes a third snapshot, and checks Store file identity and supervisor attachment before returning.

Validation and limits

Focused installed tests cover exact redacted read, normal lease restart, malformed selection, supervisor detachment, policy revocation, pending projection, source gap, retention tombstone, correction, wrong block/turn/operation, forged Activity, stored text corruption, member remap, missing/symlinked/rewritten source, and races that revoke or swap the source during proof. python -m unittest tests.test_plugin_pi_command_read -q passed 10 distinct read-gate tests.

The search is bounded by 48 files, 4,096 entries and an 8 MiB acknowledged Pi prefix; larger or ambiguous sources fail closed. A later same-inode edit after the final proof can invalidate a returned point-in-time result, so delivery must take a fresh proof.

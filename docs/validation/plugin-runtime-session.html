Opt-in plugin runtime session

19 November 2026 · An explicit session composes the supervised process host with Store admission for a supplied manifest and source ID. One worker stays alive across polls. Activation resumes the durable cursor; a batch is acknowledged only after the Store has accepted it. The caller owns scheduling and creates a fresh session after a crash.

The initial cursor is empty. An adapter with no new records may return an empty batch at the unchanged cursor, including on its first poll. The host checks source ownership and lease, acknowledges the idle result, and leaves evidence, cursor and dirty sequence untouched. Batches with records still require a forward cursor or exact durable replay. Revoking a lease closes the worker without acknowledgment.

No default production collector instantiates this session. Capture-policy epochs, live projection, scheduling, restart/backoff, external SDK conformance and installed Rust/Python plugin packaging remain open.

Twenty process, runtime and admission tests passed locally. A separate executable fixture covers three idle polls on one worker, idle after progress, exact replay and revoked lease without acknowledgment. Earlier crash, timeout, malformed frame, rollback and restart tests also passed. See the execution plan and Markdown report.

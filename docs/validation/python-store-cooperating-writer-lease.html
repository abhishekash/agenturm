Python Store cooperating writer lease

20 November 2026 · Opt-in Linux fence; production Rust authority remains off.

Lock and admission

Store(path, writer_lease=True) acquires a sibling lock derived from the resolved database target before Store authority preflight or database initialization. Opt-in requires an existing private database parent. The lock is an owner-only, singly linked regular file opened without symlink following and with close-on-exec, then held by a nonblocking exclusive Linux flock. Symlink aliases to one database target contend on the same lock.

Same-process Store instances share one descriptor through a PID-and-path registry with a reference count. Forked children drop inherited descriptor copies; exec does not inherit the descriptor. Each writer connection checks lock and database identity before open, after open, and before commit. A database absent at lease acquisition is bound only after Store proves it created the file exclusively.

Close and constructor failure

Opt-in close uses the existing handoff proof to fence new work and wait for that Store's tracked writer connections, pooled readers, migration worker, derived worker, and incoming-status read. It releases only when quiescence succeeds. A timeout or cleanup failure keeps a strong registry reference to the lock, so garbage collection cannot unlock it; while the Store object is available, a later close may retry. If constructor-time quiescence fails, the partial Store is not returned and the retained lock stays registered until process exit. Failures before handoff tracking exists can release safely because no Store connection or worker has started.

The fixture covers process contention, symlink aliases, same-process references, fork/exec, SIGKILL, lock and database replacement, transaction rollback on a late identity change, missing-database races, constructor failures before and after worker start, active reader/writer close timeouts, and non-Linux feature-off behavior. Focused local command: python -m unittest tests.test_store_writer_lease -v. CI runs this fixture in the Linux Rust protocol and plugin-adapter job.

Limits and remaining gates

This is a cooperating fence only: legacy binaries and direct SQLite writers can ignore it. An in-flight operation and a swap-and-swap-back race are not fenced. Workflow, saved-task, outbound, and direct mutation paths remain outside this lease. Windows/macOS are unsupported. A protected Rust service-owned canonical path, full mutation routing, old-writer exclusion, synchronized migration, and forward recovery remain necessary. No performance gain is asserted.

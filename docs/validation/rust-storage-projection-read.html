Rust backup-only session projection read

The diagnostic agenturm-storage-shadow reader can now read one source’s published session projection from an explicitly supplied isolated SQLite backup. It does not read the live Store, publish a query, write a database, or change Python’s authority. The default revision-certificate request and response remain byte-compatible. Callers opt in with "include_projection": true.

Snapshot and validation contract

The reader opens the backup with SQLite READ_ONLY, URI immutable=1, and query_only, rejects sidecars, and reads the receiver/source revision and projection rows in one short transaction. It returns sessions only when capture is enabled and projection sequence and policy match the source. Unknown, pending, and disabled sources have no sessions field. The certificate is historical; Python’s live rust_shadow_snapshot.current() fence remains necessary before publishing any result.

The source ID is exact. SQLite checks at most 2,001 rows and stored text lengths before Rust loads strings. More than 2,000 sessions, over 4 MiB of aggregate text, usage text over 4 KiB, or oversized identity or relationship fields fail closed. Each row must match the ready policy and dirty sequence. Rust validates IDs, states, reasons, relationships and timestamps, then recomputes Python’s plugin:<sha256> key from receiver, source and native session. It returns the same normalized fields as Python’s read-only shadow snapshot, without re-reducing evidence.

Usage counters are parsed from raw decimal tokens, without floating-point conversion. The source’s 50,000-record admission ceiling and per-observation i64::MAX bound set a valid aggregate ceiling of 50,000 × i64::MAX, which fits u128. Negatives, fractions, exponents, duplicate or unknown keys fail closed. Values through 2^53−1 remain JSON numbers; larger values become decimal strings, matching Python’s API-safe conversion. Only serde_json raw-value support is added, not arbitrary-precision Number parsing across the workspace.

Verification and limits

Installed differential tests compare full Rust rows with Python’s rust_shadow_snapshot.capture(...).expected["sessions"] for two sessions, a parent relationship, mixed lifecycle states, the JSON-safe boundary and a sum beyond u64. A source gap yields matching unknown/source_gap rows. Pending and disabled sources omit sessions. An old ready backup remains historical after Python’s live fence rejects it. Corrupt revisions, keys, identities, relationships, times and usage fail closed; default response bytes and backup files remain unchanged.

Focused gate: Rust package tests, Clippy with warnings denied, and six installed storage-shadow differential tests. The supplied file must be a completed, quiescent backup. immutable=1 and sidecar checks do not prove that another process is not changing it. Live query parity, a Rust writer, exactly-one-writer cutover, downgrade handling and crash/rollback drills remain open. No performance gain is claimed.

Final candidate registration and clone preparation

The final HTTP harness requires an explicit full candidate commit SHA for controlled runs and records execution order. Both B→C and C→B can run from the same committed harness without changing source constants between measurements. Baseline remains the exact registered 5e0c397 source. Smoke runs remain nonpublishable.

Native-soak and modal/race runs now apply the same registered-clone raw schema preparation already used by the idle and HTTP harnesses. Only the disposable clone loses inherited derived tables, indexes and triggers. Canonical raw rows, DDL, source file and logical hashes stay unchanged; each full source tree builds its ordinary production schema. Named indexes must match a fresh schema initialized by that same source before the workload starts. Initialization, raw preparation and schema validation are outside measurement intervals. Cleanup remains limited to registered stopped clones.

The smoke HTTP schedule now keeps the full cadence, with fewer samples: two read pairs one second apart and thirty two-record batches every 100 ms. A former 50 ms pair interval was shorter than two allowed catch-up waits. The failed development gate is retained; no genuine 503 or deadline failure is retried or removed, and full-run timings/counts are unchanged.

The focused harness contract suite passed 23 tests in 18.344 seconds. Independent read-only peer review found no remaining blocker after the seeded native-soak startup deadline was changed to the existing 600-second migration allowance. That allowance is a refusal deadline, not a cold-readiness target. Desktop/light and mobile/dark report renders had no page overflow or external asset requests.

A retained development HTTP smoke at /tmp/agenturm-http-catchup-smoke-v2/results.json shows why invalidity must be explicit: one arm attempted 25 writes before a missed slot, the other 30; both retained a genuine loaded 503. The report rejects the unmatched writer inputs. The contract test now verifies exact partial-attempt/error accounting and identical attempted payload prefixes; passing this test does not turn an invalid smoke into an availability or latency pass. Earlier failed harness gates are retained in /tmp/agenturm-registration-gate.log and gate2.log.

The first short native-soak preflight preserved its initialized-index match and three verified completed turns, but failed cockpit shutdown and source-freeze checks. The compact cockpit had not published a ready frame before quit was sent, and the harness was still being edited. The harness now waits for three published main-screen frames with the expected size, visible rows and table focus before sending input. A committed-harness rerun is required; no controlled resource window or one-hour acceptance is represented here.

Active indexing is an observed availability state

The committed 12-second development soak (/tmp/agenturm-soak-raw-preflight2/results.json) completed and verified all three generated outcomes, matched production indexes, preserved frozen sources, and confirmed both cockpits and receivers exited with status zero. Its original gate still failed: two active-writer samples had indexing_ready: false, with zero source/schema/storage-error counters. That original result remains failed and is not retrospectively relabelled; it did not retain enough index detail to qualify those two states.

For subsequent preregistered runs, each active sample records the complete indexing object, the time health was observed, workload phase, initial inventory completeness, four successful subsequent data GETs, and a read-only proof of the durable v15 marker, expected receiver in both database and health, and unchanged database file identity. Only the exact error-free Indexing incoming source changes state with all those proofs is classified as incoming unavailability. It stays visible in sample counts and raw observations; it is not a healthy response or an HTTP availability pass. Missing proof, initial migration, absent marker, namespace changes, errors and unknown states remain failures. Every completed outcome still needs exact reconstruction and review persistence, final fresh health must recover ready in the same receiver, and both shutdowns must drain all queues.

The extra metadata query belongs only to the descriptive active soak. The untouched idle window and strict external HTTP 503/deadline gates are unchanged. This corrects a gate that equated ordinary asynchronous work with corruption; it does not promise zero incoming unavailability. Eleven focused proof, soak, idle and validation contracts passed in 0.398 seconds; the full touched harness gate then passed 25 tests in 17.263 seconds. Independent peer review found no blocker in the classification or its proof requirements. A committed rerun remains required.

The committed rerun (25b611a harness, 23f8c035 application) at /tmp/agenturm-soak-raw-preflight3/results.json passed the short functional contract: three completed/verified outcomes, six ready index samples, production-index equality, preserved source manifests, two successful receiver exits and two successful cockpit exits. Final receiver/marker recovery and all queue drains were proved. No incoming sample occurred in this small rerun; the explicit incoming/failure branches are covered by the proof contracts and remain visible for the one-hour run. This was a 12-second configured synthetic preflight, not a one-hour soak or a controlled CPU/RSS/HTTP result.

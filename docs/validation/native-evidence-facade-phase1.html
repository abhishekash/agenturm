Native evidence facade checkpoint

JSONL sessions and registered native readers now receive a narrow NativeEvidenceFacade. It exposes source-scoped usage, internal-source policy lookup/redaction, connection health and span/log ingestion. The existing Store still applies capture policy and owns every Agenturm SQLite write. Collector hierarchy projections retain their current Store path.

What the boundary means

The facade reduces accidental coupling to Store internals. It is not a sandbox for trusted in-process Python code. Separately installed plugins need the planned supervised process protocol. This change does not add atomic span/log/cursor admission; the current retry semantics remain.

The port contract now states the OpenCode skip_unchanged_native option and the log receiver precondition. A test checks that both reader paths receive the facade and do not get raw SQL or hierarchy methods through its ordinary API.

Validation

79 focused tests passed across native ports, reader registry, discovery, storage retries, native sessions and OpenCode. git diff --check passed.

Rust plugin fixture checkpoint

19 November 2026 · A separately compiled Rust executable exercises protocol 1 through the opt-in Python process host and Store admission path. It is a deterministic fixture, not a production harness or public SDK. It sends one synthetic lifecycle record with a timestamp above 2^53, waits for acknowledgment, then returns empty idle batches at its unchanged cursor. Wrong source IDs, unexpected cursors, missing budgets and polling before acknowledgment are rejected.

The Python host checks the manifest and artifact hash, copies the binary to a private execution directory, owns the source lease and Store transaction, and acknowledges only after commit. A second executable instance resumes the cursor without duplicate evidence. The Rust binary never opens Agenturm’s database or gains storage authority. The revised fixture sends a native session ID; the Python projection then exposes one Completed session after its background refresh.

Read-lease quiescence checkpoint

20 November 2026 · Foundational shutdown primitive; Rust writer remains off.

Guarantee

ReadConnections.wait_closed(timeout) returns true only after close has stopped new checkouts, every checked-out read context has finished cursor cleanup and connection disposition, and no cleanup has failed. It accepts a timeout from 0 to 60 seconds. Expiration returns false and leaves readers running. Waiting may start before close.

Checkout registration, close, and the drain check share a lock, preventing an admitted reader from being missed.

Evidence

The concurrency test holds two readers across close. They finish their admitted reads, new admission fails, and the wait remains false until both exit. It verifies their connections and cursors are closed. Injected idle-close, leased-close, and cursor-cleanup failures leave the drain result false. The focused read-pool and idle-history suites passed: 19 tests.

Remaining gates

This covers only this pool's checked-out reads. Store background workers, direct writer connections, task and workflow databases, and old processes with already-open writable handles still require separate quiescence and exclusion proofs before a Rust writer cutover.

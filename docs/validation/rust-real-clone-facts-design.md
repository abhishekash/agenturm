# Detached Store clone: generic fact admission design

20 November 2026. This is a feature-off continuation on the fixed private real-Store clone path. Python `Store` remains the production writer; no receiver, canonical path, or production client is routed to Rust.

## Proposed slice

Keep the existing `AdmitLifecycle` wire operation and its guarantees unchanged. Add a separate typed `AdmitFacts` v2 operation for only `message`, `tool`, `check`, and `usage`. Map each fact through the existing guarded `BEGIN IMMEDIATE` transaction, cursor/lease fence, durable request replay receipt in the same `storage_admission_request_v2` namespace as lifecycle admission, dirty-sequence update, and empty-content receipt/status writes. The canonical request digest binds the operation type, so a reused request ID across lifecycle/fact operations must conflict. The service still accepts only activation plus these two admission operations in this explicitly marked clone mode.

The service must validate canonical payload JSON itself. Match Python `plugin_admission._metadata` and `plugin_activity.validate_metadata`: message roles are `user|assistant`; tool categories are `shell|file|mcp|other` and results are `started|succeeded|failed|denied`; check categories are `test|lint|build|review|other` and results are `passed|failed|skipped|unknown`; usage is a nonempty subset of `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, and `total_tokens`, each an integer in the signed 64-bit nonnegative range. Messages, tools, and checks require a native session ID. Usage may omit identity; when supplied, it follows the plugin wire identity-field rules. An operation ID is allowed only for a tool. Lifecycle remains on its existing path. Discovery, diagnostics, relationships, revisions/corrections, content references, retention, and capture-policy changes stay rejected.

## Boundaries and failure behavior

The v2 frame, 48-row prepared batch, 800-byte cursor, identifier, payload, and request limits remain enforced before SQL. Only typed source IDs are accepted; no database path is added to requests. Lease, receiver, source identity, cursor, and fixed-clone marker/inode checks remain mandatory. The service must revalidate its startup root/inode proof before it invokes the mutable admission handler, so replacement cannot mutate the replacement file before a post-write guard fails. Inside `BEGIN IMMEDIATE`, the real-clone path rejects persistent or TEMP SQLite triggers on every admission write target before mutation; this prevents a trigger from changing sibling sources, receiver metadata, or another operation's receipt table. Before commit, it still reads back the receiver binding, competing v2 receipt namespaces, source cursor/policy state, complete bounded evidence state (including pre-existing rows), dirty state, unchanged projection/index rows, empty-content receipt/status rows, request receipt, and clone markers. Any validation, SQLite, trigger, or marker failure aborts the entire transaction. Exact request replay returns the durable receipt; conflicting reuse is rejected. Source leases have epoch and policy fences but no wall-clock expiry in the current v2 contract; tests therefore cover revoke/stale-epoch fencing and process-exit release of the OS writer lock, without claiming time-based expiry. Existing scratch JSON behavior and its lifecycle-only limit stay intact.

## Evidence required

Use independent Python Store backups and compare cursor, evidence rows, dirty state, and source state for a mixed message/tool/check/usage batch. Test multi-row rollback, ignored insert/update triggers, persistent and TEMP trigger rejection before mutation (including competing receipt, sibling-source, and receiver-mutation triggers), post-write receiver and namespace readback, lost acknowledgement and restart replay, revoked/stale lease rejection, receiver/source mismatch, marker deletion during writes, replacement of the fixed database inode while the service is running (proving no mutation occurs), exact cursor and protocol bounds, and that canonical input files remain unchanged. Any Python semantics the Rust slice cannot match must be explicitly gated rather than silently narrowed or approximated.

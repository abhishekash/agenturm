Rust exact-session query parity

Recorded 20 November 2026. agenturm-domain-query is a pure, read-only query over the version 3 domain reducer fixture. It is an offline parity gate. Python Store still owns the coherent SQLite snapshot, capture policy and every database write.

Contract

A version 1 request carries a reducer version 3 snapshot, an exact source ID and an exact native session ID. A source mismatch fails closed. The Rust query validates the snapshot through the existing reducer and returns one session or null. Its reply includes receiver, source, plugin, policy epoch and dirty sequence. Revision values are decimal strings.

Coverage stays partial. A missing session is not proof that the source is complete. A live caller must obtain rust_shadow_snapshot.capture and recheck rust_shadow_snapshot.current before using the result. The CLI cannot certify freshness by itself.

The input cap is 16 MiB plus 1,024 bytes for the query envelope. Duplicate or unknown query fields, unsupported versions, malformed identities and oversized inputs fail closed. The crate has no harness dependency, database handle, source reader or network access.

Verification

  • The version 1 corpus covers exact, absent, source-gap and invalid queries.
  • Installed CLI tests compare valid answers with disposable Python Store projections.
  • A live shadow test checks source revision freshness after a new commit and capture revocation.
  • Rust formatting, Clippy and workspace tests remain CI gates.

Next gate

Live Rust query/storage authority still requires the complete compatibility corpus, bounded pagination, source and policy handling, legacy writer exclusion and a migration drill described in the execution plan. No performance gain is claimed here.

# Success-only operation projection

The derivation path avoids full sanitized operation facts when a canonical immutable observation proves they cannot produce a finding. Error retry context still stores the same latest twenty distinct successful operation keys. No source event, credential check, raw SDK/log check, storage schema, queue policy, read guard or capture decision changes.

## Narrow eligibility and fallback

Only exact built-in dictionaries with an operation_v1 role and built-in string detail qualify. Explicit mutable evidence, compact references, mutable/non-string details and unusual result values use the original path. Error-reference processing preflights every row before any normalization. Every source-bearing event must have a passed, nonconflicting terminal result, no raw failure and no recorded exit code one. Findings also falls back for exit one in every domain, incomplete/raw failures or conflicting results.

The retained scan uses the original stable reverse timestamp ordering, without an identity tie breaker or occurrence deduplication. It fetches full facts from each original event/context before trace and receiver wrapper overrides. Full facts, exact key and positive timestamp must qualify; the original second compacting operation remains. Missing keys are skipped until twenty distinct keys or all candidates are exhausted. Output clipping and redaction do not add new success-exclusion rules. Genuine retained full-fact/context exceptions propagate; only pure gate uncertainty falls back.

## Exact evidence

Frozen expected data was generated from the actual 8abdbf8 sources, not from the optimized implementation. Seventeen fixture families across absent, empty and prepopulated preparation contexts retain all serialized Findings and error-reference fields (51 comparisons), plus three original exception classes/messages. Coverage includes more than twenty successes, duplicate IDs and keys, equal timestamps, missing owners/keys/stamps, foreign receiver/turns, secret input/output, clipped output, exit one in every domain, malformed/nonfinite data, compact contradictions and aliased mutable detail. Generated raw credential material, unmapped SDK errors and raw error logs retain their original findings.

A real synchronous Store ingestion of one hundred successful tool spans preserves all one hundred Activity observations and twenty stored compact references while invoking full operation facts twenty times. This is a deterministic call-budget result, not a latency, CPU, RSS, cold-start or loaded-HTTP target result.

## Limits

A failed/unknown/compact/noncanonical event sends error-reference processing through the entire original path. Workload-dependent gains may be smaller; Activity construction, input/output sanitization of retained candidates, credential scanning and SQLite writer holds remain. No controlled performance acceptance target is closed. The previously failed strict 420-write runs, real 503 responses, missed deadlines and post-abort progress errors remain failures.

Rust durable history query

This slice connects the fresh Rust observation store to a bounded read API, the agenturm query command, and older-history navigation in agenturm inspect. It reads only the Rust-owned observation database. It does not import, bridge, or modify Python-era state.

Query contract

  • Optional exact harness_id and session_id filters apply before paging.
  • Storage uses a deterministic descending key of timestamp, harness, event, and revision. Each page returns oldest-to-newest for capability and UI reduction.
  • The exclusive cursor carries all four ordering fields and a snapshot_id.
  • The snapshot watermark is the highest committed sequence in a dedicated AUTOINCREMENT receipt table on page one. Later pages exclude later receipts, including backdated observations, so concurrent collection cannot shift traversal. The explicit sequence is durable across VACUUM and row deletion.
  • Page size defaults to 500 and is bounded to 1–16,384. The inspector reads 500 observations per page. Timestamps and snapshot IDs are decimal strings in JSON to preserve integer precision.
  • In the inspector, [ loads older history and ] returns through a cache of at most four page models.

First page:

agenturm query --db ./state.sqlite --harness-id harness.codex --session-id session-1 --limit 500

Pass every field from next_before to fetch the next older page, including snapshot_id. When has_more is false, the current snapshot has no older matching observations.

Safety and limits

The query opens a v3 store through SQLite read-only mode. It does not create a database for a missing path, initialize an empty file, migrate schema, change journal settings, or change observation rows/cursors. Open a v2 store through a write-capable operation such as inspect or collection first; that path performs a transactionally backfilled v2-to-v3 schema upgrade. The store validates filters, page size, cursor identity, timestamp range, and snapshot watermark before parameterized SQL. A cursor from another snapshot and a future watermark are rejected. Existing marker checks reject unrelated databases. Terminal pages do not emit a next cursor.

The watermark relies on the explicit AUTOINCREMENT sequence remaining durable. The current store has no retention. If a future retention feature prunes history, it must preserve the monotonic sequence and cursor contract. Paging does not hold a long-lived SQLite transaction or pin the WAL.

This is a bounded observation query, not full domain query parity. Lifecycle summaries, relationships, private content, policy-filtered hydration, network APIs, arbitrary ordering, and text search remain open. The in-memory inspector back stack is bounded; reopening starts at the latest page.

Verification

Focused tests cover equal-timestamp ordering across harnesses, source/session filtering, stable pagination, a concurrent backdated write excluded by the watermark, v2-to-v3 schema upgrade, missing-path and empty-file no-write behavior, invalid cursor rejection, close/reopen queries, CLI cursor round-trip, terminal-page cursor omission, and UI cursor precision above JavaScript’s exact integer range. Workspace formatting, Clippy, and full Rust workspace tests are recorded with the implementation PR.

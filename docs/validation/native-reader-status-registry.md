# Native reader status registration

Recorded 20 November 2026. The native collector now builds reader-specific status fields from `NativeReaderSpec.status_extension` declarations. Its core status assembly no longer names OpenCode or keeps an `self.opencode` reader alias. The bundled OpenCode reader declares the four existing flat compatibility fields: discovered sessions, omitted sessions, diagnostics, and read errors. They retain zero/empty values when that reader is disabled, while the generic `reader_plugins` map continues to expose active reader diagnostics.

The host validates each declaration's field names against its core status keys and other reader declarations. At publication it requires the exact declared field set and a JSON payload no larger than 64 KiB; a faulty callback increments the collector's read error and cannot replace core or adapter status. Native source status extensions are also checked against the registered reader keys. An injected fixture reader proves that a second reader can add its own field without editing the collector's status assembly.

After rebasing onto the native state-context hook, 56 installed reader registry, OpenCode, budget, and native port tests passed. An earlier broader 52-test status/UI run found two failures in tests that construct a collector without calling `__init__`; the extension validator now tolerates that test fixture, and the affected tests passed in the final 56-test run. The other 50 tests passed in the broader run. This is a status boundary refactor only; it does not change polling, source discovery, evidence admission, UI layout, Rust storage authority, or measured performance.

Rust backup-only Activity projection read

The diagnostic agenturm-storage-shadow binary can now read one process source’s published activity_index_v1 rows from a completed, isolated SQLite backup when a caller sets "include_activity": true. The default certificate and optional session output remain unchanged without this option. Python still owns production writes, capture policy and live freshness. No performance gain is claimed.

Read boundary

The binary opens the backup READ_ONLY with URI immutable=1 and query_only, refuses sidecars, and reads the receiver/source certificate and Activity rows in one short transaction. It returns activities only when capture is enabled and source dirty sequence and policy match the published projection. Unknown, pending and disabled sources omit the field. This certificate describes the backup; Python’s live rust_shadow_snapshot.current() check is still required before publishing a result.

SQLite preflights at most 50,001 source-owned plugin rows, 8 MiB of aggregate JSON payload, 16 MiB of aggregate row text and 16 KiB per row before Rust loads the JSON. Each row must match the exact source and the source cursor’s plugin ID. Rust checks event, session, agent and turn IDs; index columns against the payload; fixed v1 message, tool and check vocabulary and subject; typed provenance and tool-turn relations; content-free fields; and an exact field allowlist. Invalid JSON, mismatched fields, extra content metadata or oversized rows fail closed. The reader validates the published v1 projection; it does not independently re-reduce source evidence.

Differential gate and limits

Installed tests compare full Rust Activity arrays to Python’s rust_shadow_snapshot.capture(...).expected["activities"] for messages, started and late-result tools, and checks across two sessions. They cover recovered tool-turn relation, exact source scope, source-wide gap, pending and revoked capture, historical backups, unchanged backup files and no sidecars. Corrupt IDs, subject, provenance, flags, extra prompt data, index columns and oversized payloads fail closed. Rust package tests, Clippy with warnings denied, formatting and eight installed differential tests pass.

The supplied backup must be finished and quiescent; immutable=1 cannot prove another process is not changing it. The v1 field allowlist is intentionally strict, so later Activity fields need a versioned compatibility decision. Live query parity, independent evidence recomputation, a Rust writer, one-writer cutover, downgrade handling and crash/rollback drills remain open.

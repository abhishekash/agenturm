Native adapter status extension checkpoint

19 November 2026. Active native adapters contribute top-level health metadata through an optional status_extension hook. The generic collector calls one instance per adapter group, isolates exceptions, rejects duplicate keys and forbids overriding host-owned health fields, and limits serialized extension data to 64 KiB. Kiro’s workspace permission scan, ten-second cache and metadata-only folder redaction moved from LocalAgents into KiroAdapter. The existing kiro_folders: [] field remains present when no Kiro source is active for health-client compatibility.

The adapter receives the capture-details setting and an error-report callback, not a Store handle. Kiro reports an OSError from workspace scanning while retaining its last cached result. The collector still owns discovery, bounded polling, persistence and the health response.

This is a trusted in-process extension, separate from the supervised process plugin API.

The provenance manifest binds updated source hashes to commit 41a51fa and retains prior hashes as history. Fixture bytes and observed producer-version claims are unchanged.

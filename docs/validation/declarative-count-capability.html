Declarative count capability

Agenturm validation · 20 November 2026

An explicitly installed third process contributes a Count observations pane. Existing Prompt signals and Action observations configurations remain valid. Counts and ratios describe a bounded Activity page; they are not prompt efficacy or quality scores.

Activate explicitly

python examples/count_observations_process/install.py --destination /absolute/private/counts
agenturm cockpit --capability-config /absolute/private/counts/capability.json

The inert schema-v3 descriptor declares up to six exact domain/action count selectors and six count or ratio rows. It cannot contain SQL, regular expressions or executable host code. Labels use at most 14 single-cell ASCII characters so ratio names fit the required compact two-column pane. The pinned executable asks only for scoped aggregate read access. The existing pane registry renders it without a new UI branch.

What crosses the boundary

The host fetches at most 200 events for one exact service, session and agent, then sends only named counts, observed-event count, state and a page-completeness flag to the child. No prompt, tool output, path, event ID, source ID, session ID, agent ID, policy revision or page signature crosses the process pipe. Every displayed value and label must match host recomputation. Zero denominators render unavailable.

Revision fence

Exact capture-scoped Activity replies include an opaque revision derived from receiver identity, receiver process and collector instances, approved sources and durable capture policy. Ordinary Activity replies do not. The worker reads a second exact page after the child response and compares that revision plus the selected event signature before publishing. Missing revisions, revoke/re-enable during computation and changed pages withhold the model. The existing 250 ms watcher approval window still applies after publication; this is not atomic revocation of an already displayed aggregate.

Terminal layout and checks

At 60×18 and 80×24 the cockpit shows one selected pane, with no extra border or global marker. Two columns show the signal and observed value; one summary carries coverage instead of repeating it on every row. Source evidence may be partial even when pagination is complete. The UI event thread performs no disk, HTTP or child work.

Trusted reference wire

20 November 2026 · opt-in trusted extension

A bounded process reference family can be added through a host-owned handler and capture mode. Python Store remains the production writer.

Private content is not generally enabled. The only new fixture carries a fixed nonprivate audit token. New private-content sources need their own proof, read policy and revocation tests.

Host contract

  • A registered feature selects one trusted handler. Unknown *-ref/N features and conflicting handlers fail before process startup.
  • reference_refs contains schema version 1 and at most 48 references in a 64 KiB envelope under existing frame and JSON limits. The family validator checks the exact shape.
  • The trusted capture mode binds feature, admission provider and host-derived grant. The child cannot select or install a provider. Pi's existing content and command envelopes keep their own validators.
  • The common Store admission transaction commits evidence, cursor, provider rows and replay receipts together.

Validation

An installed synthetic process commits a nonprivate audit receipt, replays exactly without a new dirty sequence, then revokes and fences its old lease. Tests also reject unknown or unbound features, forged provider fields and malformed envelopes, and check receiver-to-supervisor registry wiring.

Remaining limits

This is a transport and dispatch extension point, not a private-content authorization or Rust storage cutover. A new private-content harness still needs configured-artifact source proof, redaction/read policy, replay and retention handling, and revocation coverage. The default receiver installs only Pi reference families. No performance gain is claimed.

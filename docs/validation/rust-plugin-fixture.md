# Rust plugin fixture checkpoint

Date: 19 November 2026. A separately compiled Rust executable now exercises protocol 1 through the opt-in Python process host and Store admission path. It is a deterministic fixture, not a production harness or public SDK. The executable uses the shared bounded frame crate and JSON control messages, sends one synthetic lifecycle record with a nanosecond timestamp above 2^53, waits for its acknowledgment, then responds to later polls with an unchanged cursor and no records. It rejects wrong source IDs, unexpected cursors, missing budgets and polling before acknowledgment.

The Python host validates the fixture's manifest and artifact SHA-256, copies the binary to a private execution directory, controls the source lease, admits the record transactionally and acknowledges only after Store commit. A second process instance resumes the durable cursor and yields no duplicate evidence. The Rust binary never opens the Agenturm database or gains storage authority.

Validation on the local Linux x86_64 host with Rust 1.100.0: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked` (7 Rust tests), `cargo build --locked --bin agenturm-fixture-plugin`, and the Python cross-language integration test passed. CI builds and runs the fixture in the Rust job; the general Python matrix skips that test when no compiled fixture path is supplied. An independent Rust reviewer found and verified fixes for a Unicode source-ID mismatch and Store test cleanup; no blocking fixture finding remains. The compiled artifact is not shipped in a wheel. No throughput, resource or end-to-end Rust speed improvement is claimed.

Remaining Phase 5/6 gates: a reusable SDK, two real adapters, installed package/discovery path, restart/backoff supervisor, capture-policy epoch and live projection, packaging on supported platforms, and a measured end-to-end performance gain.

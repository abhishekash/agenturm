Native reader status registration

The collector now reads reader-specific status fields from registered NativeReaderSpec declarations. The OpenCode reader declares its four existing flat compatibility fields, including zero and empty values when disabled or replaced. Active diagnostics remain in the generic reader_plugins map.

Boundary

The collector no longer keeps an OpenCode reader alias or names OpenCode while building status. An injected replacement may add fields but cannot redeclare bundled compatibility keys. The host rejects duplicate or core field names, undeclared output fields, and payloads above 64 KiB. A faulty reader callback records an error without replacing core status. Native source extensions cannot reuse registered reader keys.

Validation and scope

After the replacement-reader fix, 57 installed reader registry, OpenCode, budget, and native port tests passed. An earlier broader 52-test status/UI run found two failures in partially initialized test collectors; the validator now tolerates that fixture, and those tests passed in the final run. The other 50 tests passed in the broader run. A fixture reader demonstrates adding a field through registration. Polling, evidence admission, UI layout, and Rust writer authority are unchanged. No performance gain is claimed.

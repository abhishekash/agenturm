Confirmed source behavior

Area Current behavior Consequence
Discovery Default discovery selects four transcript files per harness by filesystem modification time. The supported per-harness maximum is eight, with sixteen configured sources globally. Discovery is a bounded recent-file selection rather than an inventory of every running session. A running session can be outside that selection. The exact reported exclusions require runtime comparison.
Explicit history inspection --db inspection opens history read-only and does not start a collector. This mode needs a separate active writer to receive new observations; it is not equivalent to bare startup.
Live collection Bare startup uses follow discovery. If the history has another writer, the cockpit opens that history without starting its own collector. Effective data coverage depends on the actual writer, selected roots, discovery results, progress and failures. A roster refresh alone cannot collect an undiscovered source.
Session roster The catalog reads up to 200 retained source/session summaries. Status comes from the latest recorded lifecycle fact. All and Working describe the loaded retained evidence; they are not an operating-system process census or proof that every live agent is represented.
Session titles Exact saved task titles take priority. Remaining labels are selected from a bounded retained structural page: PR, file edit, MCP, check, tool or trace. The screenshot's generic labels are expected from this implementation. Native display/session titles are not projected into the roster.
Project headings Paths are read from explicit operator-saved Git snapshots linked to a current local session-level task. Native session cwd/project metadata is absent. Project unavailable is expected without a qualifying task link, even if the harness knows its project directory.

Define and implement the expected active-session inventory, separate live membership from recorded lifecycle, avoid silent omission under capacity limits, and expose discovery/admission coverage and catch-up state. Human-readable naming acceptance (E2)

The user explicitly requires names that humans can recognize. Session IDs alone do not satisfy the roster's naming requirement.

  • The primary row label must be the native task/conversation title or an explicit operator-saved task name. Generic MCP, file-edit, tool or trace activity labels do not pass named-session acceptance.
  • Agent nickname, provider and project provide supporting context. Keep task identity separate from agent identity and latest activity.
  • Session/source IDs remain available in details and copy actions; they must not displace the human-readable primary label.
  • Renaming a task or native conversation must retain stable selection, links, history scope and references. Display names must not become identity keys.
  • Handle duplicate titles, subagents and missing names explicitly. Duplicate names need supporting context; absent names need an honest unavailable-name state rather than invented names or a generic activity presented as a title.
  • Acceptance must compare actual Codex and Claude native names with their roster labels, including rename, duplicate-name and subagent scenarios.

These requirements remain the acceptance contract for the authorized implementation. The historical diagnosis itself did not change runtime behavior.

Implementation follow-up

The 0.3.9 candidate adds bounded follow-source rotation, priority for exact same-user native transcript handles, exclusion of confirmed guardian reviews before adapter admission, and visible discovery coverage. Open handles are selection evidence; roster status remains the recorded native lifecycle.

Native display context uses exact retained source cursors, native file identity, and the selected history incarnation. Explicit operator names and project links win. Safe native Codex names and Claude custom titles follow; source/session IDs remain stable keys in inspector and copy actions. Structural tool activity is supporting activity, never a substitute name. Prompt-like Codex title fields are suppressed instead of copying the initial user prompt into the roster.

The inspection mode remains read-only and now states that discovery is disabled. Large or unavailable metadata sources fail closed and report bounded coverage. Actual native root and process-witness acceptance is required before claiming that the original running-session complaint is fixed.

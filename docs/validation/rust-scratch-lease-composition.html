Scratch Rust admission with a cooperating lease

Agenturm validation · 20 November 2026

This composes two feature-off Rust experiments. The receiver and Python Store do not call them; Python remains the only production database writer.

Exact sequence

The standalone CLI validates a bounded host-prepared request, then reads an existing regular SQLite database and requires storage_admission_scratch_v1=enabled. With a stable pathname, an unmarked database gets no read/write open or Agenturm lock file. A pathname swap after that read may create a lock beside another target before the transaction rejects it. SQLite may also use its normal read-only WAL/SHM machinery.

For a marked fixture on Linux, WriterLease::acquire binds the lexical path, resolved inode and private no-follow sibling lock. Hardlinked databases are refused. The CLI verifies the lease before opening read/write and again inside BEGIN IMMEDIATE, before any write; the scratch marker is rechecked in that transaction. The lease remains held through commit and connection close. A lost reply after commit can still leave a committed batch; exact replay is the recovery path when the fixture remains available. Empty idle polls retain their earlier behavior.

Limits

The read-only preflight and later SQLite connection are separate opens. rusqlite does not expose the connection's stable main-file descriptor here, so a swap-and-swap-back race remains possible. This is a cooperating scratch fixture protocol, not a production writer, legacy-binary fence, or security sandbox against same-user filesystem changes. The writer cutover gate records the remaining ownership tests.

Verification

  • Installed Rust/Python lifecycle differential, replay, cursor, dirty-marker and empty-content receipt checks.
  • Private lock mode and no lock file for unmarked databases.
  • Another process holds the lock; scratch admission refuses without changing stored state, then succeeds after release.
  • Hardlink and final-symlink aliases refused. The lease crate separately covers symlink/database replacement, lock replacement, crash release and shared same-process handles.

Eight Rust unit tests and ten installed Python differential/contention tests passed. Focused Clippy with warnings denied, formatting and diff checks passed.

No performance gain or general evidence/content parity is claimed.

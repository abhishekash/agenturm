Exact Rust backup query attestation

Recorded 20 November 2026. This opt-in Python diagnostic boundary checks one result from agenturm-backup-query against the policy-current Python Store projection. It does not start Rust, create a backup, serve an API or change production queries. Python remains the live authority and sole writer. No performance claim is made.

Contract

attest_exact(store, query, rust_result) takes the raw Rust JSON result and one exact source-scoped session or Activity query. It rejects duplicate keys, non-finite numbers, oversized output, extra or missing fields, malformed identities, a different query/source, and any state other than ready with partial coverage. A fresh Python capture() must be ready.

The attester binds the Store’s resolved regular target identity, including an explicit --db symlink, checks the full receiver and revision, and compares the selected row or exact absence with capture(...).expected. It then calls current() and rechecks file identity before returning. A symlink retarget fails closed. It returns Python’s row, its checked revision and partial coverage. Backup content is never returned directly.

The result was valid at the final check instant. A later write can stale it. An exact miss means only absence from the current partial projection. A source gap can produce an explicit Unknown/source_gap row.

Evidence and limits

Installed Rust query tests cover matching rows and absence, a valid-looking altered backup with unchanged revision, stale evidence, capture revocation, pending projection, source-gap state, malformed output, revocation during the final check, and atomic same-revision Store file replacement. Tests use small completed SQLite backups. The helper makes no production backup copy.

This point-in-time gate does not certify full-source completeness, Rust storage authority, crash recovery, a production query default or a performance improvement. Writer and client migration gates remain open.

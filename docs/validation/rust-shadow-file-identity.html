Shadow snapshot Store-file fence

Recorded 20 November 2026. The opt-in rust_shadow_snapshot.capture() binds its content-free, policy-current fixture to the regular SQLite Store file it read. current() checks that file identity before and after reading receiver, lease, policy and projection state. Both use the Store’s read-only connection pool. Python remains the live authority and sole writer.

Why it matters

An atomic replacement can have the same receiver and revision but a different projected row. The captured target’s device and inode now form part of the freshness fence. Replacing the file, or retargeting an explicit --db symlink to another file, makes the old snapshot stale. The backup-query attester reuses the same resolved-target check. A manually constructed snapshot without a captured identity cannot pass current().

These are checks at the time of the read. A later write or file replacement requires another check. They do not authenticate a copied database or prevent swap-and-restore between observations.

Verification and limits

Focused shadow, installed backup-query and Pi content tests passed after rebasing: 36 tests, one installed-reducer test skipped. New regressions cover same-revision file replacement with a different projection and symlink retargeting. The attester now accepts a symlinked Store and rejects a retarget during its final check. The backup-attestation replacement test expects current() itself to reject the swap. An older local reducer binary had an unrelated Activity schema mismatch and was excluded from this result.

No production query default, Rust storage authority or performance claim changes. Full storage cutover and installed-client parity remain open.

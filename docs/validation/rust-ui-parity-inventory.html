Rust cockpit UI parity inventory

23 November 2026 · Python reference v0.2.8 at 2802d79930728bb331db1d4d718d6dea1c9c374d · Rust source baseline 2149034 on work/ui01-inventory.

This is the UI-01 reference map for the Rust cockpit UI parity plan. It records every tagged Python root view, inspector section, nested screen, help/diagnostics surface, control, key binding and visible state, then maps it to the Rust entry point and source location. The Markdown and HTML copies are generated from the same row data.

Architecture constraint. The inventory assumes kernel ports, supervised source adapters, agenturm-*-harness crates, the ExtensionPlugin/capability/pane seams and the process-plugin host are preserved and advanced. No provider-hardcoded path or app-level special case is acceptable where an adapter or extension seam exists. The Seam column marks where Python behavior needs a new pluggable contribution rather than a hardcode.

The large implementation-gap count is concentrated in the integrated inspector/Prompts journey, view-specific search/filter/detail behavior, Review continuity, saved-task brief/decisions/runs, diagnostics and mouse/focus. Qualification-pending rows are evidence paths that exist but still need exact paired or installed acceptance.

Method and evidence

Python behavior was read from the tagged tree with git show v0.2.8:...; the tag was never checked out. Sources included terminal_ui.py (5005 lines), ui_keyboard.py, themes.py, the monitoring/workflow/diagnostics/export/findings/investigation/review/saved-task modules and the tagged screen tests. Rust behavior was read from rust/agenturm-ui/src and the app-layer projections in rust/agenturm-app/src.

A source path is not an acceptance result. Implemented requires a usable path and a focused in-tree Rust check for that exact behavior; a named test is an acceptance case, not a claim that this inventory ran it. Qualification pending means source exists but the exact journey, paired frame or installed-candidate case is unrecorded. Implementation gap means no usable path. Source evidence unavailable means the tagged source cannot determine the behavior. Intentional difference means an approved deviation still needing UI-Q sign-off.

Key gaps discovered

  • Rust has no Prompts or Details inspector section; the integrated request navigator/reader is the main UI-03/UI-04 gap.
  • Today, History, Errors reminders, the searchable session chooser and selectable sort direction are missing; grouping/order is the approved intentional difference.
  • No command palette; Ctrl+P currently owns themes. No focus chain, focusable buttons or mouse events; Ctrl+C always interrupts.
  • Diagnostics is absent and d currently opens Findings while help says diagnostics.
  • Activity lacks search/Prompts/Errors filters, failure grouping and nearby evidence; Traces lacks a span tree; trace links are incomplete.
  • Copy/export use the loaded metadata pane, not the selected record; Review has no brief/JSON copy, receipt export, Git capture, decisions/excerpts or continuity draft.
  • Workflow lacks the composed incident report, Review-from-Workflow, cleanup and completion history; saved tasks lack search, archive, brief, decisions, runs, continuity and handoff preview.
  • The responsive floor is 38×8 and several views keep list+detail at 60×18; the exact Textual theme chooser is framework-owned and unavailable from tagged source.

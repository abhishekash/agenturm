# Plugin usage projection checkpoint

19 November 2026. The opt-in process adapter path now projects admitted, typed usage counters into its policy-current session rows. The host reduces only the latest revision of each stable event ID, then adds distinct usage observations for the same native session. An exact replay adds nothing. Corrections replace their earlier values. Missing native identity remains unattributed. Missing counters remain absent, while an explicitly reported zero remains visible.

The projection stores a compact JSON object alongside the existing lifecycle state. JSON keeps exact totals even when several valid 64-bit event counters sum beyond SQLite's signed integer range. Existing projection tables gain a default empty usage object through a non-destructive migration. The same dirty sequence, source lease and policy epoch guard both state and usage. A new batch hides the old projection until rebuild; capture revocation deletes evidence and projection together.

The receiver includes `metadata_usage` in each projected session within `/api/health`. Values above the largest exact JavaScript integer are decimal strings, preserving exact API totals. The generic session details view renders reported fields as **Reported source usage**, independent of trace-derived task usage. It does not infer `total_tokens`, model, cost, turn ownership or completeness. The [provisional source SDK](../plugin-source-sdk.md) defines event IDs as additive observation identity and explains correction behavior.

Validation: 42 focused tests passed, covering correction, distinct additive events, exact large totals, missing identity, revocation, existing-table migration, HTTP health projection, generic usage formatting and the existing UI contribution shell. `compileall` and `git diff --check` passed. The Python Store remains the only writer. This does not add retention, a bundled harness, full content capture, a Rust ingestion path or a retained-history performance gate.

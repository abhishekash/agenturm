Experimental v2 scratch service checkpoint

20 November 2026 · Opt-in Linux experiment · No production Rust writer or canonical migration

Boundary

Ordinary mode remains a v1 probe with an empty service-owned 0700 data root. --experimental-v2-scratch enabled selects one fixed, pre-existing scratch.db under that root. The client frame carries no path. The file must be a service-owned, singly linked 0600 regular file with the explicit scratch marker. The separate transport root is 2710 and its socket is 0660.

The service takes its instance lock before SQLite marker preflight and holds a private 077 umask in scratch mode. The private root admits only the scratch file, known SQLite sidecars and its writer-lease file; the scratch inode is pinned across requests.

Request handling

Linux SO_PEERCRED is checked before parsing. A single v2 frame is limited to 64 KiB and a two-second total frame deadline. The receiver identity is checked, then the existing scratch transaction rechecks source lease, policy, cursor, evidence, marker and durable replay identity. A reply is bound to the request before framing. Rejections send no reply. If a post-commit check fails, the scratch receipt remains durable while the reply is withheld; an exact retry is safe after the service path is restored. Experimental mode rejects v1 probes; normal mode never dispatches v2.

Validation

Local gates passed: 27 targeted Rust tests, Clippy with warnings denied, formatting, 10 existing installed service tests, 13 installed scratch CLI tests, and both disposable root-required Docker fixtures in a bare Python 3.12 image without network.

The v2 account fixture proves:
  • Valid commit and exact replay, including a deliberately discarded reply; conflicting request ID rejection.
  • Wrong receiver, UID/GID and same-UID denial; oversized and v1 frames rejected.
  • Fresh old-Python-Store denial and an unchanged unrelated canonical sentinel.
  • Scratch pathname replacement, extra private-root file and missing marker rejected. The fixture starts the service with inherited umask 000 and checks every resulting scratch file is service-owned 0600.

Remaining gates

This is a disposable scratch writer only. Full Python mutation routing, old held-open writer exclusion, durable workflow/task/outbound state, production migration and WAL recovery, and other platform service principals remain required. See the writer cutover plan. GitHub CI status is separate from these local checks.

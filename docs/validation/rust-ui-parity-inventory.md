# Rust cockpit UI parity inventory

23 November 2026 · Python reference **v0.2.8** at `2802d79930728bb331db1d4d718d6dea1c9c374d` · Rust source baseline **`2149034`** on `work/ui01-inventory`.

This inventory is the UI-01 reference map for the [Rust cockpit UI parity plan](../rfcs/rust-ui-parity-plan.md). It lists every Python root view, inspector section, nested screen, help/diagnostics surface, visible control, key binding and visible state that the tagged cockpit exposes, then maps it to the Rust entry point and source location. The [HTML companion](rust-ui-parity-inventory.html) is generated from the same row data and is the required responsive review copy.

**Architecture constraint.** The inventory assumes the original pluggable architecture is preserved and advanced: kernel ports, supervised source adapters, `agenturm-*-harness` adapter crates, `ExtensionPlugin`/capability/pane seams and the process-plugin host. No provider-hardcoded path or app-level special case is acceptable where an adapter or extension seam exists. The **Seam** column marks rows where Python behavior would need a new pluggable contribution rather than a hardcode.

## Method and evidence

Python behavior was read from the tagged tree with `git show v0.2.8:...`; the tag was never checked out. Sources read in full or in the relevant sections: `observatory/terminal_ui.py` (5005 lines), `ui_keyboard.py`, `themes.py`, `ui_monitoring.py`, `ui_workflow.py`, `ui_diagnostics.py`, `ui_export.py`, `ui_findings.py`, `ui_investigations.py`, `ui_review.py`, `ui_saved_tasks.py`, `ui_content.py`, `ui_layout.py` and the tagged screen tests. Rust behavior was read from `rust/agenturm-ui/src` and the app-layer projections in `rust/agenturm-app/src`.

The status vocabulary is deliberately strict. **A source path is not an acceptance result.** A row is **implemented** only when a usable path exists and a focused in-tree Rust check exercises that exact behavior; a named test is an acceptance case, not a claim that this inventory ran it. Rows with source but no focused journey are **qualification pending**. Rows with no usable path are **implementation gap**. Behavior that cannot be determined from the tagged source is **source evidence unavailable**. Approved deviations are **intentional difference awaiting acceptance** and still require UI-Q sign-off.

| Status | Meaning |
| --- | --- |
| **Implemented** | A usable Rust path exists in source and at least one focused in-tree Rust check exercises this exact behavior. This is not a paired installed-Python acceptance claim. |
| **Qualification pending** | A usable Rust path exists, but the exact journey, paired frame or installed-candidate acceptance case has not been run and recorded. Do not promote to implemented without that evidence. |
| **Implementation gap** | The Python behavior has no usable Rust equivalent, or the present path contradicts the documented contract. |
| **Source evidence unavailable** | The tagged Python source does not determine the behavior (for example, a framework-owned surface). Record the dependency and do not infer parity. |
| **Intentional difference awaiting acceptance** | A deliberate deviation approved by the plan or required by the Rust-only product decision, still needing explicit UI-Q sign-off. |

**How to read a row.** *Python reference* names the entry key/control and tagged source. *Visible fields* says what appears; *Initial focus* names the expected starting control (a selected row/table means its active row). *Actions* lists available actions. *Return and unavailable behavior* states the exact selection expected on return and what happens when access or data is unavailable. *Mouse* records the Python click equivalence (or the absence of one). *Rust entry and source* gives the current path. *Acceptance case* is the check that would promote the row. `—` in **Seam** means no new pluggable seam is implied.

This lane is documentation only. No Rust or Python code, test, preference or other lane's file was changed.

### Key gaps discovered

- **Inspector shape.** Rust has `SessionView::Overview/Activity/Review/Usage/Traces`; Python has three inspector sections (Overview/Prompts/Details). The Prompts navigator/reader and the stable-identity Details section are absent. The Workbench Prompts list is not the integrated Prompts section.
- **Command center scope.** Today, History, Errors reminders, the searchable session chooser and selectable sort direction are missing. The approved project-grouped, newest-first landing order is recorded as an intentional difference; absence of the chooser and time scopes is not.
- **Shared input.** There is no command palette (and `Ctrl+P` is currently themes), no focus chain or focusable buttons, no mouse events, and `Ctrl+C` always interrupts instead of copy-by-focus. `Esc`/q and help ownership are partial.
- **Diagnostics is misrouted.** `d` opens Findings while help says *Recorded diagnostics*; there is no diagnostics surface for collection, source, storage, index or receiver health.
- **Evidence views are tables, not journeys.** Activity has no search/Prompts/Errors filters, failure grouping or nearby evidence. Traces has no span tree or parent/child navigation. Host has recorded/current levels but no Python-style view-level process table on the root Host tab. Metrics, Usage, MCP and Findings are substantially stronger.
- **Copy/export scope.** Rust copies/exports the loaded metadata pane; Python copies the selected record or inspector and previews a per-record JSON export. The Rust loaded-view safety tests are good but do not cover the missing selection scope.
- **Review continuity.** Rust Review is a pane, not the frozen Review workspace: no latest request/agent update/context sections, brief/JSON copy, receipt export, Git capture/map, decisions/excerpts or continuity draft.
- **Workflow depth.** The composed incident report, Review-from-Workflow, cleanup and completion-history/review-visible-completions paths are absent.
- **Saved tasks.** No task search, archive/include-archived, structured brief, decisions/versions, runs list, continuity draft or handoff preview. Delete is hard delete; Esc discards a dirty draft without confirmation.
- **Responsive floor.** Rust declares 38×8 and several views have their own messages; Python requires 60×18 and gives a usable quit floor. Compact layouts still show list+detail and have no focus remap.
- **Framework-owned Python surface.** The exact Textual theme chooser/palette rendering cannot be proven from the tagged repository. Both `source evidence unavailable` rows are framework-owned surfaces.

## Boundaries and next gates

- This inventory does not run the paired Python/Rust acceptance matrix. It maps source paths and names in-tree checks. UI-Q owns the installed-candidate, fixed-clock, terminal-size, theme and provider-mode evidence.
- Test names in acceptance cells are existing Rust tests where present; their presence is not re-verified here. Where a row is qualification pending, the acceptance cell describes the missing journey rather than an already-passing result.
- The command-center grouping/order and fixed newest-first direction are the only planned landing-screen deviations recorded as intentional. The Rust-only Operations/Usage/Host keys and the Workflow `l`-versus-`g` Locate binding need explicit UI-Q acceptance.
- Unknown values must remain visible as unknown. A recorded lifecycle state never establishes current OS process liveness. A partial page or bounded prompt history must say so and link to the retained-history route.
- No provider-specific edit/MCP detail is claimed beyond FD2's retained proof and current grants. No AI summary is claimed without an explicit provider, grant and egress policy.

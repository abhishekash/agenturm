Agenturm kernel architecture checkpoint

Recorded 20 November 2026 at merged main be9a386 (PR #202). This is an implementation checkpoint for the reviewed Rust kernel plan, not a completed migration or a speed claim.

Building block Working path Remaining acceptance work
Harness adapters Trusted bundled native readers register source and format contributions. The opt-in Rust process path now has one-file or one-database Pi, Codex, Claude Code, Kiro and OpenCode readers behind framed supervision, Store admission, durable cursor and explicit source replacement. A shared JSONL runtime verifies the full acknowledged prefix and gaps prior sessions on rewrite, rotation or legacy cursor migration. OpenCode's native turn Review query is a bundled contribution. Process readers still need bounded multi-session discovery, broader native-format compatibility and complete source-to-Review/export parity. One configured source per process and the small config cap prevent default replacement. Full-prefix verification reads the acknowledged prefix twice per idle poll, up to 1 GiB of reads at the 512 MiB ceiling; its whole-app cost has not been measured.
Connectors An isolated inbound loopback fixture proves pagination, rate limits, durable cursor, expiry, replay and capture revocation. A fixture-only action process proves grants, durable outbox, idempotency, uncertain-response lookup and recovery fencing. Real destinations, credentials, user controls and production delivery are not enabled.
Capabilities and UI Generic pane registration renders a bounded Prompt signals process model at 60×18. Its receiver-side aggregate endpoint now checks exact native ownership and capture provenance at request time, with a database change watch before response. Native MCP config inventory comes from trusted adapter declarations. Capability process activation remains opt-in; UI models refresh asynchronously. Prompt signals reports observations rather than efficacy. General third-party SDK, broader metric capabilities and removal of remaining runtime labels in the UI are open.
Rust host and distribution The opt-in Rust process host runs installed adapters under Python Store and policy authority. Control writes, backpressure and process-group cleanup have regression coverage. A Linux x86_64 wheel bundles a SHA-pinned host and passes isolated installed receiver checks; the pure wheel remains functional. Further platform wheels, publication gates, default activation and a measured whole-app performance result remain.
Durable authority Python Store owns capture policy, leases, admission, cursor/commit/ack, retention, projection and the sole database writer. A read-only Rust shadow snapshot is fenced by receiver, lease, policy, dirty sequence and published revision. Pure Rust reducer fixtures v1–v3 match Python lifecycle, usage, relationship, Activity and durable source-gap invalidation on the tested corpus. Full query/storage compatibility, live Rust authority, legacy writer exclusion, one-writer cutover and rollback drill remain. No production data is written by Rust storage.
Validation Focused Rust workspace and installed receiver tests passed for the merged slices. The broad PR #188 Python snapshot ran 1,639 tests with 43 skips and one failure: the HTTP-tail smoke declined to run below its 4 GiB free-disk reserve; the exact smoke passed alone after disk cleanup. This broad snapshot is not green and predates newer merges. GitHub CI for the latest PRs was queued. The retained-history under-5% CPU gate, sustained-write latency gate, full installed-client matrix and migration drill have not passed. No Rust performance gain is asserted.

An independent Rust architecture review found the crate dependency direction clean: the host depends on the protocol, harness binaries depend on shared source crates, and the domain reducer has no harness dependency. It found no merged Rust path writing directly to Agenturm's Store. The highest-priority gap is discovery and scale: one source per configured process with at most four configured rows. The next slice is a versioned, bounded per-source checkpoint and multi-session discovery path, followed by complete evidence parity for a real harness. Remaining Python compatibility coupling, including source labels in the UI, should leave generic services through registered contributions.

Python remains the sole writer until source semantics, query compatibility, crash recovery and rollback gates pass. The user chose idiomatic Rust for the implementation; performance is measured separately and is not a prerequisite to continuing the architecture work.

Agenturm kernel architecture checkpoint

Recorded 20 November 2026 at merged main a97367b (PR #175). This is an implementation checkpoint for the reviewed Rust kernel plan, not a completion certificate or a speed claim.

Building block Working path Remaining acceptance work
Harness adapters Bundled native readers and JSONL adapters register through trusted factories. Separately installed Python and Rust samples run through the versioned, pinned process protocol and host-owned durable admission. An explicit replacement removes a claimed built-in source or reader. Bring each production harness through the process contract at source-to-Activity/Review/export parity. The samples capture only bounded metadata and cannot replace Pi, Claude Code, Codex, Kiro or OpenCode at current evidence quality.
Connectors A loopback read-only source proves pagination, rate limits, expired cursors and replay. A separate fixture-only action process proves explicit grants, durable outbox, idempotency, uncertain-response lookup, revocation and recovery fencing. Admit connector contracts through generic configuration and supervision; define real destination identity, credentials, policy and user controls before any production delivery.
Capabilities and UI A trusted pane registry renders declared, bounded view models without changes to the central Textual pane implementation. Prompt signals uses host-owned, exact-scope Activity aggregates and shows coverage. Independently installed capability discovery and process supervision, a policy-safe data exchange, and production UI activation remain open. Prompt signals is observational and does not score efficacy.
Rust host and distribution The opt-in Rust process host runs a separately installed adapter under the Python policy and Store authority. A Linux x86_64 wheel bundles a SHA-pinned host and passes isolated installed receiver checks; the pure wheel stays functional. Complete Rust host robustness, platform wheels and publication gates. The native wheel is a CI artifact; the Python path is still the default.
Durable authority The Python Store owns capture policy, leases, cursor/commit/ack, retention, projection and the database writer. Rust domain/storage parity, exact semantic corpus, single-writer cutover and rollback drill. No production data is written by a Rust storage authority.
Validation and performance Focused plugin, connector and installed-artifact checks passed locally for the merged slices. Whole-monitor diagnostics identify SQL/transaction and UI costs as credible work areas. GitHub CI for the latest merges was queued at this checkpoint. The 300-second retained-history under-5% CPU gate, sustained-write gate, complete installed-client matrix and migration drill have not passed. No Rust performance gain is asserted.

The next integration boundary is production harness evidence parity through the process protocol. Keep Python as the sole writer until that boundary, the full Rust storage compatibility corpus and an independent storage cutover review pass. New process adapter capabilities and connectors must reuse explicit grants, policy epochs, durable checkpoints and visible incomplete coverage rather than inventing a second owner for these decisions.

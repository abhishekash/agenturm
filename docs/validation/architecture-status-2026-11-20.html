Agenturm kernel architecture checkpoint

Recorded 20 November 2026 at merged main 1bd482d (PR #188). This is an implementation checkpoint for the reviewed Rust kernel plan, not a completion certificate or a speed claim.

Building block Working path Remaining acceptance work
Harness adapters Bundled native readers and JSONL adapters register through trusted factories. Separately installed Python and Rust samples use the versioned process protocol and host-owned admission. An opt-in Rust Pi reader consumes one actual Pi JSONL file with content-free lifecycle, usage and partial Activity. Its durable cursor detects several source changes. A shared Rust JSONL runtime now owns bounded tail, gap and poll/ack logic; Pi supplies format translation. Explicit replacement removes a claimed built-in reader. Pi remains native by default. The Rust reader lacks directory discovery, broader Pi version and relationship coverage, and source-to-Review/export parity. Claude Code, Codex, Kiro and OpenCode still need production process adapters and parity before replacement.
Connectors A declared inbound loopback source uses the generic connector contract with pagination, rate limits, cursor expiry, replay and capture revocation. A fixture-only action process proves grants, durable outbox, idempotency, uncertain-response lookup, revocation and recovery fencing. Real destinations, credentials, user controls and production delivery are not enabled.
Capabilities and UI The generic pane registry renders bounded view models without a Textual pane edit. A separately installed Prompt signals process receives exact-scope, host-derived content-free aggregates and supplies a validated pane at 60×18. cockpit --capability-config activates a named descriptor with a nonblocking health watcher and fail-closed cache. The current permission approval is at most 250 ms old, not an atomic receiver-side fence; a rendered model may remain until the next watcher result and UI query. A general third-party SDK and receiver-side policy-fenced aggregate API remain open. Prompt signals is observational and does not score efficacy.
Rust host and distribution The opt-in Rust process host runs an installed adapter under Python policy and Store authority. Bounded control writes, queue backpressure and process-group cleanup have regression coverage. A Linux x86_64 wheel bundles a SHA-pinned host and passes isolated installed receiver checks; the pure wheel stays functional. Further platform wheels and publication gates remain. The native wheel is a CI artifact; the Python path is still the default.
Durable authority Python Store still owns capture policy, leases, cursor/commit/ack, retention, projection and the sole database writer. A pure Rust reducer matches Python lifecycle, usage, relationship and content-free Activity fixtures, including 2,000-session lifecycle/usage capacity and malformed-input rejection. Live snapshot fencing, full reducer coverage, storage compatibility, one-writer cutover and rollback drill remain. No production data is written by a Rust storage authority.
Validation and performance Focused Rust workspace, installed-artifact and related Python tests passed locally for these merged slices. The earlier broad Python snapshot ran 1,596 tests with two failures: stale native reader hashes and a timing-sensitive catch-up expectation. PR #188 repaired those gates; a new combined-tree broad run is underway. GitHub CI for the latest merges was queued at this checkpoint. The 300-second retained-history under-5% CPU gate, sustained-write gate, complete installed-client matrix and migration drill have not passed. No Rust performance gain is asserted.

The next integration boundary is production harness evidence parity through the process protocol, followed by a complete Rust domain and storage compatibility corpus. Keep Python as the sole writer until that boundary and an independent storage cutover review pass. Process adapters, capabilities and connectors must reuse explicit grants, policy epochs, durable checkpoints and visible incomplete coverage.

Agenturm kernel architecture checkpoint

Recorded 20 November 2026 at merged main 04aa620 (PR #223, after #220–#222). This is an implementation checkpoint for the reviewed Rust kernel plan, not a completed migration or a speed claim.

Building block Working path Remaining acceptance work
Harness adapters Trusted bundled native readers register source, format and turn Review contributions. Opt-in Rust Pi, Codex, Claude Code, Kiro and OpenCode process readers use framed supervision, Store admission, durable cursors and explicit source replacement. Opt-in Codex and Pi directory modes can each track up to 48 JSONL files through one process with atomic member checkpoints, a four-file poll budget and fair scan progress. Their discovery and checkpoint engine lives in the reusable Rust agenturm-directory-source crate; each supplies its own JSONL format and stable diagnostic namespace, and a synthetic format also exercises the engine. A failed root enumeration commits a source-wide d2 gap; a previously acknowledged unreadable file commits a d3 member gap while retaining its checkpoint for recovery. Exact member ownership preserves healthy siblings, while legacy or ambiguous ownership falls back to source-wide invalidation. Pi process tool results recover their original turn only from one retained policy-current call with a strictly earlier source timestamp; ambiguous links remain partial. Shared JSONL replacement-gap diagnostics now replay identically across mtime-only changes, and acknowledged prefixes are verified. OpenCode's oc2 cursor catches same-count row replacement and ordinary restored-mtime rewrites. Pi and Codex directory discovery are explicit opt-ins; Pi single-file mode remains the default. Switching Pi modes under one durable source ID fails visibly, so each mode needs a distinct source ID. Other harnesses still need their own format binding and installed rollout gate. Process readers still need broader native-format and content-backed Review/export parity before default replacement. Deletion followed by same-identity reappearance remains a Codex and Pi directory source-history limit; changed replacement bytes or identity between retries need separate continuity treatment. Full-prefix JSONL verification can read up to 1 GiB per idle poll at the 512 MiB ceiling; whole-app cost has not been measured.
Connectors An isolated inbound loopback fixture proves pagination, rate limits, durable cursor, expiry, replay and capture revocation. A fixture-only action process proves grants, durable outbox, idempotency, uncertain-response lookup and recovery fencing. Real destinations, credentials, user controls and production delivery are not enabled.
Capabilities and UI Generic pane registration renders a bounded Prompt signals process model at 60×18. Its receiver-side aggregate endpoint checks exact native ownership and capture provenance at request time, with a database change watch before response. Native MCP config inventory and ingest scopes come from trusted bundled adapter declarations; Store's source filtering and owner-clearing triggers share the validated scope set. Host and plain output render bounded, source-neutral coverage descriptors, including unknown or failed process projection states. /api/health, the session inspector, Host and plain output surface unavailable process sources. An availability overlay alone keeps stored run outcomes last recorded; an admitted continuity gap projects affected sessions as Unknown. Selected process Pi Activity copy and JSON export now carry only typed, content-free source provenance and recheck one exact Store event, receiver, source revision and database file identity. App-mediated Ctrl+C paths check the same policy. Capability process activation remains opt-in and UI models refresh asynchronously. Prompt signals reports observations rather than efficacy. General third-party SDK and broader metric capabilities are open. The scope registry does not grant process plugins native capture authority. Full Pi content Review/export parity remains open; a source may change between the last export proof and local file creation, and text already displayed cannot be retracted from terminal-level selection.
Rust host and distribution The opt-in Rust process host runs installed adapters under Python Store and policy authority. Control writes, backpressure, bounded discovery and process-group cleanup have regression coverage. A Linux x86_64 wheel bundles a SHA-pinned host and passes isolated installed receiver checks; the pure wheel remains functional. Further platform wheels, publication gates, default activation and a measured whole-app performance result remain.
Durable authority Python Store owns capture policy, leases, admission, global and member cursor/commit/ack, session-member ownership, retention, projection and the sole database writer. Root and member read gaps commit with their cursors and invalidation before acknowledgment. Native capture-scope migration reads its marker after taking SQLite's writer lock and replaces owner-clearing triggers transactionally. A read-only Rust shadow snapshot is fenced by receiver, lease, policy, dirty sequence and published revision. A separate backup-only Rust SQLite inspector reads the same receiver/source revision from a caller-supplied isolated backup with read-only, immutable and query-only settings; its certificate is historical and Python must still check live freshness. Pure Rust reducer fixtures v1–v3 match Python lifecycle, usage, relationship, current v3 Activity and durable source-gap invalidation on the tested corpus. Pure Rust exact-session and exact-Activity queries check source scope and always report partial coverage over a validated v3 snapshot. Rust queries and the backup-only storage inspector are offline and cannot themselves check live snapshot freshness. Full live query/storage compatibility, Rust authority, legacy writer exclusion, one-writer cutover and rollback drill remain. No production data is written by Rust storage.

An independent Rust architecture review found the crate dependency direction clean: the host depends on the protocol, harness binaries depend on shared source crates, and the domain reducer and exact-query crate have no harness dependency. It found no merged Rust path writing directly to Agenturm's Store. Bounded multi-session paths now exist for opt-in Codex and Pi directory readers through the shared source crate, with Store-owned member ownership, conservative root/member continuity disposition and a visible source availability overlay. The next correctness gates are complete evidence parity for one real harness, remaining source-history limits, and live query/storage compatibility. Remaining Python compatibility logic should leave generic services through registered contributions.

Python remains the sole writer until source semantics, query compatibility, crash recovery and rollback gates pass. The user chose idiomatic Rust for the implementation; performance is measured separately and is not a prerequisite to continuing the architecture work.

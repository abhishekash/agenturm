Feature-off v2 lifecycle mutation contract

The Rust storage-service contract crate has a data-only v2 proposal for one host-prepared lifecycle batch. The existing v1 socket API and installed service still parse only v1. No receiver, Store, listener, or canonical database calls v2. Python Store remains the production writer.

Scope and wire shape

V2 has a 64 KiB JSON ceiling. A request requires version: 2, a 32-character lowercase hex request ID, bounded receiver identity and one admit_lifecycle operation. It contains matching receiver, plugin and source identities; a 64-character lowercase hex generation; positive lease and policy epochs; expected and next cursors; a 64-character lowercase hex batch digest; and at most 48 prepared rows. Cursors are at most 512 UTF-8 bytes and contain no control characters.

Each row has a source-scoped event hash, revision zero, lifecycle kind, nonnegative signed 64-bit nanosecond time, canonical metadata-only payload, record digest and bounded native identities. A payload is at most 4 KiB and contains only an allowed lifecycle state and optional reason code. Unknown or duplicate fields, duplicate event hashes, unsupported evidence, noncanonical payloads and excessive frames fail. The frame is narrower than the 1 MiB scratch experiment; the host must split or reject an oversized prepared batch.

The typed success reply binds request and receiver identities, the SHA-256 of canonical request JSON, next cursor and batch digest, nonnegative dirty sequence and one disposition: committed, replay or idle. No rejection reply semantics are defined.

Replay and policy boundary

Canonical, lexically sorted JSON gives equivalent key order and whitespace one replay digest. A reused request ID with changed content conflicts. This is pure comparison material, not a persisted receipt.

Batch and record digests are untrusted assertions derived by Python host admission from the original validated plugin batch. Prepared rows alone cannot reproduce them. A future independent writer must check the current source lease, capture policy, cursors, existing evidence and content status, then persist a durable receipt and evidence atomically before replying. A receiver string does not replace kernel peer authorization.

The scratch writer accepts only ordinary metadata-only lifecycle sources and rejects discovery, content, retention, gaps and non-lifecycle history. V2 carries that subset without a database path. The future writer still needs explicit unsupported-history checks.

Verification

A shared fixture from Python plugin_admission._validated fixes the event hash, record digest, batch digest and request digest. Rust tests check parsing, canonical replay, conflict, reply binding and malformed or unsupported inputs. A Python test independently recomputes the prepared row and digests. Focused Cargo tests, Clippy, formatting and that Python fixture test are the checkpoint gates. No test exercises production mutation or a canonical database write.

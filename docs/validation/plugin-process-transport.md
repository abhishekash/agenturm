# Opt-in plugin process transport checkpoint

This checkpoint adds a supervised local executable transport for an explicitly enabled manifest. The host verifies and copies the hashed artifact before launch, uses separate control and data pipes, negotiates protocol 1, validates source ownership and bounded batches, limits the number of active processes and queued frames, drains stderr without retaining its content, and terminates a worker that crashes, blocks or violates framing. A commit callback must return the accepted cursor before the host sends an acknowledgment. A failed commit closes the worker without an acknowledgment so a new instance can replay from the durable cursor.

The process boundary is a crash and resource-control boundary, not a same-user security sandbox. The manifest's configured-source-read grant is checked before activation but does not restrict OS file access. This transport is **not connected to production collection or Store**. The caller must still implement atomic canonical evidence/cursor admission, capture-policy checks, a lease epoch, projection invalidation and restart recovery. The batch schema is provisional; no external SDK compatibility promise is made.

Validation on Python 3.12: 16 process, manifest and framing tests passed. The tests execute a separately copied fixture plugin and cover durable-ack ordering, failed commit, wrong source, oversize frame, duplicate JSON key, child crash, timeout, artifact change, stderr drain, timestamps above 2^53 and signed 64-bit bounds. The [execution plan](../rfcs/rust-plugin-kernel-plan.md) retains the production gates.

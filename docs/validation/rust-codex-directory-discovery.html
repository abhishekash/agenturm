Bounded Rust Codex directory discovery

Recorded 20 November 2026. This opt-in adapter slice reads multiple Codex rollout JSONL files under one explicitly configured directory in one Rust process. It adds source-discovery/1 to the versioned handshake and keeps the Python Store as the sole writer, lease owner, policy owner and acknowledgment authority. The bundled Codex collector remains the default. No performance gain is claimed.

Contract

The host passes a bounded map of opaque SHA-256 member IDs to file cursors in each poll. At most 48 member checkpoints belong to one configured source. One reply advances one member and the source's sequence cursor. The Store commits the member checkpoint, content-free records, source sequence and dirty marker in one transaction; exact replay is idempotent. A restart loads checkpoints under the new source lease. The checkpoint loader checks byte lengths before fetching at most 49 rows. A stale lease, changed artifact, revoked capture, conflicting revision or over-capacity member cannot acknowledge progress. A removed member requires a newly admitted possible_source_gap diagnostic before its checkpoint is deleted; reusing an old gap record in a new batch is rejected, while exact lost-ack replay remains valid. Because the Store does not yet persist member-to-session ownership, this conservatively marks every previously admitted session of that source Unknown with source_gap and suppresses their Activity. A new session admitted after the gap remains visible.

The Rust worker scans no more than 256 directories, 4,096 entries and six nested levels. It accepts at most 48 .jsonl files, rejects symlinks in the discovered tree, and verifies at most four files per poll in sequence-cursor round-robin order. An idle partial scan advances only the durable scan position and publishes no evidence. Missing checkpoints are released first, so one disappeared and one new file at the 48-member ceiling can make progress. The per-file poll reserves structural JSON tokens for the member envelope and pages a large valid record stream without repeating the same cursor. A malformed or unreadable file and an exceeded scan bound fail visibly. The directory must exist at launch. The shared JSONL directory reader opens the final file component with O_NOFOLLOW and checks its opened device/inode against a post-open path stat, so a final symlink swap or replacement before the check fails; explicit single-file sources retain their existing symlink semantics. Intermediate directory components can still race with traversal; the configured process is not a filesystem security sandbox, and the source read grant is explicit. The worker sends hashes and coarse facts, never file paths, prompt text or output.

The per-file JSONL cursor follows the shared runtime's integrity and source-gap contract. A directory-mode manifest explicitly declares source-discovery/1; a file-mode manifest does not. The same installed binary selects its mode from the configured root. A directory cannot be silently treated as a file if its required feature is absent.

Verification and limits

Focused Python Store tests cover atomic member/evidence commit, exact replay, stale lease, capacity, deletion gap, reused-gap rejection after a newer session, corrupt/oversized checkpoint rows, idle scan progress and revocation. The installed Rust receiver test covers two nested files, restart/resume, disappearance and same-length rewrite with Unknown/source-gap projection and Activity suppression, a new session after the gap, five incomplete files with durable scan progress, near-limit batch pagination, and child cleanup when checkpoint load fails after startup. Rust unit tests reject a 49th file and a final file symlink and prove capacity replacement progress. Existing single-file Codex and sibling harness installed tests remain in the Rust CI gate.

This bounds discovery for a selected directory; it does not cover an arbitrarily large Codex history, full native Review/export parity, automatic replacement, connector discovery or Rust storage authority. If the root disappears, becomes unreadable or exceeds a scan bound, the worker fails and supervisor health reports the error, but previously projected sessions can remain visible until a later successful gap or explicit policy reset. This stale-row behavior is a production cutover gate. The whole tree and cutover gates remain open.

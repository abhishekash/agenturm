Review gate, not runtime exclusion. The static inventory covers 143 access calls at 122 source locations. It cannot fence an older process or transfer authority to Rust.

Machine check

The reviewed JSON inventory records the lexical owner, API, count, authority and effect. python -m unittest tests.test_storage_mutation_route_inventory -v scans all observatory/ Python modules and fails when a direct SQLite connection, internal Store/Workflow access, write gate, or store constructor appears without classification. It also classifies top-level, task, attention and native lifecycle CLI parser names. CI runs it. The scanner rejects imported SQLite connection aliases.

may_write is conservative; external_effect marks outbound actions between writes, and backup_target covers copy pairs. Updating JSON is a review acknowledgement, not a safety proof.

Remaining cutover gate

Dynamic access, separately installed extensions, old wheels, held-open handles and new SQL through an existing connection site are outside this AST scan. It does not inspect every UI action or HTTP route. Every mutable route still needs a Rust service API or proven stop/fence, including separate CLI/UI instances, direct task backup and outbound uncertainty. Then validate old-writer exclusion, consistent migration and forward recovery. No performance gain is claimed.

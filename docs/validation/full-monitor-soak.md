# Sustained complete-monitor validation

13 November 2026. Frozen runtime and harness: `f73b8ba0da38fd23a7a9e7c75bc3da27c4ce301c`. Delivery: [PR #70](https://github.com/abhishekash/agenturm/pull/70). This is the controlled soak follow-up to the [recovery plan](../rfcs/reliability-recovery-plan.md). These changes remain **Unreleased**.

## What changed

The real terminal journey found that Workflow's `shift+r` binding did not match the uppercase `R` byte sent by a terminal. `Shift+R` now freezes and reviews the listed completion identities; pending approvals remain separate. A regression drives the actual uppercase key at 60×18 and 120×36.

Local HTTP polling also constructed an unused HTTPS handler on every request, repeatedly loading the system TLS trust store. HTTP reads now defer that work. Actual HTTPS requests delegate to Python's standard verified handler; redirect refusal remains in force. Tests cover local HTTP without HTTPS initialization, standard certificate/hostname verification settings, and POST redirect refusal for 301, 302, 303, 307 and 308.

## Workload and boundaries

The Linux x86-64 reference host has eight logical CPUs and ran Python 3.12.3 with Textual 8.2.8. The harness runs the real discovery loop, Codex JSONL and OpenCode SQLite readers, authenticated receiver, Feed and a real tmux cockpit. Generated records cover a Codex parent, delegated child, old unfinished session and OpenCode turns with streamed text parts. A synthetic busy Codex app-server holds the current and stale transcript files open; host process inventory uses the real `/proc` implementation.

Before timing, the receiver indexes 5,751 traces, 31,000 spans and 41,000 logs distributed over 35 days. The corpus is generated by the existing history benchmark and shifted two days older, keeping old outcomes outside the default completion inbox. Its counts and payload distribution remain unchanged. This explicit fixture has no age pruning. Fixture preparation took 13.77 seconds; initial receiver readiness took **186.78 seconds**. Both precede the timed workload.

The workload ran for **3609.81 seconds**, finishing its current cycle after the one-hour deadline. It includes an eight-second receiver outage/restart near twenty minutes and a normal cockpit exit/restart at 60×18 near forty minutes; the first cockpit runs at 120×36. A probe sweep reads health, sessions, Activity, metrics and MCP approximately every five seconds, alongside the cockpit's own reads. These are **active-load measurements, not idle CPU budgets**. The host was not exclusively reserved.

All native records, home/configuration/state paths and telemetry are synthetic and isolated. System Gemini configuration is redirected to a fixture path; project configuration discovery is fenced to the generated project. tmux reads no external configuration and directly executes Python without shell startup files. Coordinator loopback requests bypass inherited proxies. This exercises three JSONL files and one native database; it does not establish the cost of scanning thousands of transcript files, live provider execution, Claude/Pi runtime behavior, or daily adoption. Heartbeat and review-queue instrumentation add overhead. Private output directories include local credentials and must not be published wholesale.

## Resource and read costs

CPU is weighted across observed intervals from process CPU counters and expressed as a percentage of one core. New process instances have separate intervals; startup/indexing CPU precedes this table. Kernel VmHWM supplies peak RSS, including any earlier peak in that process.

| --- | --- | --- | --- |
| Receiver | 28.69% | 38.91% | 64.50 MiB |
| Cockpit | 17.75% | 29.55% | 131.92 MiB |
| Synthetic Daemon | 0.57% | 0.75% | 29.66 MiB |
| Driver | 0.43% | 0.80% | 43.91 MiB |

The wide cockpit warmed from roughly 67 MiB to a plateau around 130–132 MiB after about twenty-two minutes, remaining there until its forty-minute restart. The compact replacement warmed from about 69 MiB to about 98 MiB during its remaining twenty minutes. Its segment did not establish a later plateau. Receiver memory remained around 63–64 MiB after warmup. These observations do not prove absence of leaks.

Independent source review identified Textual's `StylesCache.get_inner_outer` LRU as a bounded retention mechanism: its keys include style-cache instances and it can retain 1,024 render-cache graphs. An isolated weak-reference/GC check after all measurements confirmed retention until the global cache is cleared. This confirms the mechanism, **not its contribution to the measured RSS**. Framework retention and render-cache size remain quality work.

## Reproduction and verification

Use a new private output directory for each run:

```bash
PYTHONPATH=. .venv/bin/python scripts/soak_monitor.py \
  --output /tmp/agenturm-monitor-new --history --duration 3600
```

For the matched comparison, run without `--history`, using separate new directories, `--duration 120`, and `--eager-tls` for the previous-initialization case. The harness requires Linux `/proc` and tmux. Its directory-creation and source-consistency gates refuse reused output or changed tracked source.

[Runtime/harness CI](https://github.com/abhishekash/agenturm/actions/runs/43450456957) passed all twelve jobs: 711 tests on each of Python 3.11–3.14, with 14 optional SDK skips per version, both Node versions and six SDK/interoperability jobs. Independent review approved the product fixes and frozen harness after tightening isolation, exact receipt completeness, rendered approval, restart/coverage, source identity and exit-status checks. Preparatory fixture and timing failures were corrected before the three zero-error runs; their early exploratory results are not substituted for these results. Final delivery checks are linked from [PR #70](https://github.com/abhishekash/agenturm/pull/70/checks).

Machine-readable results: [retained-history hour](monitor-hour-history.json), [previous initialization](monitor-matched-eager.json), [deferred initialization](monitor-matched-current.json), [isolated retention mechanism](monitor-style-retention.json).

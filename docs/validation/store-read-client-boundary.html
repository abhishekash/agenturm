Read-only Store client boundary

Recorded 20 November 2026. StoreReadClient is an opt-in Python query client for an already initialized Agenturm Store. It exposes one bounded plugin_sessions(limit) view. Production server and TUI paths still use Store; Python remains the sole writer.

Contract

The writer installs plugin_sessions_read_schema = 1 after the plugin projection columns exist. The client checks that marker, required table and column shapes, and receiver ID in one read transaction. Missing, unknown or malformed state fails closed. This marker covers one query contract, not every Store table or future writer version.

The row count is capped at 1,000, and current trusted Store admission bounds persisted usage fields. A forged future writer could put oversized or misleading text under the same marker; neither the marker nor this client authenticates row contents or proves a general byte bound for arbitrary databases.

Shared plugin_projection.session_rows() and render_session_view() implement both the existing Store method and the new client, rendering after the transaction closes. The client opens SQLite with mode=ro and query_only, never constructs Store, and has no writer API. It binds the regular target and receiver on first use; file replacement or --db symlink retarget requires a new client. Pending, gap, revocation, limit and partial-coverage results match the existing query.

The client does not create the main database, initialize schema, chmod files, run migrations or start workers. SQLite read-only WAL handling may interact with existing -wal/-shm sidecars, so this does not claim literal zero filesystem writes on every platform. Live reads do not use immutable=1, which could ignore uncheckpointed WAL changes.

Verification and limits

Focused tests compare empty, pending, projected, large-usage, bounded-limit, retention-gap, source-gap and revoked results with Store.plugin_sessions(). They cover missing-path noncreation, unsupported schema, malformed usage, unchanged main-database bytes and modification time in the active-WAL fixture, and symlink retarget rejection. Existing plugin projection and retention tests check the shared query extraction.

The file check is point-in-time; it does not authenticate a copied database or detect a swap and restore entirely between observations. This is a first read-only seam. It is not routed into production, does not exclude legacy Python writers, and does not prove Rust storage compatibility or a performance gain.

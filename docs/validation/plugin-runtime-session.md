# Opt-in plugin runtime session checkpoint

Date: 19 November 2026. A `PluginSession` composes the supervised process host with the Store's durable admission transaction for an explicitly supplied manifest and source ID. It keeps one worker alive across polls. The Store returns the resume cursor at activation, checks the lease on every batch, and commits evidence/cursor/dirty state before the process host acknowledges. The caller owns scheduling and creates a new session after a crash. Nothing registers this session with default production collection.

The initial cursor is empty. An adapter with no new records can now return an empty batch at the same cursor, including on its first poll. The host validates the source and lease, acknowledges the idle batch, and leaves evidence, cursor and dirty sequence unchanged. This closes a contract gap that would otherwise terminate an idle worker on every poll. A batch with records still needs a forward cursor or exact replay of the previous durable batch. Lease revocation closes the process without acknowledgment.

Validation: 20 process/runtime/admission tests passed locally. The real executable fixture covers three consecutive empty-cursor polls in one worker, an idle poll after committed progress, an exact replay without duplicate evidence, and a revoked lease with no acknowledgment. Existing process crash, timeout, malformed frame, transaction rollback and restart tests also passed. This is not a production harness adapter: capture-policy epochs, live evidence projection, source scheduling, supervised restart/backoff, external SDK conformance and installed Rust/Python plugin packaging remain gates in the [execution plan](../rfcs/rust-plugin-kernel-plan.md).

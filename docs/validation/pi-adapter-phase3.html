Pi format adapter extraction

Pi's session identity, message/tool/model parsing, task prefix, lifecycle and activity translation now live in observatory/adapters/pi.py. The JSONL host creates a distinct adapter for each session. Direct Session(..., "Pi") callers receive the same built-in adapter.

Extension proof

A synthetic injected adapter contributes a turn, check activity, model usage and completion through the existing Store and status projection without adding a runtime-specific parser branch. Disabling the source spec prevents discovery. The host resolves source roots and rejects a JSONL file claimed by two adapters, including through a symlink alias, reporting ambiguous_sources. A second scan when conflicts exist keeps older valid files from being crowded out of the bounded selection.

The callback protocol is internal. Adapters still receive legacy Session state and run in-process. Python Store remains the only writer. Rust and the supervised process host are not enabled. Other built-in formats still use legacy collector methods; OpenCode uses the reader registry.

Validation

103 focused tests passed for adapter injection, native sessions, hierarchy, discovery, lifecycle, current schemas, reader registry and provenance. git diff --check passed. A synthetic 10,000-file scan took 55.531 ms median CPU, versus an earlier 61.979 ms run; these short unpaired results do not prove a speedup.

The provenance manifest pins the changed source bytes without claiming a live Pi producer version.

# Native source compatibility and fixture provenance

This increment repairs the verified current OpenCode 2.2.5 source layout and records what the native compatibility fixtures actually prove. All records are synthetic. No producer session, provider, or personal transcript was used.

The machine-readable [provenance manifest](../../tests/fixtures/native_review/provenance.json) binds fixture hashes, immutable primary source files and their hashes, reader source hashes, and local test conditions. The original minimal Codex fixture and legacy OpenCode test builders retain **unknown observed producer versions**. An installed CLI version does not establish which producer created an older fixture.

## Verified formats and repaired behavior

OpenCode 2.2.5's [SQL schema](https://raw.githubusercontent.com/anomalyco/opencode/9bbb8ce18c80f099e0e448775f59d965ead40a21/packages/core/src/session/sql.ts), [projector](https://raw.githubusercontent.com/anomalyco/opencode/9bbb8ce18c80f099e0e448775f59d965ead40a21/packages/core/src/session/projector.ts), and [history reader](https://raw.githubusercontent.com/anomalyco/opencode/9bbb8ce18c80f099e0e448775f59d965ead40a21/packages/core/src/session/history.ts) establish the current `session_v2`, `session_message`, and ordinal-keyed `session_part` layouts. Assistant envelopes can have empty inline content while text and tool records live in parts. The adapter now reads those parts in the same SQLite snapshot, preserves scalar type and part order, and notices text changes or deletion without relying on a changed parent timestamp.

Recorded idle boundaries define current OpenCode execution intervals. Steered user prompts remain in the same interval until a closing idle. Assistant completion, source silence, and shutdown do not invent an idle or completion. A missing preceding idle remains exact-step scope with an explicit unknown-prefix reason. Legacy layouts keep their existing IDs and parent-based behavior. Schema2 is applied only when the current split-part table shape is present; older inline `session_message` layouts retain their legacy contract.

Current-layout identities include a path-qualified filesystem generation (device/inode), stable across ordinary writes and reader restarts. Atomic database replacement changes actor, step, and interval identities. Membership proof includes the preceding idle, optional closing idle, expected assistant count and a digest of exact canonical step IDs. The Store requires consistent proof from every retained member before allocating whole-interval usage. Partial/capped membership, deferred parts, or stale indexed summaries withhold totals and expose reasons.

The current producer's [token usage contract](https://raw.githubusercontent.com/anomalyco/opencode/9bbb8ce18c80f099e0e448775f59d965ead40a21/packages/schema/src/token-usage.ts) sums disjoint input, output, reasoning, cache-read and cache-write components. The adapter converts current-layout input into input plus both cache components, and output into output plus reasoning, while retaining the component breakdowns. Missing, malformed, fractional, nonfinite or unsafe counts leave the corresponding total unavailable. Inclusive sums also have a JavaScript-safe integer bound. Legacy interpretation stays unchanged.

The current [shell](https://raw.githubusercontent.com/anomalyco/opencode/9bbb8ce18c80f099e0e448775f59d965ead40a21/packages/core/src/tool/plugin/shell.ts), [edit](https://raw.githubusercontent.com/anomalyco/opencode/9bbb8ce18c80f099e0e448775f59d965ead40a21/packages/core/src/tool/plugin/edit.ts), and [write](https://raw.githubusercontent.com/anomalyco/opencode/9bbb8ce18c80f099e0e448775f59d965ead40a21/packages/core/src/tool/plugin/write.ts) contracts provide qualified command/workdir and explicit file paths. A background launcher whose tool call completed while execution remains running is not a passed check. Captured output clipping remains visible.

Codex 0.167.1's [rollout wire payload](https://raw.githubusercontent.com/openai/codex/0a94398fa60c4fac0e7659e4213a0a36e613dd46/codex-rs/history/src/rollout_payload.rs), [protocol](https://raw.githubusercontent.com/openai/codex/0a94398fa60c4fac0e7659e4213a0a36e613dd46/codex-rs/protocol/src/protocol.rs), and [items](https://raw.githubusercontent.com/openai/codex/0a94398fa60c4fac0e7659e4213a0a36e613dd46/codex-rs/protocol/src/items.rs) support the new version-labelled synthetic fixture: required metadata and token fields, `AgentMessage` content tagged `Text`, command argument vectors and file updates using `unified_diff`. That fixture reaches current Review and export without a Codex adapter change. The provider-free `codex app-server generate-json-schema` output is JSON-RPC schema; it is explicitly **not rollout format proof**.

## Local validation

Reader baseline: `1e8bdcbe5337ca52e7fdfe5b30c793c1e48764c8`. Final adapter/test commit: `cc63b7d` (including the conservative legacy-shape and current-inline equivalence followups). The root-owned membership proof commits are `d955cbb` and `c4e4231`; the manifest records owned source hashes independently of cherry-pick hashes.

- The final native/legacy/turn-proof/budget/provenance batch passed **78 tests in 60.817 seconds**. This is local compatibility validation, not a controlled performance measurement.
- The current-format tests exercise actual Store ingestion, authenticated HTTP Review, exact-turn JSON, Markdown/HTML receipts and persisted task links. A same-Store split→inline→split roundtrip retains one tool span, stable source identity, native timing, output/metadata and exactly one Review check.
- Offline provenance tests validate immutable source locators, fixture and reader hashes, format distinctions and explicitly unknown legacy versions. CI evidence is not asserted in this report; the integration commit must run its own checks.

Boundary cases cover split-part ordering and deletion; equal-timestamp text changes; nonzero cache/reasoning and unsafe counts; open intervals; unknown prefixes; reader restart/database replacement; source replacement and capture revocation during a read; a concurrent WAL update; member/part caps; bounded rotating byte windows; and a changing live message while older messages are still being indexed. The metadata-only fixture preserves usage and boundary facts without importing prompt, assistant or command text. No test executes the synthetic check commands.

The existing limits remain: 50 discovered sessions, 30 message envelopes per session/poll, 200 parts per selected assistant, 2 MiB per source payload, 16 MiB aggregate source payload per poll and 1,000 assistant membership IDs. Scalar cursor state and proof digests are retained; source bodies are not cached between polls. Oversize/partial evidence produces incomplete coverage rather than extrapolated totals.

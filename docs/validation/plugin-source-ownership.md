# Process adapter source ownership checkpoint

19 November 2026. An explicitly configured process source may claim one built-in native source ID through `replaces = ["pi"]` and a matching `harness.pi/1` manifest feature. The receiver validates the named manifest, protocol, grants, executable hash, local collection setting and registered source ID before opening the Store. It then constructs the trusted collector without the replaced source. The process supervisor remains the sole reader for that owner; a later child failure is visible in plugin health and does not start a second trusted reader.

The replacement is opt-in. A regular source row without `replaces` keeps the existing collectors. The configuration rejects repeated replacement claims. The current registry switch covers registered native JSONL sources; OpenCode still has a separate reader. This checkpoint establishes single reader ownership, not a separately packaged production harness or source-to-review parity. The provisional process inbox currently accepts metadata lifecycle, usage and diagnostics, so it cannot reproduce a native source's complete message, tool, check and relationship evidence.

Validation: 26 focused config, process, supervisor, collector runtime and registry tests passed. Cases cover missing manifest claim, unknown source, invalid grant, executable hash mismatch and disabled local collection before Store creation; the collector construction test confirms Pi is removed while Codex remains. `compileall` and `git diff --check` passed. A real packaged harness and end-to-end replacement proof remain open.

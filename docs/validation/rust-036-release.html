Subsequent selector finding

A later review found a private telemetry evidence-binding gap in Rust 0.3.5 and 0.3.6: a selector from one fresh history can match different text in another fresh history with the same span identities and numeric watermark. Both histories still require their own current grants; this is not a grant bypass. Do not carry private telemetry selectors between independent histories. The next candidate binds each selection to its logical history identity and rejects older selectors with refresh guidance. That fix has its own qualification; the original release assets are unchanged.

Rust v2 scratch client checkpoint

20 November 2026. This is a feature-off client transport for the experimental Rust scratch service. The production receiver does not call it, and Python remains the canonical writer.

Client boundary

send_v2_request checks the exact service UID/GID with Linux SO_PEERCRED before sending any lifecycle evidence, then sends canonical JSON in one bounded frame and half-closes the socket. read_v2_reply rechecks the peer before reading reply bytes. It accepts one frame of at most 64 KiB within one two-second deadline, then binds version, receiver and request IDs, the full canonical request digest, cursor and batch digest to the original request. The caller creates its server policy after dropping to a distinct non-root client account.

A missing or rejected reply does not prove the scratch write failed. An exact retry uses the durable scratch receipt.

Installed proof

The fixture-only Rust v2_client example runs under a separate client UID/GID against the opt-in scratch service in a bare Python 3.12 Docker image without network. A wrong claimed service UID is denied before request bytes, while the exact service UID/GID returns a validated replay reply. The account fixture also retains wrong-client-peer, wrong-receiver, private-root, marker and unrelated-canonical-file checks. The client request contains no database path and opens no database.

Validation and limits

23 Rust contract tests passed, including malformed, truncated, oversized, duplicate-key and trailing reply frames; no request bytes to a wrong peer; wrong peer and bound reply fields; total drip-feed frame deadline; and a valid exchange. Targeted Clippy with warnings denied and workspace formatting passed. The separate-UID Docker fixture passed. GitHub CI is a separate gate.

This API does not route production mutations, exclude old held-open writers, migrate canonical SQLite/WAL state, or provide forward recovery. See the writer cutover gate.

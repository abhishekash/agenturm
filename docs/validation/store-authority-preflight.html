Python Store authority preflight

Recorded 20 November 2026 · Migration prerequisite

This is a guarded startup prerequisite for a future one-writer migration. Python Store remains the sole production writer. No Rust writer, process lock, cutover, default change, or performance result is introduced.

Startup contract

Before Store.__init__ creates a directory or file, changes mode, enters WAL, installs schema, or starts a worker, it opens an existing regular SQLite database through a short mode=ro, query_only read. A missing database is still created by Python. A valid legacy SQLite database without schema_meta or an authority marker remains accepted. A marked database must have exactly schema_meta.storage_authority_v1 = python-v1. rust-v1, unknown or oversized values, duplicate values, malformed metadata, a corrupt database, nonregular file, or broken symlink fail closed.

The marker query reads at most two rows and asks SQLite only for the value’s byte length and a 32-character prefix. The constructor binds a relative path to one lexical absolute path, checks target device and inode before path mutation, refuses a file that appeared after an absent-path check, changes permissions through a verified open descriptor, and checks the connected database marker again before WAL or schema SQL. Python records python-v1 after creating schema_meta without overwriting another marker. Later Store._connect() calls use SQLite mode=rw, so they cannot recreate a vanished database. Explicit --db symlinks remain supported.

Evidence and limits

Focused tests cover new, reopened, empty and legacy databases; foreign, unknown, oversized and live uncheckpointed WAL markers; corrupt and nonregular paths; broken symlinks; retargeting during preflight and before chmod; concurrent creation after an absent preflight; disappearance before the first SQLite connection; and a cwd change after relative-path startup. Refusal leaves the tested main database bytes, mode, and modification time unchanged and starts no migration worker.

Point-in-time guard. This is not writer exclusion. A path can change after the final check, an ABA swap may escape observation, and an already open SQLite connection is not fenced. Older Python binaries ignore this marker. SQLite may touch WAL sidecars during read-only preflight; literal zero filesystem writes are not claimed.

A Rust authority cutover still requires stopping legacy writers, cross-process ownership, schema and replay parity, and a reviewed rollback drill.

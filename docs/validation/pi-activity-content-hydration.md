# Explicit Pi user-text preview in Activity

Recorded 20 November 2026. A selected Pi process **user-message** Activity row can request one redacted preview with `z` in its inspector. This is an explicit read of the exact projected event. Other Activity records, normal Review history, copy, and investigation export remain content-free. It does not deliver assistant messages, tool input/output, or complete Pi Review parity.

The `GET /api/plugin-content?event_id=...` route inherits the receiver's bearer and Host policy, and requires a loopback-bound receiver and loopback client. The receiver normally uses a local token unless authentication is explicitly disabled. The route accepts one canonical plugin event ID, then calls the receiver-owned `read_exact_pi_user_text` gate. That gate requires the trusted active Pi directory config, enabled per-source content grant, current projection and Store revision, exact source row and nofollow file proof. The route bounds the already redacted `redacted_text` field to 4,096 UTF-8 bytes, omits source paths, disables response caching, and re-runs the full gate and receiver/source identity check immediately before writing HTTP headers and body. Unavailable or revoked evidence returns a generic error with no text.

The TUI verifies the selected row, receiver, and `/api/plugin-activity-proof` revision before and after the request. It keeps the text only in a transient inspector field; it never adds text to the Activity row, ReviewHistory, clipboard copy, or JSON export. The preview is a loaded point-in-time snapshot and expires after 20 seconds. A background Activity proof recheck every two seconds clears it on policy revocation or Activity revision change. Selection, receiver, or view changes also clear it. The background check does not block UI input. The Pi source file is fully proven at load and on each explicit `z` reload; a later same-inode edit may leave a previously loaded preview visible until the 20-second expiry. A preview already seen by a person cannot be erased.

The 60×18 inspector uses the existing `z` binding and adds no navigation controls or chrome. A missing grant, source change, or stale proof shows a generic unavailable state without raw text or path.

Focused verification: `python -m unittest tests.test_plugin_content_delivery tests.test_plugin_pi_content_read tests.test_plugin_activity tests.test_activity_redaction_certificate -q` (installed Python environment). The delivery suite covers authentication, exact ID validation, redaction, empty and clipped text, absent supervisor, source rewrite before loading and between route gates, policy revocation between route gates, stale TUI selection, pending Activity refresh, direct tab switching, post-display revocation, copy/export isolation, and the 60×18 inspector shell. This is correctness coverage, not a performance claim.

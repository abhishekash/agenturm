Process-plugin Activity facts checkpoint

Recorded 20 November 2026. An explicitly enabled process source can now submit three content-free evidence families: message with a user or assistant role; tool with a coarse shell, file, mcp or other category and a typed result; and check with a test, lint, build, review or other category and a typed result. The host rejects extra fields, free text, command names, paths, output and records without native session identity before database admission. The standalone Python sample emits these facts from append-only JSONL through the actual child protocol. Its installer still pins the executable hash.

The Store projects the latest revision of each admitted event into the existing Activity index. Each row has a source-scoped opaque event, session, agent and turn identity, a generic subject and an empty detail. The original native session, worker and turn IDs remain only in the durable evidence table; Activity does not borrow identity from an unrelated event. Exact agent filtering works for plugin Activity even while plugin agents are outside the native hierarchy; subtree scope reports partial coverage. A failed check is an observed check fact and does not set the session outcome. A check appears as passed only when its admitted payload explicitly says passed.

The Activity query checks the source capture flag, policy epoch and projected dirty sequence in the same read snapshot as pagination and hydration. A newly committed correction hides the previous plugin Activity revision until the projection transaction replaces all rows for that source. Capture revocation deletes evidence, projected sessions and Activity rows in one fenced transaction. A retention checkpoint suppresses Activity for invalidated sessions and reports the source gap through health. The receiver's existing HTTP response cache is invalidated by the committed SQLite write; a warm /api/activity response cannot replay an older check after correction or revocation. An upgrade marker invalidates older plugin projections once so they are rebuilt with Activity rows.

Validation: uv run python -m unittest across the plugin admission, projection, retention, runtime, supervisor, sample, config, process, SDK, manifest and frame modules plus Activity index, worker scope, redaction certificate and source projection modules passed 113 tests before the last two exact-agent tests were added. The focused plugin Activity module then passed 8 tests. Cases cover malformed content, missing identity, correction visibility, exact event and agent identity across sources, no false completion, HTTP cache invalidation, capture revocation, retention invalidation, upgrade rebuild and a real installed sample child. The suite emitted existing ResourceWarning messages for unclosed SQLite connections but had no test failures. git diff --check also passed.

This is metadata-only Activity evidence. It does not capture prompt/response text, tool arguments/output, check logs, file paths, trace membership, exact review-turn proof or a Pi/Codex replacement at parity. The separately installed Rust sample adapter still needs these new input kinds; its protocol host already supports the same admitted wire kinds. No performance gain is claimed.

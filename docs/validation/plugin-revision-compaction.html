19 November 2026. Admission replaces obsolete revisions of a source event inside the same transaction that inserts its higher revision and advances the cursor. The projector uses only the latest revision of each event ID, so lifecycle and usage results are unchanged. Immutable kind and native identity checks run before replacement. A same-revision replay stays idempotent; a stale revision still fails.

A correction can pass even when the source is at its 50,000-row cap, provided it replaces an existing event row. A later failure in the same batch rolls back deletion, insertion and cursor together. The latest revision and digest remain for future monotonic and conflict checks. Earlier revision payloads are deliberately no longer retained as an audit history; the current projected state and source cursor remain durable.

This is not full retention. Each distinct event still occupies one row, so a continuously emitting source can reach the cap and pause. Discarding distinct events needs a reviewed correction horizon, durable aggregate checkpoint, late-event policy and recovery tests. No source is silently acknowledged past capacity.

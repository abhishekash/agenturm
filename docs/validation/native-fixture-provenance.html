Native source compatibility and fixture provenance

This increment repairs the verified current OpenCode 2.2.5 source layout and records what the native compatibility fixtures actually prove. All records are synthetic. No producer session, provider, or personal transcript was used.

The machine-readable provenance manifest binds fixture hashes, immutable primary source files and their hashes, reader source hashes, and local test conditions. The original minimal Codex fixture and legacy OpenCode test builders retain unknown observed producer versions. An installed CLI version does not establish which producer created an older fixture.

Verified formats and repaired behavior

OpenCode 2.2.5's SQL schema, projector, and history reader establish the current session_v2, session_message, and ordinal-keyed session_part layouts. Assistant envelopes can have empty inline content while text and tool records live in parts. The adapter now reads those parts in the same SQLite snapshot, preserves scalar type and part order, and notices text changes or deletion without relying on a changed parent timestamp.

Recorded idle boundaries define current OpenCode execution intervals. Steered user prompts remain in the same interval until a closing idle. Assistant completion, source silence, and shutdown do not invent an idle or completion. A missing preceding idle remains exact-step scope with an explicit unknown-prefix reason. Legacy layouts keep their existing IDs and parent-based behavior. Schema2 is applied only when the current split-part table shape is present; older inline session_message layouts retain their legacy contract.

Current-layout identities include a path-qualified filesystem generation (device/inode), stable across ordinary writes and reader restarts. Atomic database replacement changes actor, step, and interval identities. Membership proof includes the preceding idle, optional closing idle, expected assistant count and a digest of exact canonical step IDs. The Store requires consistent proof from every retained member before allocating whole-interval usage. Partial/capped membership, deferred parts, or stale indexed summaries withhold totals and expose reasons.

The current producer's token usage contract sums disjoint input, output, reasoning, cache-read and cache-write components. The adapter converts current-layout input into input plus both cache components, and output into output plus reasoning, while retaining the component breakdowns. Missing, malformed, fractional, nonfinite or unsafe counts leave the corresponding total unavailable. Inclusive sums also have a JavaScript-safe integer bound. Legacy interpretation stays unchanged.

The current shell, edit, and write contracts provide qualified command/workdir and explicit file paths. A background launcher whose tool call completed while execution remains running is not a passed check. Captured output clipping remains visible.

Codex 0.167.1's rollout wire payload, protocol, and items support the new version-labelled synthetic fixture: required metadata and token fields, AgentMessage content tagged Text, command argument vectors and file updates using unified_diff. That fixture reaches current Review and export without a Codex adapter change. The provider-free codex app-server generate-json-schema output is JSON-RPC schema; it is explicitly not rollout format proof.

  • Offline provenance tests validate immutable source locators, fixture and reader hashes, format distinctions and explicitly unknown legacy versions. CI evidence is not asserted in this report; the integration commit must run its own checks.

Boundary cases cover split-part ordering and deletion; equal-timestamp text changes; nonzero cache/reasoning and unsafe counts; open intervals; unknown prefixes; reader restart/database replacement; source replacement and capture revocation during a read; a concurrent WAL update; member/part caps; bounded rotating byte windows; and a changing live message while older messages are still being indexed. The metadata-only fixture preserves usage and boundary facts without importing prompt, assistant or command text. No test executes the synthetic check commands.

The existing limits remain: 50 discovered sessions, 30 message envelopes per session/poll, 200 parts per selected assistant, 2 MiB per source payload, 16 MiB aggregate source payload per poll and 1,000 assistant membership IDs. Scalar cursor state and proof digests are retained; source bodies are not cached between polls. Oversize/partial evidence produces incomplete coverage rather than extrapolated totals.

# Trusted capture-mode registry: first phase

20 November 2026. This refactor moves explicit capture-mode selection from Pi-name branches in generic plugin configuration, supervisor and session startup into a receiver-owned, immutable `CaptureModeRegistry`. The default registry contains metadata-only, Pi user-text references and Pi requested-command references. The receiver passes the same registry through configuration parsing and worker construction. A plugin TOML file names a mode but cannot install a validator or grant factory.

The registry checks the selected mode's required manifest features, configured grants, source root, replacement claim and mutually exclusive reference feature. At session startup it rechecks those invariants against the trusted `PluginSource`, then selects the existing Pi grant class and fingerprint through the mode declaration. Metadata-only remains the default. The synthetic audit-only mode in tests is installed solely by trusted host code; it exercises configuration, receiver composition and session selection but has no reference feature, grant or private-content admission.

The exact Pi source verifier, policy/lease/cursor checks, replay receipts, redaction and SQLite admission remain in their existing Pi modules and `plugin_admission.commit_batch`. `BatchHandlerRegistry` still selects the negotiated wire envelope. This phase does **not** let a new content-capable harness admit private text: the next SPI must move verified reference admission and durable receipts behind host-owned handlers while preserving those proof gates. Untrusted process code cannot provide those handlers.

Validation: 115 related plugin/process/admission tests passed (21 installed-binary skips), and 36 focused Pi transport, registry, config, runtime and supervisor tests passed after the receiver composition wiring. With local Rust Pi and plugin-host binaries supplied, the 21 installed Pi content/command tests also passed. The synthetic second mode, unknown mode, TOML validator injection, Pi reference-feature borrowing and forged source policy were exercised. No Rust production writer, performance result or connector rollout is implied.

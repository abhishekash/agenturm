Offline migration candidate producer

20 November 2026 · feature off

A manually invoked producer of three detached SQLite backups and a Rust-verifiable manifest. Python Store remains the production writer.

Writers must already be stopped. This tool cannot prove a shared stopped-write epoch, fence an old process, or authorize a Rust writer cutover.

Operator contract

Invoke python -m observatory.migration_candidate with absolute --telemetry, --workflow, --tasks, --output, and trusted --verifier paths. Sources and the output parent must be private real paths; output must be new. The tool is absent from receiver startup.

Preparation and proof

  • Create a private output directory and mark it incomplete. An absent marker also means incomplete.
  • Read main and any WAL/SHM through no-follow descriptors; reject rollback journals or incomplete WAL pairs. Bounded copy and hashing compare identity and SHA-256 after a successful copy.
  • Clone main and WAL bytes privately, then use SQLite online backup on those clones. SQLite never opens the canonical sources and cannot update their shared-memory sidecars.
  • Fsync detached backups and build migration_manifest_v1 with receiver, every source cursor and optional Pi receipt, workflow/task counts, and file identity/digests.
  • Invoke the Rust verifier and require its exact receiver reply before atomically marking the candidate verified with the manifest SHA-256. A final sync failure attempts to restore incomplete state; an unrecoverable filesystem failure requires manual quarantine. Later use must rehash and reverify the candidate.

Validation

Installed tests use actual telemetry, workflow and task stores, including a row proved to reside only in WAL before backup. They compare source main/WAL/SHM bytes before and after and exercise incomplete output on verifier failure, final sync failure or interrupted backup, plus rollback-journal and symlink rejection. CI builds and exercises the Rust verifier.

Remaining gate

File checks cannot exclude a writer that races or restarts after copying. The trusted verifier validates detached historical consistency, not complete receipt parity or cutover readiness. Old writer exclusion, global mutator drain, protected service identity, publish and crash recovery remain open. See the writer cutover gate and verifier checkpoint.

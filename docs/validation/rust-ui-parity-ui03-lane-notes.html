What changed

This lane completes the command-center time scopes, the searchable session chooser, the exact-agent/subtree scope and the three-section session inspector. It follows the published shared shell contracts and keeps the shell generic over model data: no provider switch, no captured-text read and no second key or help table were added.

Time scope, Errors and search

Today

Current work of any age, pending input of any age, and only today's non-acknowledged outcomes. A reviewed outcome or acknowledged pending request drops out. Verified with a fixed clock and fixed UTC offsets.

History

Everything retained, including earlier unreviewed completions and failures. History is the approved landing scope.

Independent facets

Time scope, status filter, errors-only, search and exact session scope are separate fields. Counts describe the loaded page and say which facets they ignore.

Keys: T Today, O History, E Errors only, S subtree scope. Each is an inventory row and a palette row. The chip strip also shows Today N, History N, the status filters, Errors N and Unknown N.

Search covers task title, project path, provider label, exact source, exact session, worker identity, native name/role/path/model provider, state and reason. Empty states distinguish no catalog page, empty collection, an active search with no match, errors-only empty, Today empty and a status-filter miss.

The kernel owns the boundary: agenturm_kernel::session_scope is data-only and provider-free. The host resolves the local calendar day for the read instant (including the offset at local midnight) and sends it as SessionCatalog::day_start_unix_ns.

Agent scope and relationships

  • Exact-agent scope selects one recorded (source, session).
  • S adds only confirmed delegated descendants whose parent is retained on the page and in the same source family.
  • forked, cross-source and chain-incomplete relationships are counted and reported in the footer, never guessed into the subtree.
  • Alt+↑/↓/→ parent/child/attention paths and tree/flat/expand/collapse are unchanged. A cycle stays a separate row with no invented root.

Navigation

  • The tab strip is one focus stop; the active tab is always visible and the focused strip shows › plus READ: Enter.
  • ←/→ choose on the tab strip. Enter/Down enter content; on Prompts they open UI-04’s navigator. ↑ on Prompts also opens it.
  • From content, Ctrl+←/Ctrl+→ and m switch sections. Plain ←/→ stay with content.
  • Esc returns one layer: prompt overlay → inspector → roster. The roster keeps filter, grouping, selection and display offset. Footer hints come from keymap::hint; only the read-state cue and page coverage are inspector-local.
  • Section changes reload in place with Change::SessionMode; a pushed Activity/Review/Traces/Usage page returns to the same section.

App projection

session_evidence::add_session_panes(snapshot, &RecordedSession) now emits app.session-overview, app.session-details, activity, review, usage, and the MCP/operation/trace panes. session_display::add_context prepends the human name, provider, native context, project provenance and recorded state/reason to Overview. Exact identity stays in Details.

Overview and Details are generic PaneModel rows produced from typed observations and the session record. A new adapter contributes observations; it never edits the inspector.

Deliberate narrowing. session.today/session.history are inventory rows in the CommandCenter context only. T already means “choose recorded turn” in History; a second meaning would violate one-key-one-owner.

What remains

  1. Evidence primary-event pinning. Overview links open exact session Activity, but do not yet pin a failed call, request or interruption.
  2. Locate and acknowledgement from the inspector. X/Y remain roster actions. Dismissed failures are not a separate retention state, so Errors is a recorded failed/interrupted filter, not Python’s two-conversation unseen-error reminder.
  3. Evidence subtree membership. Roster and chooser honour exact agent + delegated subtree. Activity/MCP/Traces/Findings remain exact-session/turn; subtree evidence needs a kernel/query capability.
  4. AI summary. Not implemented; it requires an optional extension capability with explicit egress policy.
  5. Capture policy in Details. The roster projection has no capture-policy field, so Details says it is not reported here rather than inferring it.
  6. Mouse. Still keyboard-first; any mouse route must call the same action id.
  7. Provider payload/detail. Unchanged and owned by UI-05/FD2.
  8. Installed paired boundary run. A fixed-zone PTY run against the installed candidate remains UI-Q work.

Exact hooks for the integration pass

UI-02 · shared shell

  • Keep the five new inventory ids and contexts. keymap::hint is unchanged. Focus gained no variant: inspector tab focus lives in Workspace::inspector, because it is screen-local navigation, not a modal owner.
  • ui::render_selected_pane is pub(crate) and tolerates an empty pane list. The inspector reuses it; no shell layout was duplicated.
  • The command center no longer renders agents.help; F1 routes to the shared help::Help. The field remains only for direct-render compatibility.
  • Palette: session.sections focuses the tab strip; the other four run their documented dispatch.

UI-04 · Prompts

  • Entry hook: WorkCommand::Prompts(WorkAnchor { source, session, worker: None, turn: None }) for the exact inspector session, also reachable with P.
  • The shell sets inspector.tab = Prompts before the request. When the navigator closes, the tab strip remains focused on Prompts; Esc then returns to the inspector section, then the roster.
  • Do not render a second section reader: replace or overlay the inspector body inside the existing Workbench flow, keeping the same anchor semantics for worker/turn scope.

UI-05 / UI-06

  • Use RecordedSession::provider_label() and display_name() for human labels; do not add Name unavailable.
  • SessionCatalog::day_start_unix_ns is the resolved local boundary; reuse it rather than recomputing UTC midnight.
  • RecordedSession::worker_id is the exact recorded lifecycle worker; it does not establish live process ownership.
  • session_scope::in_session_time_scope is the neutral policy for saved-task run lists and workflow incidents.

Intentional differences to accept

  1. The approved landing order remains project-grouped, newest-first with fixed Updated ↓; Python offers status-first and selectable direction.
  2. Today/History are independent time-scope chips with T/O, not members of Python’s single filter select. Status filters stay independent.
  3. The inspector’s Prompts section opens the shared UI-04 navigator overlay instead of embedding the reader in the tab body in this change.
  4. session.today/session.history stay command-center scoped to avoid overloading History’s T turn picker.
  5. Recorded lifecycle wording never implies live process health; the inspector labels every state as recorded.
